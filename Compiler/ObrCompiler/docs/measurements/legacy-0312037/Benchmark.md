# ObrCompiler 优化交付与实测报告

日期：2026-10-30。对应需求 v1.0；需求第 13 节将 -20% 镜像/-20% 指令/-15% 访存定义为期望，禁止新增格式/native PIE。用户后续要求先完成实现，暂不提 PR。本报告记录本地结果，不代表协议变更、维护者验收或跨机器性能保证。

## 结论与交付范围

已实现默认 O1、O0 回退、O2 有界内联、可独立开关/排序的 forward 与 dce、结构化机器 IR/CFG、私有槽转发、native 紧凑立即数/disp32、覆盖诊断和 debug 同步。修复 dormant Peephole 中会破坏程序结果/启动的边界错误，以及字符拼接的既有正确性缺陷。实现与测试只改编译器、CMake、忽略路径和相关语言文档，产品 CPU、loader、内核、NAS 服务、协议、布局常量和依赖列表未改。

默认 O1 的真实 kernel/start 从 672,933 B 降为 504,898 B（-24.97%）；大输入编译时间增幅在约定的 +10% 以内。58 个真实 PIE 程序镜像变化中位数 -5.31%，未达到 -20% 的期望。可正常完成的示例/微基准中，ZAP 动态步数中位数 -6.23%、逻辑 load/store 中位数 -9.55%；也未达到期望。不能据此声称整机快 20%、60 FPS 或 boot-to-shell 加速。

## 主要静态结果

| 程序/指标 | 原始基线 | O1 | O2 |
|---|---:|---:|---:|
| kernel/start 字节 | 672,933 | 504,898 (-24.97%) | 500,745 (-25.59%) |
| os/sh 字节 | 391,860 | 373,307 (-4.73%) | 370,920 (-5.34%) |
| kernel/init 字节 | 21,672 | 19,740 (-8.91%) | 19,740 (-8.91%) |
| os/session 字节 | 18,982 | 16,993 (-10.48%) | 16,993 (-10.48%) |
| 58 个 ZPB1 字节变化中位数 | — | -5.31% | -6.28% |
| kernel/start 编译中位 ms | 2,340.33 | 2,409.68 (+2.96%) | 2,412.45 (+3.08%) |
| os/sh 编译中位 ms | 364.94 | 396.65 (+8.69%) | 398.25 (+9.13%) |

真实非 PIE 程序只有 kernel/start，三个优化级别均生成 ZNB1，覆盖率为 1/1。其余 58 个保持 PIE ZPB1。native 覆盖诊断准确拒绝未登记 GPU 等指令，仍使用整段回退；没有声称任意非 PIE Obr 程序都能 native。

59 个真实输入中，O1/O2 均没有相对基线的镜像增长。O2 的内部 AST 成本上限不等价于最终字节单调下降：例如 ls 的 O2 比 O1 多 412 B，但仍比基线小 5.38%。较小输入的编译增幅会超过 10%：PIE 逐程序中位数约 +10.61%，最高 kill O1 约 +18.01%（48.80 → 57.59 ms），ls/grep 约 +13.5%。本次通过的是需求明确列举的 kernel/start、os/sh 两个大输入门槛，不是所有输入都保证 +10%。

## 动态执行与正确性

[差分原始记录](measurements/differential.json)覆盖全部示例、错误输入、Logo、字符拼接、宽位移、别名、循环、PIE 重定位、数字/十六进制跳转、原样汇编、故障和 ABI 样本。baseline/O0/O1/O2 各跑 PIE 与非 PIE；有限程序真正执行，设备/交互型无限程序进行真实 loader/decoder 静态检查。每项明确记录是否执行，不能把仅编译/解码当作运行成功。

只有基线与候选均正常 halt 且格式相同的配对参加性能统计；基线 libmore/字符拼接故障被修好后不把短故障路径当作性能基线。每个 `(label,pie)` 算一项，Logo 两种装入形式为两项。

| 指标 | O1 | O2 | 分母与单位 |
|---|---:|---:|---|
| ZAP 动态步数中位变化 | -6.23% | -6.23% | 34 对正常完成执行 |
| Native 动态步数中位变化 | -6.76% | -6.76% | 33 对正常完成执行 |
| ZAP 逻辑访存中位变化 | -9.55% | -9.55% | 成功 load + store；零分母排除 |
| Native 数据八位组中位变化 | -8.90% | -8.90% | 扣除取指的读字节 + 写字节；非访存指令数 |

这些配对中没有动态步数退化。arith 的 ZAP 步数 162 → 98，collect 为 19,023 → 18,877；收益依源程序而异。O2 的额外内联在这批被动态测量的路径上没有提供进一步中位数收益，不能把真实 NAS 静态缩小当作其动态提速。

ZAP 用测试构建钩子观测私有缓存与真实主板访问，产品文件不变；同时单列主板请求/八位组，避免把多数全部命中缓存的微基准写成“信箱流量降低 9.55%”。没有采集真实 shell/NAS 工作负载的整机动态指令及访存总数，也没有可靠的五次 boot-to-shell 定量数据。

差分检查返回值、设备事件、共享可见写入、故障结果，验证 debug 覆盖、源位置范围和 native 指令边界，故障 fixture 回溯到实际源码语句。bad-* 的拒绝诊断逐字比较。O0 对正常兼容样本逐字节匹配旧编译器，以下明确正确性修复例外：

1. 字符 + 字符串（两侧、UTF-8）：旧 boxChar 覆盖另一操作数，bump 使用被帧寻址覆盖的堆指针；新 O0/O1/O2 正确，libmore 返回 73。
2. 含 register return r6/r7、PIE 或 unaligned 访问的既有 native 选择失败：现在回退既有 ZPB1，保留运行语义/故障，而不是写入不支持的 scaled 指令或编译失败。

[契约测试](measurements/contracts.json)实际执行 slot 0..7、PIE install 到 core 1/4、args block、动态库 attach/import/export、七参递归/栈平衡/callee-saved、shell editor 149 项检查、sandbox 原样汇编；检查 CLI 拒绝、可重复 pass、native-report、#LINK/@Callfun 和默认不写 zap。产品旧 NativeImageCheck 只认识固定 disp8 模板，因此按原样对 O0 黄金运行；O1/O2 由真实产品解码器、边界与 ABI 执行验证，未修改 CPU 测试来迁就编码。

最终差分为 464 组编译/执行组合、323,532 项断言、0 失败；契约检查 195 项通过。CMake 的 native-encode-check、peephole-check、obrc-smoke 共 3/3 通过；NAS 文件系统检查、仓库 consistency、TypeScript 类型检查、lint 和 Vite 生产构建均通过。Vite 仍提示原有的大 chunk，构建成功；未为消除提示改动产品打包结构。

## Peephole 的启动边界

本次接入实测发现：只保留 ret 的 r0/r7 会删掉 UI 等手写多返回寄存器，Logo 绘制参数错误，导致黑屏。修复为全部 ret 保守保留八个文本寄存器；原样汇编也是 opaque 边界。另修复 halt r0 活跃性、数字/间接全局跳转目标失效、共享读错误转发、别名失效与重定位折叠风险。都有独立黄金样本，Logo 真实 GPU 参数事件与基线一致，完整系统可启动到 shell。

没有仓库历史失败提交可把注释中“停在 Starting”的现象绑定为唯一历史根因。这里明确报告当前代码中可复现、已修的失败机制和最终启动证据，不以推断替代历史复现。

## 浏览器与已知基线问题

最终 O1 经完整生产构建启动到 shell，分别冷启动验证 pwd、ls、重定向写入、cat、grep，NAS 主机实际文件内容与预期一致。O2 启动、cat 与 BIOS 鼠标/键盘/显示结果记录在[浏览器验证](BrowserSmoke.md)和截图中。它们是功能冒烟，没有统一计时、GPU 像素逐帧黄金或 FPS 测量。

同一 shell 连续运行 `echo alpha`、`echo beta`，第二条仍输出 alpha：在**完全冻结的原始基线固件、内核和 NAS**中也复现，在一致的候选中同样存在。证据为 `frozen-baseline-stale-argv.png` 与 `consistent-candidate-stale-argv.png`。它是本提交以前的系统问题，本次未定位到可证实的唯一源头，不将其归因于 DCE，也未越界修改 CPU/内核来修复。由于这个问题，文件命令使用分别冷启动验证；不能声称连续多命令场景完全通过。

## 未达目标、风险与后续边界

- ZPB1 -20%、动态步数 -20%、访存 -15% 的期望未达到。大量手写 runtime/外设/原样汇编和未知别名边界必须保守；未做全局寄存器分配、完整 SSA、循环优化或 ABI 重设计。降低这些边界的保守性需要独立效应摘要和更多真实负载证据。
- boot-to-shell 不退化/-10%、真实 NAS 动态计数、跨 Windows/Linux、独立 Chrome 版本和宿主峰值内存尚未定量验收。已做的多次功能启动不能替代这些数据。
- 全部 debug 行的结构、边界和源范围检查通过；只有明确 fixture 验证运行故障语句。不能把这些有限样本说成所有程序逐语句调试的完备证明。
- `-O0` 关闭新优化，但保留正确性修复；逐字节复现原缺陷用固定提交的基线编译器。任何单 pass 可禁用，`-passes` 可排序重复；无需协议/CPU/loader 升级。
- 原仓库连续 shell 参数异常保留为独立缺陷。正式合并前建议由维护者在自己的浏览器和机器复现本报告，并决定是否先拆出该系统问题。

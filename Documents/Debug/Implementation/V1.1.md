# ZTrace v1.1 交付合同

> 产品名：**ZTrace**；命令行：`ztrace`；交付版本：**v1.1**。  
> 数据 schema：**`zeros.ztrace.capture/2`**；v1.0 的 `/1` 仍可读。  
> 状态：**已交付（2026-11-02，工作区基线；尚未提交）**。

## 1. 版本定位

v1.1 是在 v1.0 基线上补齐“命令成败 + 退出码 + 基础故障现场”的可交付版本。

它不是 v2 全量完成，也不是 P4 全量完成。v1.1 的目标是：

- 全量 54 条 `/bin` 命令能稳定回到提示符；
- 每条命令的退出码可判定；
- 启动旧 fault 不再混进每条命令；
- 解释器核能拿到寄存器、PC、栈指针；
- 报告能区分 boot 现场和 command 现场。

## 2. 纳入 v1.1

| 能力 | 交付物 | 证据 |
|------|--------|------|
| 命令窗口 | `windows`（64 位 `At`） | 全量 capture |
| 命令退出码 | `exitCode` / `exitCodeSource` / `exitEvents` | 54/54 退出码门禁 |
| 宿主退出传输 | 服务 28 直接读 `home+128` 的 `ProcessExit` | ZAP/native 两条路径 |
| 全量语料 | 54 条 `/bin`，200ms 基线 | `dev/Debug/ztrace-p4-full3/` |
| 采集门禁 | `ztrace-check` / `ztrace-diff` / `ztrace-gate` | gate 8/8 |
| fault 作用域 | `At`、`Scope=boot/command` | boot fault 不混入命令 |
| 解释器现场 | `Mode`、8 个寄存器、PC、栈指针 | core 7 实测 `sp=0x74105840` |
| 停机现场 | `At`、`Reason`、`Snapshot`、`StackBytes` | 失败停机补读 128 字节 |
| 栈分离 | `HostStack` + `GuestStack` 摘要 | `sp=` / `range=` |
| 报告过滤 | 命令报告只显示本次 stop/fault | `latest stops`、`faults` |
| 长序列 VFS | 512 项路径缓存 + 满时回收 | 54/54 长序列 |

## 3. 验收结果

最终全量：

```text
dev/Debug/ztrace-p4-full3/
```

- 54/54 通过；
- `failed=0`、`timeouts=0`、`dropped=0`；
- `ztrace-gate --require-corpus --require-exit-codes`：8/8；
- 54 条命令的 fault 合计为 0；
- 所有命令 stop 都是 `Scope=command`；
- 所有带 Snapshot 的 stop 都有 8 个寄存器。

## 4. 明确边界

以下能力**不在 v1.1**，不能当成已完成：

- stdout/stderr 文本捕获；当前 `outputCaptured=false`；
- `/bin/*` 外部命令的全核符号与构建 ID；
- 逐帧 `GuestStack`；当前只有 `sp=` 和范围摘要；
- `StackBytes` 的真实命令 fault 样本验证；
- `TaskWait`/`TaskExit` 的可靠队列化；当前仍依赖 `sig.obr` 4416 单诊断字，发布门禁用宿主 `ProcessExit`；
- 120ms 输入漂移下的全量稳定性；发布基线是 200ms；
- 目录缓存的回收；当前只回收普通文件，极端大量目录仍受 512 项限制。

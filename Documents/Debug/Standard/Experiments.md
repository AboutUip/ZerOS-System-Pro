# 实验标准

## 1. 目的

本文件规定怎样设计、执行和记录一次调试实验。它不绑定具体 runner、批次或命令。

命令、脚本和测试程序都是实验载荷；载荷可以替换，实验结构不变。

## 2. 实验类型

| 类型 | 用途 | 关键要求 |
|------|------|----------|
| 复现实验 | 确认症状可重复 | 固定环境、最小输入 |
| 基线实验 | 建立未改动时的分布 | 足够样本、记录噪声 |
| 对照实验 | 比较处理与基线 | 单一变量、同条件 |
| 消融实验 | 移除一个阶段/设备 | 保持其余路径不变 |
| 二分实验 | 缩小时间/代码/输入范围 | 每步可判定 |
| 校准实验 | 验证观测点本身 | 已知答案、关闭/溢出 |
| 回归实验 | 证明修复没有回退 | 同批次、同载荷、负向路径 |

## 3. 设计

每次实验先写：

```text
编号：
问题：
假设：
变量：只列一个处理变量
对照：基线和反事实
载荷：命令/程序/输入
环境：版本、配置、开关、服务、屏幕状态
样本：次数、顺序、预热
指标：单位、采集方式
超时：单次/整体
中止条件：
原始数据路径：
```

要求：

- 一个实验只回答一个问题。
- 处理组和对照组使用同一载荷、同一环境、同一采集方式。
- 记录冷启动、缓存、滚屏、GC、宿主负载等顺序效应。
- 需要时随机化或交替顺序，避免系统性偏差。
- 不因一次异常值重跑直到好看；异常值保留并解释。

## 4. 重复与噪声

- 至少 3 次用于稳定性判断；修复决策建议 5 次。
- 报告范围和中位数，不只报最好一次。
- 先算噪声底，再判断处理差异。
- 处理差异小于噪声底时，结论写「无可辨识差异」。
- 不把不同日期、不同负载、不同屏幕状态的样本混在一起比较。

## 5. Runner 要求

自动 runner 至少具备：

- 预检：版本、开关、服务、端口、依赖。
- 明确的完成信号：事件/提示符/协议回复，不用固定睡眠猜结束。
- 每条载荷硬超时；超时中止并保留日志。
- 实时日志：开始、完成、耗时、记录数、错误。
- 原始输出：结构化结果 + 文本日志。
- 失败可复现：保留载荷、环境、随机种子、输入节流。
- 不静默重试；重试必须记录次数和原因。
- 不跳过 preflight；缺服务时快速失败。

runner 的具体实现见 `Implementation/Runbook.md`。

## 6. 执行

1. 预检并记录环境。
2. 清空/重置会话状态；记录重置方式。
3. 跑基线；检查噪声。
4. 跑处理；保持相同载荷和顺序。
5. 跑反事实/回退；确认方向。
6. 保存原始数据。
7. 计算范围、中位数、差异和噪声。
8. 写结论和限制。

## 7. 中止条件

- preflight 失败。
- 完成信号超时。
- 记录丢失超过阈值。
- 被测系统进入错误状态或不可恢复。
- 观测开销超过预算。
- 环境发生未记录的变化。

中止不是失败；中止原因必须记录。

## 8. 结果分析

- 先看原始日志，再看汇总。
- 区分排队、传输、执行、呈现、等待。
- 并行区间不相加。
- 采样/计数结果标注口径。
- 对候选做反事实检查。
- 负结果和回退同样记录。

## 9. 报告模板

```text
实验编号：
问题/假设：
版本/环境：
载荷：
变量：
样本数/顺序：
基线：范围、中位数
处理：范围、中位数
反事实/回退：
噪声底：
结论等级：
限制：
原始数据：
```

## 10. 反模式

- 用不同载荷证明处理有效。
- 只跑一次就宣布收益。
- 固定睡眠代替完成信号。
- 超时后加大超时继续跑。
- 丢弃失败样本。
- 把并行 span 相加。
- 为了提高数字改变采集口径。
- 没有 preflight 就开始长跑。

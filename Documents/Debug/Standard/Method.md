# 调试方法

## 1. 目的

本文件规定一次调试从问题出现到结论落地的工作顺序。它不绑定具体硬件、命令或某次性能事件。

适用范围：

- 功能异常、时序异常、性能退化、资源异常、协议边界问题。
- 宿主 TypeScript、虚拟硬件、CPU/内存/设备线程、客程序与内核路径。
- 单次故障和长期观测设施建设。

不适用范围：

- 协议定义。协议在 `Documents/Protocol/`。
- 基准测试排名。基准是实验的一种，不是调试结论的替代品。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 症状 | 可观察到的异常，不包含原因猜测 |
| 问题陈述 | 一句可验证的话：在什么条件下，什么指标偏离什么预期 |
| 模型 | 对系统应有行为、边界和不变量的描述 |
| 基线 | 未施加候选改动时，同一实验的结果 |
| 处理 | 被验证的候选改动或候选配置 |
| 反事实 | 如果原因不成立，应观察到什么 |
| 噪声底 | 同一条件下重复实验自然产生的波动 |
| 证据等级 | 见 `Evidence.md` |
| 观测点 | 在不改变业务语义的前提下读取状态的位置 |

## 3. 工作流

### 3.1 定义问题

输出：

- 症状：发生了什么，何时、在哪个层。
- 问题陈述：条件 + 指标 + 预期。
- 成功标准：修复后哪一个指标回到什么范围。
- 非目标：这一次不解决什么。

要求：

- 不把「某命令慢」直接当原因；它只是症状的一个实例。
- 不把「某函数采样多」直接当原因；它只是权重线索。
- 一次只定义一个主问题；其它问题登记，不混入同一次改动。

### 3.2 建立模型

列出：

- 参与线程、进程、设备、队列和共享内存。
- 正常路径的状态转换和边界。
- 已知不变量：顺序、所有权、生命周期、容量、时钟。
- 未知点：当前没有观测或没有文档的部分。

模型必须能回答「如果 X 是原因，应该观察到什么」。回答不了，说明模型还不够。

### 3.3 复现

要求：

- 最小化输入和步骤。
- 固定环境：版本、配置、开关、输入节流、屏幕状态、服务状态。
- 先跑基线；没有基线不进入定位。
- 保留失败样本和成功样本。
- 记录不能复现的条件；不能复现也是结论。

复现失败时，先补环境信息，不先改代码。

### 3.4 观测

选择观测级别：

| 级别 | 适用 | 代价 |
|------|------|------|
| 计数 | 高频、只需总量 | 低 |
| 事件 | 状态变化、离散边界 | 低 |
| span | 有始有终的操作 | 中 |
| 边 | 等待、唤醒、请求/回复关系 | 中 |
| 采样 | 高频执行、需要热区 | 中 |
| 全量/指令环 | 需要逐条语义 | 高 |
| 快照 | 故障现场 | 一次性 |

要求：

- 观测点放在已有边界，不为观测新增协议或指令。
- 每个点写明语义、单位、频率、父关系和关闭行为。
- 观测本身可能改变结果；记录开销和采样偏差。
- 没有观测点时写「未覆盖」，不用推断填充。

### 3.5 隔离

按信息量选择：

- 差分：开/关一个条件。
- 消融：移除一个阶段或一个设备。
- 二分：按时间、代码路径或输入范围切半。
- 替换：换实现/换配置，保持接口不变。
- 时间分解：排队、传输、执行、呈现分开。
- 空间分解：按核、任务、设备、缓冲区分开。

隔离的目标是让候选原因产生**可区分**的预测，而不是收集更多数字。

### 3.6 提出假设

假设必须：

- 可证伪：说明反事实。
- 有机制：解释为什么会造成症状。
- 有范围：影响哪些路径，不影响哪些路径。
- 有优先级：按信息量和风险排序。

示例格式：

```text
假设：X 导致 Y。
机制：X 使 ...，所以 ...
预测：若成立，关闭 X 后 Y 应下降；打开 X 后 Y 应复现。
反事实：若关闭 X 后 Y 不变，假设不成立。
```

### 3.7 测量与判定

- 使用 `Evidence.md` 的等级和统计口径。
- 记录样本数、范围、中位数和噪声底。
- 单次样本只能作线索，不能作结论。
- 处理与基线使用同一实验、同一条件、同一输入。
- 先看原始数据，再看派生报告。
- 报告「没有可辨识差异」也是一种结论。

### 3.8 修复

要求：

- 一次只改一个原因。
- 保持不变量：顺序、所有权、生命周期、容量；协议字段变更必须显式记录。开发期可在同一协议标识下原位更新正文，发布后必须升版本，不能作为隐式调试改动。
- 有回退路径；没有证明就回退。
- 改客程序后重编映像；改宿主后跑类型检查和 lint。
- 不为了让报告好看而改观测口径。

### 3.9 回归

- 同一实验重复，至少覆盖基线、处理、回退。
- 检查相邻路径和负向路径，不只检查目标命令。
- 检查关闭开关时是否惰性。
- 检查观测开销是否超出预算。
- 记录没有改善或变差的样本。

### 3.10 记录与评审

记录必须包含：

- 问题陈述、环境、基线、假设、实验、原始数据、结论、限制。
- 被否决的假设和回退的候选。
- 下一步或明确关闭。

评审问题：

1. 症状和原因是否分开？
2. 证据等级是否足够？
3. 是否只有一个变量？
4. 反事实是否被检查？
5. 是否覆盖了关闭/异常/边界路径？
6. 是否把未覆盖写成正常？
7. 改动是否超出授权边界？
8. 下一次能否只靠记录复现？

## 4. 问题类型与默认策略

| 类型 | 首选观测 | 常见错误 |
|------|----------|----------|
| 功能错误 | 事件、状态快照、边界日志 | 只看最终错误码 |
| 延迟 | span、队列、计数 | 把并行 span 相加 |
| 吞吐 | 计数、时间窗、队列深度 | 用单次峰值 |
| 资源 | 计数、采样、容量 | 只看平均值 |
| 协议 | 边界事件、字节计数、配对 | 改协议字段来方便观测 |
| 回归 | 同批次基线、二分 | 换一组输入证明变快 |
| 安全/隔离 | 开关、访问点、负向测试 | 只测打开状态 |

## 5. 根因判定

至少满足：

- 时间顺序：原因先于结果。
- 机制：能解释结果如何产生。
- 可重复：同一条件下可复现。
- 反事实：移除原因，结果改变；恢复原因，结果回来。
- 排除：主要替代解释被排除。

不满足时，用「候选」「相关」「未定因」，不用「根因」。

## 6. 改动纪律

- 调试期间本地工作，不因调试新增大量提交或 tag。
- 需要提交时，一次提交只包含一个可解释的改动。
- 提交说明包含：问题、机制、基线/处理数字、回退条件。
- 没有可重复收益的候选必须回退；保留记录作为反例。
- 标准和实现同时更新；不允许代码和文档各说一套。一次实验的原始输出不写入 `Documents/Debug`。

## 7. 调试简报模板

```text
标题：
问题陈述：在 <条件> 下，<指标> 从 <基线> 偏离到 <观察>。
范围：涉及 <层/线程/设备>；不涉及 <非目标>。
环境：<版本/配置/开关/输入>。
已知模型：<边界/不变量>。
未知：<没有观测的部分>。
下一步：<复现/观测/隔离>。
成功标准：<指标范围>。
```

## 8. 退出条件

一次调试可以结束，当且仅当：

- 问题陈述被回答；或
- 明确判定为不可复现/不在当前范围；或
- 候选被证伪并记录。
- 原始数据、结论、限制和下一步留在当次运行的输出目录，不写入 `Documents/Debug`。

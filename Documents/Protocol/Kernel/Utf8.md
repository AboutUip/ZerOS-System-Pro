# UTF-8 · Unicode 标量

> 路径：`Documents/Protocol/Kernel/Utf8.md`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

内核交给显卡的是 Unicode 标量，不是字体文件，也不是固件点阵码点。符合本节的解码只产出标量，或在第一个非法字节序列处失败。

## 1. 规定

- 标量是闭区间 `0 .. 1114111` 的整数，并且不是 `55296 .. 57343`。
- 字节串按 UTF-8 解释。空串成功，标量序列为空。
- `U+0000` 是一个标量，字节 `00` 必须接受。
- 成功时，标量按字节顺序排列，不得重排，不得做规范化，不得把多个标量收成一个。
- 失败时必须给出第一个非法序列的起始字节下标，从 `0` 起。该下标之前的字节不得被当成已接受的标量交出去。

## 2. 字节序列

| 字节数 | 首字节 | 标量下限 | 标量上限 |
|--------|--------|----------|----------|
| 1 | `00 .. 7F` | `0` | `127` |
| 2 | `C2 .. DF` | `128` | `2047` |
| 3 | `E0 .. EF` | `2048` | `65535` |
| 4 | `F0 .. F4` | `65536` | `1114111` |

后续字节必须是 `80 .. BF`。序列被截断、首字节不在上表、或后续字节不在 `80 .. BF` 时，失败下标是该序列的首字节。

还须拒绝：

- 过短编码：解出的标量小于该字节数的下限，包括 `C0`、`C1` 和 `E0` 后面小于 `A0` 的后续字节；
- 代理项：标量落在 `55296 .. 57343`，包括 `ED A0 80` 至 `ED BF BF`；
- 超出 Unicode：标量大于 `1114111`，包括 `F4` 后面大于 `8F` 的第二个字节。

`U+10FFFF` 的字节是 `F4 8F BF BF`，必须接受。

## 3. 明确不规定

- UTF-16、UTF-32、BOM 的特殊含义。开头的 `EF BB BF` 就是标量 `U+FEFF`，不得删掉。
- 规范化、字素簇、双向算法、连字。两个标量保持两个标量。
- 字体里有没有这个标量。那是字体面的事，见 [../PhysicalHardware/Gpu/Font.md](../PhysicalHardware/Gpu/Font.md)。

## 4. 不符合示例

1. 把 `C0 80` 解成 `U+0000`。
2. 把 `ED A0 80` 解成一个代理项并继续。
3. 截断的 `E0 A0` 从后续字节报失败，而不是从 `E0`。
4. 失败时仍返回失败点之前的标量，调用方分不清整串是否合法。
5. 把 `65 CC 81` 收成单个 `U+00E9`。

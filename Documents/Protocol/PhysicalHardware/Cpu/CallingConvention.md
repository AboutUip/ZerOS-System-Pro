# ZAP 调用约定

> 文档路径：`Documents/Protocol/PhysicalHardware/Cpu/CallingConvention.md`  
> 规范状态：**规范性（Normative）**，约束使用短形式 `call` / `ret` / `icall` / `iret` 的程序、汇编器与编译器  
> 不构成 ZCP1 符合性条件。CPU 必须把 8 个寄存器当作同一种整数寄存器，禁止因本约定拒绝一条指令

寄存器文本名仍是 `r0` 至 `r7`。编号增加时沿用 `r` 加十进制编号。本约定不给寄存器另起硬件名字。

## 1. 职责

| 寄存器 | 职责 | 谁保存 |
|--------|------|--------|
| `r0` | 返回值 | 调用者。`call` 或 `icall` 返回之后，返回值在 `r0` |
| `r1` | 第 1 个参数，也可当临时 | 调用者 |
| `r2` | 第 2 个参数，也可当临时 | 调用者 |
| `r3` | 第 3 个参数，也可当临时 | 调用者 |
| `r4` | 第 4 个参数，也可当临时 | 调用者 |
| `r5` | 第 5 个参数，也可当临时 | 调用者 |
| `r6` | 第 6 个参数。`icall` / `iret` 的链接也占用这里 | 调用者；链接见 §2 |
| `r7` | `call` / `ret` 的链接 | 见 §2 |

第 7 个及以后的参数放在调用双方约定的存储里，每个 64 位。调用方按参数顺序放下，被调用方返回前把栈指针对回进入时的位置。

`rbx`、`rbp`、`r12`、`r13`、`r14`、`r15` 由被调用方保存。被调用方若改写它们，必须在返回前写回进入时的值。调用方不保存。

## 2. 短形式

汇编器必须把下列写法展开成 ZCP1 已有的指令，禁止展开成别的寄存器：

| 短形式 | 展开 |
|--------|------|
| `call 标号` | `link r7, 标号` |
| `ret` | `jmp r7` |
| `icall 标号` | `link r6, 标号` |
| `iret` | `jmp r6` |

`call rD, 编号` 与 `ret rD` 是 ZCP1 指令，寄存器由程序自己写明。本约定不改写它们。

被 `call` 进入的程序必须在改写 `r7` 之前把 `r7` 存进自己的存储，执行 `ret` 之前写回。被 `icall` 进入的程序对 `r6` 同样办理。嵌套调用前保存的是自己的链接，返回前写回的也是自己的链接。

默认的 `call` 把第 6 个整数参数放在 `r6`。当时若有活着的 `icall` 链接，必须先把链接存进存储，返回前写回，并且这次调用不再把第 6 个参数放在 `r6`。`icall` 的双方禁止把 `r7` 当数据，除非当时没有活着的 `call` 链接。带第 6 个参数的默认调用使用 `call`，不用 `icall`。

## 3. 借用

一条序列既不被 `call` / `icall` 进入，自己也不执行 `call` / `icall` 时，可以借用 `r6` 和 `r7` 存放数据。

`gpu.box` 的六个操作数已经占满 `r0` 至 `r5` 时，新编号可以写入 `r6` 或 `r7`。写入之前若该寄存器里有活着的链接，必须先存进存储，用完再写回，然后才能 `ret` 或 `iret`。

`chars "文本"` 改写 `r0`，并把每个字形交给 `r1` 里已经存在的文本节点。执行 `chars` 之前 `r1` 必须是该节点。

## 4. 本约定不规定

- CPU 如何检查寄存器编号；
- 把 `r0` 至 `r7` 改成带职责的硬件名字；
- 超过 8 个 ZAP 寄存器时的参数个数；
- 原生指令字节怎样压栈。那一条取指把线性位地址压进栈，见 [ZCP1.md](./ZCP1.md) §4.12。寄存器怎么对应见 §5；
- 原生 `0F 3F` 系统调用的回复寄存器。回复写入编码指定的原生寄存器，不是本节的 `r0`。

## 5. 原生编码

这一节只约束 `obrc` 写出的原生映像，不约束 CPU。CPU 仍禁止因参数所在的寄存器拒绝一条已登记编码。ZAP 文本名不变。

| 文本 | 原生寄存器 |
|------|------------|
| `r0` | `rax`，返回值 |
| `r1` | `rdi`，第 1 个参数 |
| `r2` | `rsi`，第 2 个参数 |
| `r3` | `rdx`，第 3 个参数 |
| `r4` | `rcx`，第 4 个参数 |
| `r5` | `r8`，第 5 个参数 |
| `r6` | `r9`，第 6 个参数。短形式 `icall` 仍展开成 `link r6`，所以带第 6 个参数的默认调用使用 `call` |
| `r7` | `r10`，`call` 链接 |

第 7 个及以后的参数仍在双方的存储里。`rbx`、`rbp`、`r12` 至 `r15` 不参与这 8 个文本名，编译器不分配它们。使用它们的被调用方必须保存并写回。

原生 `call` 执行时，`rsp` 里的八位组地址必须能被 16 整除。被调用方入口把 `rsp` 减 8，返回前加回。没有红色区：调用方不得假定 `rsp` 之下的八位组在 `call` 之后仍保持。

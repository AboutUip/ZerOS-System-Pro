# ZAP 调用约定

> 文档路径：`Documents/Protocol/PhysicalHardware/Cpu/CallingConvention.md`  
> 规范状态：**规范性（Normative）**，约束使用短形式 `call` / `ret` / `icall` / `iret` 的程序、汇编器与编译器  
> 不构成 ZCP1 符合性条件。CPU 必须把 8 个寄存器当作同一种整数寄存器，禁止因本约定拒绝一条指令

寄存器文本名仍是 `r0` 至 `r7`。编号增加时沿用 `r` 加十进制编号。本约定不给寄存器另起硬件名字。

## 1. 职责

| 寄存器 | 职责 | 谁保存 |
|--------|------|--------|
| `r0` | 返回值 | 调用者。`call` 或 `icall` 返回之后，返回值在 `r0` |
| `r1` | 第 1 个参数，也可当临时 | 调用者 |
| `r2` | 第 2 个参数，也可当临时 | 调用者 |
| `r3` | 第 3 个参数，也可当临时 | 调用者 |
| `r4` | 临时 | 调用者 |
| `r5` | 临时 | 调用者 |
| `r6` | `icall` / `iret` 的链接 | 见 §2 |
| `r7` | `call` / `ret` 的链接 | 见 §2 |

第 4 个及以后的参数放在调用双方约定的存储里，不占用 `r4`、`r5`。`r4` 与 `r5` 只做临时。

## 2. 短形式

汇编器必须把下列写法展开成 ZCP1 已有的指令，禁止展开成别的寄存器：

| 短形式 | 展开 |
|--------|------|
| `call 标号` | `link r7, 标号` |
| `ret` | `jmp r7` |
| `icall 标号` | `link r6, 标号` |
| `iret` | `jmp r6` |

`call rD, 编号` 与 `ret rD` 是 ZCP1 指令，寄存器由程序自己写明。本约定不改写它们。

被 `call` 进入的程序必须在改写 `r7` 之前把 `r7` 存进自己的存储，执行 `ret` 之前写回。被 `icall` 进入的程序对 `r6` 同样办理。嵌套调用前保存的是自己的链接，返回前写回的也是自己的链接。

`call` 的双方禁止把 `r6` 当数据，除非当时没有活着的 `icall` 链接。`icall` 的双方禁止把 `r7` 当数据，除非当时没有活着的 `call` 链接。

## 3. 借用

一条序列既不被 `call` / `icall` 进入，自己也不执行 `call` / `icall` 时，可以借用 `r6` 和 `r7` 存放数据。

`gpu.box` 的六个操作数已经占满 `r0` 至 `r5` 时，新编号可以写入 `r6` 或 `r7`。写入之前若该寄存器里有活着的链接，必须先存进存储，用完再写回，然后才能 `ret` 或 `iret`。

`chars "文本"` 改写 `r0`，并把每个字形交给 `r1` 里已经存在的文本节点。执行 `chars` 之前 `r1` 必须是该节点。

## 4. 本约定不规定

- CPU 如何检查寄存器编号；
- 把 `r0` 至 `r7` 改成带职责的硬件名字；
- 超过 8 个寄存器时的参数个数。个数增加之后，仍然是 `r0` 返回值，其后连续若干个做参数，最后两个编号保留给 `icall` 链接和 `call` 链接。

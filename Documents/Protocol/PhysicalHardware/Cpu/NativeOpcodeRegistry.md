## 0. 文档定位

本文登记 §4.12 必须直接执行的原生指令编码。未登记的字节序列必须失败，且不得改尚未写完的目的寄存器。

- 约束对象：声称兼容 ZCP1 并执行原生指令字节的实现。
- 这些字节不是 ZAP 文本，也不是 [CallingConvention.md](./CallingConvention.md) 的短形式。
- 禁止先把本表的字节编成 ZAP 指令下标再执行。

## 1. 编码规则

指令按小端读取。一条指令最多一个 `REX` 前缀，取值 `0x40` 至 `0x4F`。`REX` 的位 3 是 W，位 2 是 R，位 1 是 X，位 0 是 B。`0x64` 可以放在 `REX` 前面。它把本条非相对内存地址加上该任务的 `fsbase`。相对指令指针不加，`lea` 也不加。`fsbase` 来自兼容帧，这条前缀不改它。64 位整数运算必须带 W。没有 W、且本表没有把它登记成 32 位或 16 位形式的运算必须失败。`0x66` 后面只登记了 `0x83`。其它 `0x66` 与全部 `0x67` 必须失败。访存使用与 ZCP1 §4.6 相同的 bound。窗口外的读或写必须失败，且不得留下只写了一部分的 8 个八位组。`rsp` 减 8 后小于 0 时，`call` 与压栈必须失败，且不得改 `rsp`。

寄存器编号是 `0` 至 `15`。操作码低 3 位或 ModRM 的 3 位字段是编号的低 3 位。B 把 `r/m` 或立即数目标加上 `8`，R 把 ModRM 的 `reg` 加上 `8`，X 把 SIB 的变址加上 `8`。8 位写入只改目的那一个字节，其余位保持。没有 `REX` 时，字段 `4` 至 `7` 是 `AH`、`CH`、`DH`、`BH`，位置在第 8 至 15 位。有 `REX` 时这四个是 `SPL`、`BPL`、`SIL`、`DIL` 的低 8 位。

ModRM 的位 7–6 是 mod，位 5–3 是 reg，位 2–0 是 rm。

| mod | rm 低 3 位 | 操作数 |
|-----|------------|--------|
| `3` | 任意 | 寄存器。编号是 rm 低 3 位，B 为 1 时加 `8` |
| `0` | `5`，且不是 SIB | 相对本条下一八位组的 32 位位移 |
| `0` | `4` | 见 SIB。基址字段为 `5` 时没有基址，后面是 32 位位移 |
| `0` | 其它 | 基址寄存器，位移 `0` |
| `1` | 任意 | 8 位位移，按符号扩成 64 位 |
| `2` | 任意 | 32 位位移，按符号扩成 64 位 |

rm 低 3 位为 `4` 且 mod 不是 `3` 时，后面是 SIB。SIB 的位 7–6 是比例编码，位 5–3 是变址，位 2–0 是基址。比例编码 `0`、`1`、`2`、`3` 分别是比例 `1`、`2`、`4`、`8`。变址字段为 `4` 且 X 为 0 时没有变址。基址字段为 `5` 且 mod 为 `0` 时没有基址。

`rel32` 与位移都是小端。`rel32` 是从本条下一八位组起算的有符号八位组距离。线性位地址的增量是 `rel32 × 8`。本条末尾的立即数算在本条里面，相对位移从立即数之后的那个八位组起算。

| `0x0F`，`0x3F`，`0x06`，一个寄存器字节 | 调度该寄存器所指的核心 | 已登记 |
| `0x0F`，`0x3F`，`0x07`，一个寄存器字节 | 卸下该寄存器所指的核心 | 已登记 |
| `0x0F`，`0x3F`，`0x08`，三个寄存器字节 | 划定可访问范围。依次是核心、起点、长度 | 已登记 |
| `0x0F`，`0x3F`，`0x09`，一个寄存器字节 | 把本核心时间片设为该寄存器中的条数 | 已登记 |
| `0x0F`，`0x3F`，`0x0A` | 停在下一条。没有寄存器字节。停止原因是 `1` | 已登记 |
| `0x0F`，`0x3F`，`0x0B`，四个寄存器字节 | 查询。依次是结果、座位、字段、下标。座位必须是 `1` | 已登记 |
| `0x0F`，`0x3F`，`0x0C`，三个寄存器字节 | 装入程序。依次是核心、线性位地址、八位组长度 | 已登记 |
| `0x0F`，`0x3F`，`0x0D`，两个寄存器字节 | 把第一寄存器所指核心抄进第二寄存器所指的槽 | 已登记 |
| `0x0F`，`0x3F`，`0x0E`，两个寄存器字节 | 把第二寄存器所指的槽放回第一寄存器所指核心 | 已登记 |
| `0x0F`，`0x3F`，`0x0F`，两个寄存器字节 | 把第二寄存器中的整数设为第一寄存器所指核心的 Hz | 已登记 |
| `0x0F`，`0x3F`，`0x10`，四个寄存器字节 | 接入动态库。依次是结果、核心、线性位地址、八位组长度 | 已登记 |
| `0x0F`，`0x3F`，`0x11` | 交出画面。没有寄存器字节 | 已登记 |
| `0x0F`，`0x3F`，`0x12`，五个寄存器字节 | 画封闭点阵字形。依次是横坐标、纵坐标、码位、前景、背景 | 已登记 |
| `0x0F`，`0x3F`，`0x13`，六个寄存器字节 | 固定功能绘制。依次是结果、操作码、四个二进制 64 位型 | 已登记 |
| `0x0F`，`0x3F`，`0x14`，三个寄存器字节 | `xchg`。依次是口、方向、数据。结果写入第三个寄存器 | 已登记 |
| `0x0F`，`0x3F`，`0x15`，六个寄存器字节 | `carry`。依次是结果、口、句柄、偏移、位地址、个数 | 已登记 |
| `0x0F`，`0x3F`，`0x16`，两个寄存器字节 | `port.state`。结果写入第一个寄存器 | 已登记 |
| `0x0F`，`0x3F`，`0x17`，三个寄存器字节 | `port.char`。依次是结果、口、偏移 | 已登记 |
| `0x0F`，`0x3F`，`0x18`，四个寄存器字节 | `port.byte`。依次是结果、口、字段、偏移 | 已登记 |
| `0x0F`，`0x3F`，`0x19`，四个寄存器字节 | `mmap`。依次是结果、口、句柄、八位组个数。结果是起始位地址 | 已登记 |
| `0x0F`，`0x3F`，`0x1A`，两个寄存器字节 | `munmap`。依次是位地址、长度。不写结果寄存器 | 已登记 |
| `0x0F`，`0x3F`，`0x1B`，一个寄存器字节 | `dwell`。该寄存器是毫秒 | 已登记 |
| `0x0F`，`0x3F`，`0x1C`，两个寄存器字节 | `inbox`。第一个写入有没有，第二个写入值 | 已登记 |
| `0x0F`，`0x3F`，`0x1D`，四个寄存器字节 | `fill`。依次是结果、口、位地址、个数 | 已登记 |
| `0x0F`，`0x3F`，`0x1E`，三个寄存器字节 | `admit`。依次是核心、描述符位地址、描述符八位组数。八位组数必须是 `32` | 已登记 |
| `0x0F`，`0x05` | 兼容任务的系统调用。没有寄存器字节。原生程序执行必须失败 | 已登记 |

寄存器字节必须是 `0` 至 `15`。每条转义的寄存器个数是固定的，编码里没有计数字节。少一个字节，或未登记的编号，都必须失败，且不得改寄存器或指令指针。

客核心可以执行 `0x01` 和 `0x05`。客核心执行 `0x02`、`0x03` 或 `0x04` 必须失败，且不得改监督核或保持位。

`0x03` 的第一个寄存器里是目标核心编号，第二个是要放入的整数。目标未挂载，或该保持位已有值时，必须失败，且不得覆盖。

`0x05` 把 `调用者编号 × 2^32 + 服务号` 放进监督核的保持位。服务号必须是 `0` 至 `4294967295`。客程序停在下一条，停止原因是 `2`。核心保持执行中，只做不取客程序指令的空转。监督核把回复放进调用者的保持位后，下一次调度把该回复写入第一个寄存器所编号的原生寄存器，并从留下的线性位地址继续。回复不得写入 ZAP 的 8 个寄存器。没有监督核、调用者就是监督核，或监督核的保持位已满时，必须失败。

`0x06`、`0x07`、`0x08`、`0x0C` 的效果与 §4.6 的 `schedule`、`release`、`bound`、`install` 相同。寄存器里是操作数的值，不是 ZAP 寄存器编号。`0x09` 与 `slice` 相同，只改本核心。`0x0A` 与 `yield` 相同：留下下一条的线性位地址，核心回到停止，停止原因是 `1`。再次 `0x06` 从该位地址继续，不得从第一条重跑。`0x0B` 只查询座位 `1`；座位不是 `1` 时必须失败，且不得写结果寄存器。客核心执行 `0x06`、`0x07`、`0x08`、`0x0C` 按监督核规则失败。客核心可以执行 `0x09` 和 `0x0A`。

`0x0D` 与 `0x0E` 的效果与 §4.6 的 `capture`、`restore` 相同。`0x0F` 与 `hertz` 相同。`0x10` 与 `attach` 相同，入口编号写入第一个寄存器，不得写入 ZAP 的 8 个寄存器。客核心执行 `0x0D`、`0x0E`、`0x10` 按监督核规则失败。客核心执行 `0x0F` 必须失败，错误码 `22`，且不得改频率。

`0x11`、`0x12`、`0x13` 的效果与 §4.6 的 `gpu.present`、`gpu.character`、`gpu.accel` 相同。`0x13` 的后四个寄存器是二进制 64 的位型，结果写入第一个寄存器，不得写入 ZAP 的 8 个寄存器。客核心执行这三条必须失败，错误码 `22`，且不得把显卡命令送出。

`0x14` 至 `0x1D` 的效果与 §4.6 的 `xchg`、`carry`、`port.state`、`port.char`、`port.byte`、`mmap`、`munmap`、`dwell`、`inbox`、`fill` 相同。结果写入第一个寄存器；`0x14` 的结果写入第三个寄存器；`0x1A` 不写结果。除 `0x1B` 外，客核心执行必须失败，错误码 `22`，且不得改扩展口或存储。客核心可以执行 `0x1B`。

`0x1E` 的效果与 §4.13 的 `admit` 相同。客核心执行必须失败，且不得改目标；这次失败不使用错误码 `22`。`0F 05` 只在兼容任务里按 §4.13 陷入。原生程序执行 `0F 05` 必须失败，不得把服务号 `27` 交给监督核。

`0F 3E` 的操作字节：

| 操作 | 作用 |
|------|------|
| `0x01` / `0x02` | 64 位加、减。更新 ZF、SF、PF、CF、OF |
| `0x03` / `0x04` / `0x05` | 按位与、或、异或。CF 与 OF 清零，并更新 ZF、SF、PF |
| `0x06` | 有符号乘积的低 64 位。不改标志 |
| `0x07` / `0x08` | 有符号除、余，向 `0` 截断。除数为 `0` 必须失败 |
| `0x09` / `0x0A` | 无符号除、余。左值小于 `0` 或右值小于等于 `0` 必须失败 |
| `0x0B` / `0x0C` | 左移、算术右移。次数不在 `0` 至 `63` 必须失败，不得改成只取低 6 位 |
| `0x0D` 至 `0x11` | 有符号等于、小于、小于等于、大于、大于等于。目的写成 `0` 或 `1`，不改标志 |
| `0x12` | 按位取反 |
| `0x13` | 整数转二进制 64。结果不是有限值必须失败 |
| `0x14` 至 `0x19` | 二进制 64 的加、减、乘、除、幂、余。操作数或结果不是有限值必须失败。除或余的右值为 `0` 必须失败 |
| `0x1A` | 二进制 64 按原始位比较相等。两边都是非数时结果是 `0` |
| `0x20` / `0x21` | 位地址上的 64 位读、写。读按符号扩展 |
| `0x22` / `0x23` | 8 位读、写 |
| `0x24` / `0x25` | 16 位读、写 |
| `0x26` / `0x27` | 32 位读、写 |
| `0x28` / `0x29` | 二进制 64 的原始 8 个八位组读、写 |
| `0x2A` / `0x2B` | 二进制 32 与二进制 64 互转后读、写 |

访存时左寄存器是线性位地址，必须能被 `8` 整除。目的寄存器在读时接收结果，在写时提供要写的值。右寄存器字节必须是 `0` 至 `15`，不参与这次访存。写之前必须确认全部八位组都能写下，失败时不得留下只写了一部分的字节。未列出的操作字节必须失败。

加法、减法和比较的标志在 [ZCP1.md](./ZCP1.md) §4.12。

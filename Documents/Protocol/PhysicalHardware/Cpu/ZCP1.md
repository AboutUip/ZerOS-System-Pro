## 0. 文档定位与符合性

### 0.1 目的

本文是 **ZerOS CPU Protocol 第 1 版（ZCP1）** 的对外契约。

- 规定一份 CPU 实现必须声明的核心数上限，以及核心的调度、执行和核心间传递。
- 坐座主机只挂载或强制卸载核心。核心之间的交互由 CPU 实现自己完成。
- 第三方不得以查阅参考实现源码为前提理解本文。

### 0.2 规范性用语

| 用语 | 含义 |
|------|------|
| **必须（MUST）** | 违反即不符合 |
| **禁止（MUST NOT）** | 违反即不符合 |
| **应（SHOULD）** | 强烈建议 |
| **可以（MAY）** | 可选 |

### 0.3 符合性声明

仅当实现同时满足以下全部条件时，方可声称「完全兼容 ZCP1」：

1. 协议标识字符串精确为 `ZCP1`；
2. 提供本文全部必选字段与方法名，拼写与大小写逐字一致；
3. `CoreCount` 落在本文值域内，并且与该实现实际能够提供的核心数上限一致；
4. 不把本文「明确不规定」的内容宣称为协议要求。

### 0.4 字段名

规范名必须逐字使用。禁止用 `core_count`、`scheduleCore`、`send` 等近似名冒充兼容。

### 0.5 与参考实现的关系

参考实现不是规范。参考实现声明的核心数是标定值，不是协议常量。冲突时以本文为准。

## 1. 概述

符合本协议的 CPU 是调度与执行的主体。每个核心是一个独立执行单元。坐座主机按 `CoreCount` 挂载这些核心，并可以强制卸载已挂载的核心。核心之间的传递不经过坐座主机。

---

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZCP1`；
- `CoreCount` 的类型、值域和声明语义；
- 核心编号；
- 封闭的核心运行状态；
- 封闭的执行命令；
- 每个核心 8 个寄存器，编号 `0` 至 `7`；
- `Schedule`、`Halt`、`CoreState`、`Place`、`Add`、`Load`、`Store`、`Pass`、`Take`、`SetHertz`、`Metric`；
- 坐座主机对挂载数量和强制卸载的义务，以及它不转达核心间传递；
- 汇编语言的简称 `ZAP`。§4.6 的每一行就是一条 ZAP 指令。
- §4.12 的原生指令字节、16 个原生整数寄存器，以及线性位地址上的指令指针。

### 2.2 本协议明确不规定

下列事项不在本文内。禁止宣称为 ZCP1 已规定：

- 进程、地址空间、分页、系统调用，以及进程、文件和用户的权限；
- 把 ZAP 文本当成机器码字节。原生指令的编码只以 §4.12 为准；
- 汇编器这一程序本身，以及 ZAP 文本存放在哪一种文件里；
- 核心内部的流水线、缓存、分支预测；
- 坐座主机用哪一种宿主线程实现一个核心；
- 参考实现的核心数标定值；
- 显示器、总线；
- 八个寄存器谁传返回值、谁做参数、谁保存链接。CPU 必须把它们当作同一种整数寄存器。短形式 `call` / `ret` / `icall` / `iret` 的分工见 [CallingConvention.md](./CallingConvention.md)，该约定不是 ZCP1 符合性条件。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 核心数 | 该实现能够提供的核心上限，字段名 `CoreCount` |
| 核心编号 | 从 0 起、小于 `CoreCount` 的整数 |
| 挂载 | 坐座主机使一个核心编号进入可被 CPU 调度的状态 |
| 强制卸载 | 坐座主机撤掉一个已挂载核心。CPU 实现必须不再把它当作可调度核心 |
| 执行命令 | `Place`、`Add`、`Load`、`Store` 之一。`Load` / `Store` 才访存 |

正整数按数学整数理解。`CoreCount` 与核心编号禁止用非整数、NaN、Infinity 冒充。

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZCP1` |
| 核心数下限 `CoreCountMin` | `1` |
| 核心数上限 `CoreCountMax` | `256` |
| 上下文槽下限 `SlotCountMin` | `1` |
| 上下文槽上限 `SlotCountMax` | `256` |
| 停止 `CoreStateHalted` | `0` |
| 执行中 `CoreStateRunning` | `1` |
| 寄存器个数 `RegisterCount` | `8` |
| 频率下限 | `1` |
| 频率上限 | `1000000000` |
| 指标 `Hertz` | `0` |
| 指标 `Executed` | `1` |

运行状态只有 `0` 和 `1`。禁止另增状态值并仍声称兼容本版。

### 4.1 CoreCount

符合本协议的实现必须提供字段 `CoreCount`。

- 类型：整数。
- 值域：`1` 以上且 `256` 以下，含两端。
- 单位：核心个数。
- 语义：该实现的核心数上限。编号 `0` 至 `CoreCount - 1` 是它能够提供的全部核心。
- 单核实现必须把 `CoreCount` 标为 `1`。禁止把只能跑一个核心的实现标成更大的数。
- 坐座主机禁止挂载编号大于或等于 `CoreCount` 的核心。

### 4.1.1 SlotCount

符合本协议的实现必须声明上下文槽个数 `SlotCount`。

- 类型：整数。
- 值域：`1` 以上且 `256` 以下，含两端。
- 单位：槽个数。
- 语义：`capture` 与 `restore` 可以使用的槽。编号 `0` 至 `SlotCount - 1` 全部可用。协议不规定槽对应哪一份任务，也不规定一台机器必须只有 8 个槽。
- 声明小于实际能够保存的槽数，或大于 `256`，都不符合本协议。

### 4.2 调度

CPU 实现必须提供：

| 方法 | 含义 |
|------|------|
| `Schedule(Ordinal)` | 已挂载的该编号进入 `1`（执行中） |
| `Halt(Ordinal)` | 已挂载的该编号进入 `0`（停止） |
| `CoreState(Ordinal)` | 返回 `0` 或 `1` |

编号未挂载、或落在 `0 .. CoreCount-1` 之外时，这三个调用必须失败，并且不得改变其它核心的状态。

停止中的核心禁止执行命令。

### 4.3 寄存器

每个已挂载核心有 `8` 个寄存器。编号是 `0` 至 `7` 的整数。

- 每个寄存器持有一个整数，不设固定位宽，不按 `2^n` 取模。
- 核心刚挂上时，8 个寄存器都是 `0`。
- 编号不是 `0` 至 `7` 的整数时，任何使用该编号的命令必须失败，且不得改写任何一个寄存器，也不得访问存储。
- 寄存器不属于存储体。坐座主机禁止读取或改写寄存器。
- 核心间保持位不是寄存器。`Pass` / `Take` 不得改写寄存器。
- 这 8 个寄存器没有各自的硬件职责。返回值、参数和链接的分工不在本协议内，见 [CallingConvention.md](./CallingConvention.md)。

### 4.4 写入与相加

这两条命令只使用寄存器，禁止访问存储。

| 方法 | 含义 |
|------|------|
| `Place(Ordinal, Register, Data)` | 把整数 `Data` 写入该寄存器 |
| `Add(Ordinal, Destination, Left, Right)` | `Destination = Left + Right`，和是精确整数 |

`Left`、`Right`、`Destination` 都是寄存器编号。允许三者相同：先读出左、右操作数，再写入目的寄存器。

核心不是执行中或未挂载时，两条命令都必须失败，且不得改写寄存器。

### 4.5 访存命令

执行命令的操作码是封闭集合：

| 操作码 | 方向 | 字宽（位） |
|--------|------|------------|
| `1` | 读 | `1` |
| `2` | 写 | `1` |
| `3` | 读 | `8` |
| `4` | 写 | `8` |
| `5` | 读 | `16` |
| `6` | 写 | `16` |
| `7` | 读 | `32` |
| `8` | 写 | `32` |
| `9` | 读 | `64` |
| `10` | 写 | `64` |

`Load(Ordinal, Opcode, Address, Register)` 把一次读访存的结果写入该寄存器。操作码必须是上表中的读操作码。

`Store(Ordinal, Opcode, Address, Register)` 把该寄存器里的整数写入存储。操作码必须是上表中的写操作码。

- `Address` 是线性位元下标，类型为整数，允许大于 `2^53-1` 的整数。
- 字宽大于 `1` 时，`Address` 必须能被 `8` 整除。否则必须失败，且不得写出部分数据，也不得改写寄存器。
- 读命令成功时，寄存器变为读出的整数，低位是窗口的最低有效位。
- 写命令使用寄存器里的整数，成功时不改写寄存器，也不产生读出值。
- 读操作码交给 `Store`，或写操作码交给 `Load` 时，必须失败，且不得访问存储。
- 核心不是执行中、未挂载、或操作码不在表内时，必须失败，且不得访问存储。读失败时不得改写目标寄存器。

存储体本身不是本协议的对象。坐座主机完成这一次访存。CPU 实现禁止绕过坐座主机去读写存储体。

### 4.6 指令序列

一条指令是汇编语言 ZAP 的一行。简称必须逐字为 `ZAP`。这些行不是机器码字节。坐座主机可以把一段 ZAP 交给一个已挂载核心，由该核心从第一条执行到 `halt` 或序列结束。

| 指令 | 作用 |
|--------|------|
| `place rN, 整数` | 写入寄存器 |
| `core rD` | 把正在执行这条指令的核心编号写入 `rD`。编号从 `0` 起。任何程序都能用它找到自己的数据，不依赖调用者事先放入寄存器 |
| `add rD, rL, rR` | 精确相加 |
| `load.bit` / `load.octet` / `load.16` / `load.32` / `load.64` / `load.f32` / `load.f64` `rN, 地址` | 读访存进寄存器。`load.f32` 与 `load.f64` 读出的是浮点位型的补码整数 |
| `store.bit` / `store.octet` / `store.16` / `store.32` / `store.64` / `store.f32` / `store.f64` `rN, 地址` | 寄存器写入存储。宽度 2、4、8 个八位组以及两种浮点写入，使用该宽度的补码 |
| `gpu.clear rP` | 把寄存器里的像素交给显卡 `Clear` |
| `gpu.plot rX, rY, rP` | 交给显卡 `Plot` |
| `gpu.character rX, rY, rC, rF, rB` | 交给显卡 `Character` |
| `gpu.box rD, rP, rX, rY, rW, rH, rF` | `SpawnBox`，新编号写入 `rD` |
| `gpu.text rD, rP, rX, rY, rW, rH` | `SpawnText`，新编号写入 `rD` |
| `gpu.align rN, rX, rY` | `Align` |
| `gpu.paint rN, rF, rB` | `Paint` |
| `gpu.glyph rN, rC` | `Glyph` |
| `gpu.drop rN` | `Drop` |
| `gpu.compose` | `Compose` |
| `gpu.present` | 交给显卡 `Present` |
| `halt` | 该核心进入停止，不再取下一条 |
| `hertz rN, rH` | 把 `rH` 里的整数设为 `rN` 所指核心的 Hz，并记下 |
| `metric rD, rN, rK` | 把 `rN` 所指核心的指标 `rK` 写入 `rD`。`0` 是 Hz，`1` 是已完成条数 |
| `eq rD, rL, rR` | `rD` 为 `1` 当且仅当 `rL` 与 `rR` 相等，否则为 `0` |
| `lt rD, rL, rR` | `rD` 为 `1` 当且仅当 `rL` 小于 `rR`，按数学整数序，否则为 `0` |
| `le rD, rL, rR` | `rD` 为 `1` 当且仅当 `rL` 小于或等于 `rR` |
| `gt rD, rL, rR` | `rD` 为 `1` 当且仅当 `rL` 大于 `rR` |
| `ge rD, rL, rR` | `rD` 为 `1` 当且仅当 `rL` 大于或等于 `rR` |
| `feq rD, rL, rR` | 把 `rL`、`rR` 当作二进制 64。按 IEEE 754 相等则 `rD` 为 `1`，否则为 `0`。`NaN` 与任何位型都不相等，`+0` 与 `-0` 相等。位型放不进 64 位时失败 |
| `jz rC, 编号` | `rC` 为 `0` 时，下一条改为这段文本里的该编号 |
| `jnz rC, 编号` | `rC` 不为 `0` 时，下一条改为这段文本里的该编号 |
| `inbox rF, rV` | 从坐座主机的入站队列取出一个整数写入 `rV`。取到则 `rF` 为 `1`，队列空则 `rF` 与 `rV` 都为 `0` |
| `xchg rP, rD, rV` | 把 `rV` 里的无符号 64 位整数按小端 8 个八位组，与扩展口 `rP` 做一次方向 `rD` 的交换。返回的 8 个八位组写回 `rV` |
| `fill rD, rP, rA, rN` | 把扩展口 `rP` 上已经准备好、尚未取走的应答写到线性地址 `rA`，相邻八位组相隔 8 个位元。至多 `rN` 个，且 `rN` 不得大于 `4096`。`rD` 是写入的个数。设备状态不是成功时 `rD` 为该状态的相反数，且不得写入 |
| `carry rD, rP, rH, rO, rA, rN` | 向扩展口 `rP` 按句柄 `rH`、偏移 `rO` 读取至多 `rN` 个八位组，写到 `rA`，相邻八位组相隔 8 个位元。`rN` 不得大于 `268435456`。成功时 `rD` 是写入个数。失败时 `rD` 是状态的相反数，且不得写入。返回前会话必须已经结束 |
| `port.state rD, rP` | 把扩展口 `rP` 的状态写入 `rD` |
| `port.char rD, rP, rI` | 把扩展口 `rP` 上 `DeviceProtocol` 的第 `rI` 个字符码写入 `rD` |
| `port.byte rD, rP, rF, rI` | 扩展口 `rP` 上字段 `rF` 的第 `rI` 个字符码写入 `rD`。`0` 是 `DeviceProtocol`，`1` 是 `ProviderId`，`2` 是 `ProviderVendor` |
| `sub rD, rL, rR` | `rD` 等于 `rL` 减 `rR`，精确整数，不截断 |
| `mul rD, rL, rR` | `rD` 等于 `rL` 乘 `rR`，精确整数，不截断。负数按数学乘法 |
| `div rD, rL, rR` | `rD` 等于 `rL` 除以 `rR` 的商，向 0 截断。`rR` 为 `0` 时失败 |
| `mod rD, rL, rR` | `rD` 等于 `rL − rR × div(rL, rR)`。`rR` 为 `0` 时失败 |
| `and rD, rL, rR` | 按无限补码做按位与，结果不截断 |
| `or rD, rL, rR` | 按无限补码做按位或，结果不截断 |
| `xor rD, rL, rR` | 按无限补码做按位异或，结果不截断 |
| `not rD, rS` | `rD` 等于 `rS` 的按位取反，即 `−rS−1` |
| `itof rD, rS` | 把 `rS` 里的数学整数换成最接近的有限二进制 64，写入 `rD`。整数超出有限二进制 64 的范围时失败 |
| `shl rD, rL, rR` | `rD` 等于 `rL` 左移 `rR` 位，精确，不截断。`rR` 不在 `0` 至 `63` 时失败 |
| `shr rD, rL, rR` | `rD` 等于 `rL` 算术右移 `rR` 位，符号保留。`rR` 不在 `0` 至 `63` 时失败 |
| `fadd rD, rL, rR` | 把 `rL`、`rR` 里的二进制 64 位型相加，有限位型写回 `rD`。操作数或结果不是有限数时失败 |
| `fsub rD, rL, rR` | 二进制 64 相减。失败条件同 `fadd` |
| `fmul rD, rL, rR` | 二进制 64 相乘。失败条件同 `fadd` |
| `fdiv rD, rL, rR` | 二进制 64 相除。除数位型是 0，或结果不是有限数时失败 |
| `fpow rD, rL, rR` | 二进制 64 的幂，底数是 `rL`，指数是 `rR`。操作数或结果不是有限数时失败 |
| `fmod rD, rL, rR` | 二进制 64 的余数，被除数是 `rL`，除数是 `rR`，向零截断。除数是 0，或操作数、结果不是有限数时失败 |
| `call rD, 编号` | 与 `link` 相同：把下一条编号写入 `rD`，然后跳到该编号 |
| `ret rD` | 与 `jmp` 相同：跳到 `rD` 里的编号 |
| `udiv rD, rL, rR` | `rD` 等于 `rL` 除以 `rR` 的商。两者都必须是非负整数，`rR` 为 `0` 时失败 |
| `umod rD, rL, rR` | `rD` 等于 `rL` 除以 `rR` 的余数。两者都必须是非负整数，`rR` 为 `0` 时失败 |
| `link rD, 编号` | 把下一条的编号写入 `rD`，然后跳到该编号 |
| `jmp rD` | 跳到 `rD` 里的编号。编号不在这段文本里时失败 |
| `ldi.octet` / `ldi.16` / `ldi.32` / `ldi.64` / `ldi.f32` / `ldi.f64` `rD, rA` | 把 `rA` 所指线性位元地址上的该宽度读进 `rD`。对齐和补码与同宽度的 `load` 相同 |
| `sti.octet` / `sti.16` / `sti.32` / `sti.64` / `sti.f32` / `sti.f64` `rS, rA` | 把 `rS` 按该宽度写到 `rA` 所指的线性位元地址 |
| `query rD, rS, rF, rI` | 把座位 `rS` 的字段 `rF`、下标 `rI` 读进 `rD`。座位与字段见 [QueryRegistry.md](./QueryRegistry.md) |
| `install rC, rA, rN` | 把一段程序映像装到核心 `rC`。目标正在执行时先停在下一条边界。`rA` 是线性位元地址，`rN` 是八位组长度。成功后目标仍停止 |
| `admit rC, rA, rN` | 把核心 `rC` 放进兼容任务。`rA` 是 32 个八位组的描述符，`rN` 必须是 `32`。全机同时一份。成功后目标仍停止。见 §4.13 |
| `schedule rC` | 请求坐座对核心 `rC` 做 `Schedule`。目标已在执行时不得从头再跑 |
| `slice rN` | 把本核心每一轮最多执行的指令数设为 `rN`。`0` 表示直到 `halt` 或序列结束 |
| `pass rT, rV` | 把 `rV` 里的整数放进核心 `rT` 的空保持位 |
| `take rF, rV` | 取出本核心的保持位。取到则 `rF` 为 `1` 且 `rV` 为该整数；空则 `rF` 与 `rV` 都为 `0`，不得失败 |
| `svc rD, rS` | 把服务号 `rS` 交给监督核。客程序停在下一条。核心保持执行中，只做不取客程序指令的限速空转。回复稍后写入 `rD` |
| `bound rC, rA, rN` | 把核心 `rC` 的可访问位元设为从 `rA` 起的 `rN` 位。监督核自己不受这道限制 |
| `gate` | 当前核心成为监督核。已经有监督核时失败 |
| `release rC` | 卸下核心 `rC`。目标正在执行时先停在下一条边界。序列清空，可访问长度变为 `0`，寄存器清零，并清掉只对这颗核心可见的已写入八位组 |
| `yield` | 停在下一条。寄存器保留。下一次从停止进入执行中时从这条的下一条继续 |
| `dwell rT` | 按 `rT` 里的宿主毫秒等待后再取下一条。必须是 `0` 至 `1000`。等待期间核心保持执行中，寄存器不变 |
| `mmap rD, rP, rH, rN` | 把扩展口 `rP` 上句柄 `rH` 的前 `rN` 个八位组映射进线性位元。`rD` 写入起始位元地址。页长 `4096` 个八位组，按页调入 |
| `munmap rA, rN` | 卸下 `mmap` 返回的起始地址 `rA`、长度 `rN`。卸下之后再读这段必须失败 |
| `capture rC, rN` | 把核心 `rC` 抄进槽 `rN`。目标正在执行时先停在下一条边界。槽号是 `0` 至 `SlotCount - 1`。抄走 8 个寄存器、留下的下一条、停止原因、时间片、已装入序列，以及只对这颗核心可见的已写入八位组。不改这颗核心上已经停下的内容 |
| `restore rC, rN` | 把槽 `rN` 放回核心 `rC`。目标正在执行时先停在下一条边界。只对核心可见的八位组按原来的线性位元地址替换。放回后仍是停止。空槽必须失败，且不得改目标 |
| `attach rD, rC, rA, rN` | 把 `rA` 起、`rN` 个八位组的动态库接到核心 `rC` 的指令末尾。目标正在执行时先停在下一条边界。`rD` 写入第一个导出在这条序列里的指令编号。成功后目标仍停止 |
| `gpu.hertz rH` | 把 `rH` 里的整数设为显卡 Hz |
| `gpu.metric rD, rK` | 把显卡指标 `rK` 写入 `rD`。`0` 是 Hz，`1` 是已完成条数 |
| `gpu.load rD, rA` | 把显存地址 `rA` 上的一个字节写入 `rD` |
| `gpu.store rA, rV` | 把 `rV` 的低 8 位写到显存地址 `rA` |
| `gpu.accel rD, rOp, rA, rB, rC, rE` | 按 `rOp` 做一次 WebGPU 加速的固定功能绘制。四个参数是二进制 64 位型。操作码见 [AccelRegistry.md](../Gpu/AccelRegistry.md)。结果写入 `rD` |
| `mem.hertz rH` | 把 `rH` 里的整数设为内存 Hz |
| `mem.metric rD, rK` | 把内存指标 `rK` 写入 `rD`。`0` 是 Hz，`1` 是已完成条数 |

`install rC, rA, rN` 让正在执行的程序请求坐座主机，把一段程序映像装到另一颗核心。`rC`、`rA`、`rN` 都是寄存器编号。

- 目标必须已经挂载，并且不是正在执行这条指令的核心。目标正在执行时，必须先停在下一条指令的边界上，停止原因是 `1`，寄存器和下一条保留，然后这条指令再按已经停止的目标继续。不得等目标自己执行 `yield`。抢占之后若这条指令失败，目标留在这次抢占写下的停止状态，不得自动再调度。`release`、`capture`、`restore`、`attach`、`bound` 的另一颗正在执行的目标同样先抢占。`bound` 的目标就是执行它的核心时不抢占。
- `rA` 里的线性位元地址必须能被 `8` 整除。`rN` 里的长度必须是非负整数，单位是八位组。
- 坐座主机把该跨度上的八位组读一次，并按它接受一段程序时使用的同一种映像解码。这段字节的布局不是机器码，也不在本节规定如何逐条取指。
- 成功时，目标的指令序列换成按重定位改过的解码结果，下一条是第一条，`8` 个寄存器都是 `0`，只对目标核心可见的已写入八位组被清掉，运行状态仍是停止。映像若带链接目录且种类是可执行程序，目标的导出与尚未接上的导入换成这份目录；没有目录时这两份是空的。种类是动态库的映像必须失败，目标不变。重定位对不上时同样失败，且不得先清寄存器。
- 失败时，目标的序列、寄存器和只对它可见的已写入八位组都保持原样。抢占已经写下的停止保留，不得再自动调度。没有发生抢占时，运行状态也保持原样。这条指令失败，不得再取下一条。
- 目标执行期间不得把这段地址当作取指来源。新的成功装入替换旧序列，下一条改回第一条，寄存器只在装入成功时清零，时间片改回 `0`。
- 没有保留下一条时，目标从停止进入执行中，必须从装入序列的第一条执行。`halt` 或序列结束会忘掉下一条。
- `yield` 与时间片用尽会留下下一条和全部寄存器，运行状态回到停止。下一次从停止进入执行中时从留下的那一条继续，时间片重新数这一轮。
- `dwell` 把 `rT` 里的整数当作宿主墙上的毫秒，不按该核心的 Hz 折算。这个整数必须是 `0` 至 `1000`（含两端）。`0` 不得等待，立即取下一条。正数必须在取下一条之前等待这么多毫秒：核心保持执行中，8 个寄存器不得改变，已完成条数加上 1，其它核心可以继续执行。抢占在这次等待结束之后、下一条之前生效；因此抢占最多再等 1000 毫秒。超出范围必须失败，错误码 `23`（见 [FaultRegistry.md](./FaultRegistry.md)），不得等待，也不得取下一条。`dwell` 不是 `yield`：它不得把核心改成停止。
- `mmap` 把扩展口上一个已经打开的句柄映射进线性位元。`rN` 必须是 `1` 至 `268435456`。成功时 `rD` 是起始位元地址，并且能被 `8` 整除。保留长度向上取整到页。页长固定是 `4096` 个八位组。某一页第一次被读到时，必须用一次搬运从该句柄的对应偏移读入这一页，然后这次读以及以后对这一页的读都从线性位元完成，不得再访问扩展口。失败时不得留下可继续读的半页，错误码 `24`。`munmap` 的 `rA` 与 `rN` 必须等于某一次仍有效的 `mmap` 结果和当时的 `rN`。成功后这段地址再读必须失败，错误码 `24`。重复卸下同一段也失败。客核心执行 `mmap` 或 `munmap` 按错误码 `22` 失败，不得映射。
- `svc` 会留下下一条和全部寄存器，停止原因是 `2`。客程序不得继续取指，寄存器不得被这次等待改写，已完成条数不得因此增加。核心必须保持执行中，并且只做不取客程序指令的空转。这趟空转必须让出宿主，不得占满。`Schedule` 结束空转，把回复写入 `rD`，并从留下的那一条继续。
- 时间片是 `0` 时，序列一直执行到 `halt` 或结束，中间不因条数停下。
- 核心已经在执行时，`Schedule` 与 `schedule` 不得把该序列从头再跑。
- `gate` 成功之后，只有监督核可以 `install`、`schedule`、`bound`、`release`、`capture`、`restore`、`attach`。在此之前，正在执行的核心都可以。`release` 不得卸下自己。`bound` 的长度是 `0` 时，该核心除监督核外的访存必须失败。
- 监督核成功执行 `install` 或 `bound`，且目标不是监督核自己时，目标成为客核心。尚未出现监督核时，不得把任何核心当成客核心。监督核对自己执行 `bound` 时，自己仍不是客核心。`release` 成功后目标不再是客核心。`capture` 与 `restore` 不改变这一标记。没有被这样装入或划定的核心，包括监督核出现之前就已经在执行的核心，仍可执行本节列出的全部指令。
- 客核心可以执行运算、跳转、调用、访存、`halt`、`yield`、`slice`、`dwell`、`core`、`svc`。访存仍受该核心的 `bound` 约束。`query` 的座位必须是 `1`：字段 `0` 至 `4` 可以查任意下标，字段 `5` 至 `12` 的下标必须是正在执行这条指令的核心自己。
- 客核心执行显卡指令、`port.state`、`port.char`、`port.byte`、`xchg`、`inbox`、`fill`、`carry`、`mmap`、`munmap`、`mem.hertz`、`mem.metric`、`hertz`、`metric`、`pass`、`take`、`gate`，或不符合上一条的 `query` 时，必须失败，错误码 `22`（见 [FaultRegistry.md](./FaultRegistry.md)）。失败时不得把显卡命令送出，也不得改其它核心。`install`、`schedule`、`bound`、`release`、`capture`、`restore`、`attach` 仍按原有的监督核规则失败，不改用错误码 `22`。
- `capture` 与 `restore` 的目标必须是另一颗已挂载的核心。目标正在执行时先按本节的抢占规则停下。槽号必须落在 `0` 至 `SlotCount - 1`。实现声明的槽全部可用，协议不把槽数固定成 8。槽保存寄存器、下一条、停止原因、时间片、已装入序列，以及这份序列上的导出和尚未接上的导入。槽不保存可访问范围，也不保存 Hz。若实现把一部分线性八位组只留给写入它的那颗核心，使其它核心的读操作观察不到这些写入，则槽还必须保存这些八位组，以及该核心自己持有、没有进入共享线性位元的帧字和临时字。这些八位组带着当时的线性位元地址，`restore` 不得把它们换算到另一颗核心的窗口。没有这种私有写入的实现，保存的集合是空的，`capture` 与 `restore` 仍然成功。`restore` 用槽里的集合替换目标上的对应内容，不得启动目标。空槽上的 `restore` 必须失败，且不得改目标。`install` 与 `release` 成功时必须清掉目标上的这份私有写入，失败时不得清。`release` 同时清掉导出和导入。这两个指令不是进程，也不规定槽号对应哪一份任务。
- `attach` 的目标必须是另一颗已挂载、已经有指令序列的核心。目标正在执行时先按本节的抢占规则停下。`rA` 必须按 `8` 对齐，`rN` 是非负的八位组长度。映像必须是下面这种版本 2、种类 2 的动态库。失败时不得改目标的序列、导出、导入、寄存器或运行状态。成功时把库的指令接在已有序列后面，不改下一条，不清寄存器，也不清只对该核心可见的已写入八位组。
- 映像前四个八位组是 `5A 4E 42 31` 时，这是原生指令映像，不按 `5A 50 42 31` 的 ZAP 映像解码。随后两个八位组是小端版本，必须是 `1`。再两个八位组是小端标志，必须是 `0`。再四个八位组是小端代码长度，单位是八位组，必须至少为 `1`，并且 `12 + 长度` 不得超过这次给出的字节数。代码从第 12 个八位组起，按 [NativeOpcodeRegistry.md](./NativeOpcodeRegistry.md) 取指。长度之后的字节必须忽略，不得当成链接目录。装入成功后目标仍停止，ZAP 序列必须是空。被调度时从代码第一个八位组的线性位地址开始，16 个原生寄存器都是 `0`。此后对这串代码八位组的取指不得因 `bound` 失败。数据访存仍使用 `bound`。版本、标志或长度不合格时必须拒绝，且不得改目标。
- 程序映像版本 1 只有文件头和指令，读完必须正好用尽字节。版本 2 在这些指令之后还有链接目录，目录读完也必须正好用尽。文件头 12 个八位组不变：`5A 50 42 31`、版本、小端标记 `1`、指令条数。目录先是种类（`1` 可执行，`2` 动态库）、标志（必须是 `0`）、导出个数、导入个数、重定位个数，四个个数都是小端 32 位。导出和导入各自不超过 `256`，重定位不超过 `4096`。每个名字是 1 至 64 个八位组，每个八位组在 `0x21` 至 `0x7E`，前面一个长度字节，后面一个小端 32 位编号。导出的编号是本映像里的指令下标。导入的编号是本映像里要改掉的那条跳转。重定位是 32 位指令下标、1 个字段、1 个必须为 `0` 的填充，再加一个小端有符号 64 位加数。字段 `0` 改数据立即数，`1` 改跳转编号。其它版本、种类、字段或个数必须拒绝。
- 接到已有序列时，代码重定位的新编号是加数加上这段库的起始下标。整段换上可执行映像时，起始下标是 `0`，新编号就是加数。数据重定位的新立即数是加数加上目标核心相对 0 号核心的数据窗口位移；没有多窗口的实现，这个位移是 `0`。加数本身按 0 号核心窗口记录。跳转编号必须落在接好或换上的序列之内，数据立即数必须落在有符号 64 位里。`install` 必须在清寄存器和替换序列之前做完这些修改；任一条失败则目标不变。
- 库自己的导入按名字匹配目标上已经有的导出。对不上则失败且不改目标。对上的，那条跳转改成导出的现成编号，不再加起始下标。目标上同名的未接导入改成「库内下标 + 起始下标」，并从待接名单里去掉。新导出记成同样的绝对下标。`rD` 写入目录里第一个导出的这个绝对下标。若每个导出名字都已经在，不得再追加，`rD` 写入已有的那个编号。有的名字已经在、有的不在，则失败且不改目标。同一核心上的两份任务若共用一条指令序列，库的指令和数据立即数也共用；换任务时槽里的序列和名单一起换回。
- `svc` 把 `调用者编号 × 2^32 + 服务号` 放进监督核的保持位。服务号必须是 `0` 至 `4294967295`。监督核把回复放进调用者的保持位后再 `Schedule`，调用者才把回复写入 `rD` 并从下一条继续。保持位已满、没有监督核、或调用者就是监督核时，`svc` 失败。
- 调用者不是客核心时，`take` 在保持位为空时不得失败。`pass` 在目标保持位已有值时必须失败且不得覆盖。客核心执行这两条指令时按错误码 `22` 失败，保持位不变。

这些指令不是进程，也不是分页。本协议不规定地址如何换算，也不规定服务号的含义。

`rN` 是 `r0` 至 `r7`。整数可以写成十进制或 `0x` 十六进制。跳转编号从这段文本的第 `0` 条算起，空行不占编号。编号不在这段文本里时必须失败，且不得继续取指。显卡命令一次只转发一条，坐座主机不解释像素。`gpu.image` 不在本表：图像的像素序列放不进寄存器。`xchg` 一次只交换 8 个八位组。`fill` 把该口上已经准备好的更长应答一次写到位元线。`rA` 必须能被 `8` 整除，`rN` 必须是 `0` 至 `4096` 的整数。超出时失败，且不得写入。效果与该口领域协议里取走这些尚未取走的八位组相同，不要求客机再逐个八位组执行 `xchg`。`carry` 的 `rN` 必须是 `0` 至 `268435456` 的整数。超出时失败，且不得写入。一次能读多少由该口的领域协议在这个上界之内规定。`mem.hertz` 与 `mem.metric` 读写的是内存自己的 Hz，不是处理器的 Hz。

核心不是执行中时，序列中的下一条必须失败，并且不得继续取指。

### 4.7 核心间传递

每个已挂载核心有一个保持位。空或持有一个整数，二者只居其一。

| 方法 | 含义 |
|------|------|
| `Pass(FromOrdinal, ToOrdinal, Data)` | 把整数放入目标核心的空保持位 |
| `Take(Ordinal)` | 取出并清空该核心的保持位 |

目标保持位已经有值时，`Pass` 必须失败且不得覆盖。保持位为空时，`Take` 必须失败。任一编号未挂载或越界时必须失败。

坐座主机禁止转达 `Pass` 或 `Take`。

### 4.8 坐座主机

启用本协议的坐座主机必须：

1. 只挂载编号落在 `0 .. CoreCount-1` 的核心；
2. 能够强制卸载已挂载核心；
3. 强制卸载之后，该编号不再处于可调度状态，直到再次挂载。

坐座主机可以在上电时挂载全部已声明核心，也可以少挂。禁止挂载超过 `CoreCount`。

### 4.9 必选成员

`CoreCount`、`Schedule`、`Halt`、`CoreState`、`Place`、`Add`、`Load`、`Store`、`Pass`、`Take`、`SetHertz`、`Metric`，以及元数据 `ProviderId`、`ProviderVendor`、`ActiveProtocol`（取值 `ZCP1`）。可插拔形态同时符合 ZVHP1。每个核心的寄存器个数是 `8`，不另设字段。

### 4.10 频率与指标

每个已挂载核心记录两个整数：当前 Hz，以及已完成命令条数。挂上时 Hz 由该实现自己选定，必须落在 `1` 至 `1000000000`。条数是 `0`。失败的命令不增加条数。

`SetHertz(Ordinal, Hertz)` 把该核心的 Hz 改成新值并重新记下。`Hertz` 必须是 `1` 以上且 `1000000000` 以下的整数，含两端。超出时必须失败，且不得改写已记下的 Hz。

`Metric(Ordinal, Kind)` 返回已记下的数。`Kind` 为 `0` 时返回 Hz，为 `1` 时返回已完成条数。别的 `Kind` 必须失败。

命令按该核心当前 Hz 逐拍记账。第 n 拍到期于本次频率起点 + n × 1000 / Hz 毫秒。一次连续完成的本地指令，每一条仍占一拍，不得因为合并执行就少记账。算出的等待短于 1 毫秒时不挂起，一个宿主节拍里可以连续送出多条命令。改频率之后，下一拍从新的起点按新 Hz 计算。已经错过的拍不补做。

这不是显示器的刷新率，也不是内存或显卡的 Hz。上电时的时间起点由坐座主机记下，并交给处理器、内存和显卡。坐座主机不解释这些数，也不替核心选择下一条命令。

### 4.11 指令失败

一条指令失败时，序列必须停止，不得再取下一条。停止时必须留下下列字段，缺一不可：

| 字段 | 类型 | 值域 | 语义 |
|------|------|------|------|
| `Code` | 整数 | 已在 [FaultRegistry.md](./FaultRegistry.md) 登记的错误码 | 失败种类。尚未归类时必须是 `0` |
| `Source` | 整数 | 已在该登记表登记的来源 | 失败归到哪一类硬件 |
| `Text` | 字符串 | 长度 `1` 至 `240`。每个字符的码位必须是 `0x20` 至 `0x7E` | 给人看的说明。不得夹带该范围以外的字符 |
| `Core` | 整数 | `-1`，或 `0` 至 `255` | 失败发生的核心编号。不是某一颗核心的失败时必须是 `-1` |
| `Index` | 整数 | `0` 至 `4294967295` | 失败指令在当前序列中的编号。没有指令编号时必须是 `0` |
| `Op` | 字符串 | 长度 `0` 至 `32`。每个字符的码位必须是 `0x20` 至 `0x7E` | 失败指令的操作名。没有操作名时必须是空串 |
| `Site` | 字符串 | 长度 `1` 至 `80`。每个字符的码位必须是 `0x20` 至 `0x7E` | 源位置。未知时必须是一个字符 `-` |

错误码与来源的完整表不在本节。未登记的整数禁止当作已定义含义。`Core`、`Index`、`Op`、`Site` 不是查询字段，客程序读不到。

坐座主机必须把下列失败送上面板：固件所在核心的失败、监督核的失败、以及尚未被划成客核心的装入程序的失败。来源是 `Gpu` 时禁止送面板，上面七个字段仍然必须留下，并且必须写到坐座主机的诊断输出。诊断输出不得进入客程序能读的内存或查询字段。已经是客核心的任务失败不得因此停掉监督核，也不得因此替换面板上已有的一帧；七个字段仍然必须留下。

固件所在核心正忙时，坐座必须在下一条指令边界上停掉它正在跑的序列，再呈这一帧。这次停掉不得再记成一次新的失败。这一帧自己没有画成时，禁止再呈第二帧，七个字段必须写到坐座主机的诊断输出。来源是 `Gpu` 的失败在已经呈过一帧之后仍必须写到诊断输出。

坐座主机若把这次失败送上面板，必须另呈一帧，且只呈这一帧：

- 未绘制的像素是 `0`。文字墨色是 `16777215`。
- 第一行五个字形依次是 `E` `R` `R` `O` `R`（码位 `0x45` `0x52` `0x52` `0x4F` `0x52`）。
- 其后一行是 `CODE ` 与 `Code` 的十进制写法，中间一个空格。
- 再一行是 `SRC `、`Source` 的十进制写法、一个空格、以及该来源的规范短名。
- 再一行是 `CORE `。`Core` 为 `-1` 时这一行是 `CORE -`，否则是 `CORE ` 与 `Core` 的十进制写法。
- 再一行是 `AT `、`Index` 的十进制写法。`Op` 非空时再加一个空格和 `Op`。
- 再一行是 `SITE ` 与 `Site`。
- 再往后是 `Text`。按帧宽每 `8` 个像素一格从左向右排列，放不下的字符改到下一行。超出帧的部分必须裁掉，不得画到帧外。
- 可以在 `Text` 之后另起至多 `4` 行。每一行以 `STACK ` 开头，后面是宿主调用栈的一帧，字符码位必须是 `0x20` 至 `0x7E`。没有宿主调用栈时禁止画空的 `STACK` 行。这四行不是 `Text`，也不增加上面的必留字段。
- 字形使用 ZGP1 的封闭字形表。码位不在 `0x20` 至 `0x7E` 的字符禁止画上这一帧。

这一帧自己的指令再失败时，禁止再为它呈第二帧失败画面。没有面板，或来源是 `Gpu` 因而禁止送面板时，七个字段仍然必须留下，本节不要求呈帧。

### 4.12 原生指令字节

本节是另一条取指。它不替换 §4.3 的 8 个寄存器，也不替换 §4.6 的 ZAP 序列。ZAP 序列的寄存器编号仍然只有 `0` 至 `7`，编号 `8` 仍然必须失败。

原生指令的指令指针是线性位地址。实现必须从该地址起、按每 8 位一个八位组读取指令字节，执行后再按指令的八位组长度把指针加上 `长度 × 8`。禁止先把这些字节编成 ZAP 指令下标再执行。

原生整数寄存器有 16 个，编号 `0` 至 `15`，依次是 `rax`、`rcx`、`rdx`、`rbx`、`rsp`、`rbp`、`rsi`、`rdi`、`r8`、`r9`、`r10`、`r11`、`r12`、`r13`、`r14`、`r15`。每个都是 64 位。另有标志中的 CF、ZF、SF、OF、PF。

寻址计算的是八位组地址：`基址 + 变址 × 比例 + 位移`。比例只能是 `1`、`2`、`4`、`8`。缺基址或变址时该项是 `0`。相对指令指针的位移从本条指令的下一个八位组算起，立即数算在本条里面。`0x64` 把本条非相对内存地址加上该任务的 `fsbase`。相对指令指针不加，`lea` 也不加。`fsbase` 来自兼容帧，这条前缀不改它。八位组地址换成线性位地址时乘 `8`。读或写 2 个及以上八位组时，该位地址必须能被 `8` 整除。越出实现提供的位元线、或编码未在 [NativeOpcodeRegistry.md](./NativeOpcodeRegistry.md) 登记时，必须失败，且不得改尚未写完的目的寄存器。已经成功写入的其它寄存器保持新值。原生访存使用与 §4.6 相同的 bound。窗口外的读或写必须失败，且不得留下只写了一部分的 8 个八位组。

`rsp` 里的值是栈的八位组地址。`call` 先把 `rsp` 减 `8`，再把返回用的线性位地址按小端 8 个八位组写入 `rsp × 8` 这个位地址，然后把指令指针改到目标。`ret` 从 `rsp × 8` 读回这个位地址，再把 `rsp` 加 `8`。`rsp` 减 `8` 后小于 `0` 必须失败，且不得改 `rsp`。这里的 `call` 与 `ret` 不是 [CallingConvention.md](./CallingConvention.md) 的 ZAP 短形式。

把返回值放在 `rax`、前六个整数参数依次放在 `rdi`、`rsi`、`rdx`、`rcx`、`r8`、`r9`，是 [CallingConvention.md](./CallingConvention.md) §5 对编译器的约定，不是本条的取指规则。CPU 禁止因参数所在的寄存器拒绝一条已登记编码。

必须执行的编码以登记表为准。登记表单独写下的 32 位形式按 32 位运算，结果零扩展到 64 位。除此之外，没有 `REX.W` 的整数运算必须失败。`0x66` 后面只登记了 `0x83`、`0x89` 和 `0x8B`，这次按 16 位运算：寄存器只改低 16 位，内存只读写 2 个八位组。其它 `0x66` 与全部 `0x67` 必须失败。`0F 3F` 开头的字节是 ZerOS 操作，不是 x86 条件跳转。`query` 座位 `1` 字段 `1` 仍是 `8`，它数的是 ZAP 寄存器。

已登记的 `0F 3F` 直接完成监督权、保持位和系统调用，禁止先编成 ZAP 指令。其中系统调用的回复写入编码指定的原生寄存器。效果与 §4.6 的 `svc` 相同：停止原因是 `2`，核心保持执行中，下一次调度再写入回复并继续。回复不得写入 §4.3 的 8 个寄存器。`0x06` 至 `0x0C` 直接完成调度、卸下、划定、时间片、`yield`、座位 `1` 的查询和装入，效果与 §4.6 的同名指令相同。`yield` 留下下一条的线性位地址，停止原因是 `1`。再次调度从该地址继续。`0x0D` 至 `0x10` 直接完成 `capture`、`restore`、`hertz` 和 `attach`。`attach` 的入口编号写入编码指定的原生寄存器，不得写入 §4.3 的 8 个寄存器。`0x11` 至 `0x13` 直接完成 `gpu.present`、`gpu.character` 和 `gpu.accel`。`gpu.accel` 的结果写入编码指定的原生寄存器。

`0F 3E` 共六个八位组：`0F`、`3E`、操作字节、目的寄存器、左寄存器、右寄存器。三个寄存器字节都必须是 `0` 至 `15`。它不是特权指令。操作字节、除数为 `0`、移位次数不在 `0` 至 `63`，或结果不是有限二进制 64 时必须失败，且不得写入目的寄存器，也不得改指令指针。比较把目的寄存器写成 `0` 或 `1`，不改标志。访存的地址在左寄存器，是线性位地址，必须能被 `8` 整除；右寄存器字节不参与这次访存。

`0x83` 和一个 8 位立即数：reg 字段 `0` 是加，`1` 是或，`4` 是与，`5` 是减，`6` 是异或，`7` 是比较。立即数按符号扩展。有 `REX.W` 时按 64 位环绕。没有 `REX.W` 时按 32 位运算，寄存器目的零扩展，内存目的只读写 4 个八位组，SF 是第 31 位。比较不写目的。或、与、异或清掉 CF 和 OF。读不齐，或 reg 是 `2`、`3` 以及其它未列出的值时必须失败，且不得改目的和标志。`0x81` 的运算相同，立即数改为 4 个八位组。有 `REX.W` 时按符号扩成 64 位。没有 `REX.W` 时按 32 位运算并零扩展，这 4 个八位组本身就是 32 位立即数。mod 不是 `3` 时必须失败，且不得改寄存器。

`0xF3` 后接 `0xAB` 把 `rax` 的低 32 位按小端写入 `rdi`，然后 `rdi` 加 `4`、`rcx` 减 `1`，重复到 `rcx` 为 `0`。方向向前。`0xF3` 后接带 W 的 `REX` 再接 `0xAB` 时每次写 8 个八位组，`rdi` 加 `8`。单独的 `0xAB` 只写一次，不看 `rcx`。这些写入不改标志。`rcx` 一开始为 `0` 时重复形式不写。第一次写入失败时 `rdi` 与 `rcx` 保持进入这条指令时的值。已经写进若干次后再失败时，必须留下已完成的次数。其它 `0xF3`、以及 `REX` 出现在 `0xF3` 前面，必须失败。`0xFC` 与 `0xFD` 未登记，必须失败。

`0x70` 至 `0x7F` 带一个 8 位相对位移，`0x0F` 后接 `0x80` 至 `0x8F` 带一个 32 位相对位移。条件码低 4 位：`0` 看 OF，`2` 看 CF，`4` 看 ZF，`6` 看 CF 或 ZF，`7` 看 CF 与 ZF 都为 0，`8` 看 SF，`10` 看 PF，`12` 看 SF 与 OF 不同。奇数码是相反条件。不跳时目标可以落在可执行范围外。`0xFF` 在 mod 为 `3`、reg 为 `0` 或 `1` 时对寄存器加一或减一，不改 CF。没有 `REX.W` 时按 32 位运算并零扩展。reg 为 `2` 时调用该寄存器里的地址，先压入下一条的地址。reg 为 `4` 时跳到该寄存器里的地址，不改标志。两者都不要求 `REX.W`。兼容任务把这个地址当成用户八位组地址。目标落在窗口外，或调用时栈放不下返回地址，必须失败且不得改指令指针。其它 reg 或 mod 不是 `3` 时必须失败。`0xC1` 在 mod 为 `3` 时按 8 位立即数移位：reg `4` 左移，`5` 逻辑右移，`7` 算术右移。`0xD1` 次数固定为 `1`。64 位次数对 `64` 取余，32 位对 `32` 取余。余数是 `0` 时不改寄存器和标志。没有 `REX.W` 时按 32 位并零扩展。其它 reg 或 mod 不是 `3` 必须失败，且不得改寄存器。`0x85` 在 mod 为 `3` 时按两个寄存器的按位与改标志，不写寄存器。没有 `REX.W` 时只看低 32 位。内存形式必须失败。

`0xC7` 的 reg 字段必须是 `0`。它把随后 4 个八位组的立即数写入 `r/m`，不改标志。有 `REX.W` 时按符号扩成 64 位。没有 `REX.W` 时只写 32 位，寄存器目的零扩展，内存目的只写 4 个八位组。其它 reg 字段必须失败，且不得改寄存器。

`0x05`、`0x2D`、`0x3D` 对 `rax` 做加、减、比较，立即数是 4 个八位组。`0x0D`、`0x25`、`0x35` 是或、与、异或。有 `REX.W` 时立即数按符号扩成 64 位。没有 `REX.W` 时只运算低 32 位，写入时零扩展。比较不写 `rax`。`0x15` 与 `0x1D` 必须失败。

8 位传送、测试和运算只改目的那一个字节，不把寄存器的其余位清零。没有 `REX` 时，ModRM 字段 `4` 至 `7` 是 `AH`、`CH`、`DH`、`BH`。有 `REX` 时这四个是 `SPL`、`BPL`、`SIL`、`DIL` 的低 8 位。`0x3C` 比较 `AL`。`0x38` 与 `0x3A` 是 8 位比较，不写目的。读不齐时不得改标志。`0xF6` 的 reg 字段为 `0` 时，用随后的 8 位立即数与目的字节做测试，不写目的。其它 reg 必须失败。`0x80` 的 reg 字段 `0`、`1`、`4`、`5`、`6`、`7` 分别是加、或、与、减、异或、比较；`2` 与 `3` 必须失败。`0xC6` 的 reg 字段必须是 `0`。`0xFE` 的 reg 字段 `0` 加一、`1` 减一，不改 CF。`0xEB` 按 8 位位移无条件跳转。这些 8 位运算的 SF 是第 7 位。`0x0F` `0xAF` 在 mod 为 `3` 时做有符号乘法，结果写入 `reg`。有 `REX.W` 时是 64 位，没有时按 32 位并零扩展。乘积放不进这一宽度时 CF 与 OF 置位。内存形式必须失败，且不得改寄存器。`0x0F` `0x90` 至 `0x9F` 在 mod 为 `3`、reg 字段为 `0` 时，按与条件跳转相同的条件把目的字节写成 `0` 或 `1`，不改标志，也不改该寄存器的其余位。`0x0F` `0xB6` 把一个字节零扩展后写入寄存器，不改标志。`0x0F` `0xB7` 把低 16 位零扩展后写入寄存器，不改标志。读不齐时不得改寄存器。没有 `REX` 时源字段 `4` 至 `7` 是 `AH`、`CH`、`DH`、`BH`。读不齐时不得改寄存器。

`0xF7` 在 mod 为 `3` 时，reg 字段 `2` 是按位取反，不改标志；`3` 是取负，标志按从 0 减去原值。有 `REX.W` 时按 64 位，没有时按 32 位并零扩展。其它 reg 字段和内存形式必须失败，且不得改寄存器。

没有 `REX.W` 的 `0x31`、`0x33`，在 mod 为 `3` 时是 32 位寄存器异或，结果零扩展到 64 位，SF 是第 31 位。这两种的内存形式在没有 `REX.W` 时必须失败。没有 `REX.W` 的 `0x39`、`0x3B` 在 mod 为 `3` 时按低 32 位比较，不写寄存器，SF 是第 31 位。这两种的内存形式在没有 `REX.W` 时必须失败。`0x21` 与 `0x23` 是与，`0x09` 与 `0x0B` 是或，规则与异或相同：有 `REX.W` 时是 64 位，没有时在 mod 为 `3` 上按 32 位零扩展，没有 `REX.W` 的内存形式必须失败。没有 `REX.W` 的 `0x89`、`0x8B` 是 32 位传送，结果零扩展，不改标志。内存形式只读写 4 个八位组；读不齐时必须失败，且不得改寄存器。

`0xB8` 至 `0xBF` 没有 `REX.W` 时，立即数是 4 个八位组，零扩展后写入寄存器，不改标志。前面的 `REX` 可以不带 W，用来选择 `r8` 至 `r15`。有 `REX.W` 时仍是 8 个八位组。

`REX.W` 后接 `0x63`、mod 为 `3` 的 ModRM：把 `r/m` 的低 32 位按符号扩成 64 位写入 `reg`，不改标志。没有 `REX.W` 或 mod 不是 `3` 时必须失败，且不得改寄存器。

`0F 3F` 的 `0x14` 至 `0x1D` 直接完成 `xchg`、`carry`、`port.state`、`port.char`、`port.byte`、`mmap`、`munmap`、`dwell`、`inbox` 和 `fill`。除 `0x1B` 的 `dwell` 外，客核心执行必须失败，错误码 `22`。`dwell` 客核心可以执行。结果写入编码指定的原生寄存器，不得写入 ZAP 的 8 个寄存器。

加法、减法、比较和异或必须按结果更新 ZF、SF、PF。加法、减法和比较还必须更新 CF、OF。登记为 32 位的运算，ZF 与 SF 按这 32 位计算，SF 是第 31 位。PF 在结果最低 8 位里有偶数个 1 时为 1。

### 4.13 兼容任务

`admit rC, rA, rN` 让监督核把一颗已停止的核心放进兼容任务。`rA` 是描述符的线性位地址，`rN` 必须是 `32`。描述符是四个小端 64 位整数，依次是入口的用户八位组地址、初始 `rsp`、空间长度、标志。标志必须是 `0`。空间长度必须是 `16777216`。入口和 `rsp` 必须落在 `4096` 至 `16777215`。`rsp` 必须能被 `16` 整除。全机同时只能有一份兼容任务。目标正在执行、已经有一份未卸下的兼容任务，或描述符不符合时必须失败，且不得改目标。成功后目标仍停止。客核心执行 `admit` 必须失败，目标不变。失败不使用错误码 `22`，规则与 `install` 相同。

兼容任务的用户八位组地址 `v` 换成线性位地址时，落在实现划出的这 `16777216` 个八位组里。前 `4096` 个八位组只由实现在陷入时写帧。任务自己对小于 `4096` 或大于等于 `16777216` 的地址访存必须失败，且不得写到一半。`lea` 不读存储，算出的地址可以是 `0`、小于 `4096`，或落在这 `16777216` 个八位组之外，仍然必须写入目的寄存器。没有 `REX.W` 时只写这个地址的低 32 位并零扩展，不改标志。随后对这个地址的访存才必须失败。寄存器间接寻址先做这道换算。相对指令指针的位移已经在这段线性位地址上，不再加第二遍。`call` 压入的是下一条的用户八位组地址，`ret` 把它换回线性位地址。官方标定把这段放在映射区之后：起点位地址 `2432696320`，长度 `134217728` 位。映射区的上界不因此移动。本协议不把这个起点写成所有实现必须相同的数，只要求换算自洽，并且其它核心的 `bound` 到不了任务自己的那一段。

`0F 05` 只在兼容任务里陷入。`rcx` 记下下一条的用户八位组地址，`r11` 记下标志。停止原因是 `2`。帧是 19 个小端 64 位，顺序为 `rax`、`rcx`、`rdx`、`rbx`、`rsp`、`rbp`、`rsi`、`rdi`、`r8`、`r9`、`r10`、`r11`、`r12`、`r13`、`r14`、`r15`、下一条的用户八位组地址、`rflags`、`fsbase`。帧放在这 `16777216` 个八位组的页 0。服务号 `27` 交给监督核。原生程序执行 `0F 05` 必须失败，不得进入服务号 `27`。续跑时从帧里的用户地址继续，返回值在帧的 `rax`。`release` 成功卸下这份任务时，必须丢掉帧和这 `16777216` 个八位组里的用户内容。

## 5. 不符合示例

1. 协议标识使用 `zcp1` 或 `ZCP-1`；
2. 只能提供 1 个核心，却声明 `CoreCount` 为 `4`；
3. `CoreCount` 为 `0`、负数或 `257`；
4. 坐座主机挂载编号 `CoreCount`；
5. 停止中的核心仍然执行 `Load`、`Store`、`Place` 或 `Add`；
6. 保持位已有值时 `Pass` 覆盖旧值；
7. 由坐座主机把一个核心的整数转交给另一个核心，或由坐座主机改写寄存器；
8. CPU 实现直接改写存储体，不经坐座主机的这一次访存；
9. `Add` 访问存储，或把加法结果按固定位宽截断；
10. 使用寄存器编号 `8` 仍改写了某个寄存器；
11. 把进程或分页放进 CPU 并声称是 ZCP1 的要求。
12. 指令失败后继续取下一条，或失败记录缺少 `Code`、`Source`、`Text`、`Core`、`Index`、`Op`、`Site` 之一。
13. 面板上的失败帧没有 `ERROR`、十进制错误码、十进制来源、`CORE`、`AT`、`SITE`，或画了 `0x20` 至 `0x7E` 以外的字符。固件、监督核或尚未成为客核心的装入程序失败后没有留下七个字段。来源是 `Gpu` 时仍把失败帧送上了面板，或没有把七个字段写到坐座主机的诊断输出。固件所在核心正忙时没有在下一条指令边界上呈失败帧，或把这次接替记成了新的失败。客核心的任务失败停掉了监督核。
14. 对正在执行 `install` 的那一颗核心装入，仍然替换了它的序列或清了它的寄存器。对另一颗正在执行的核心装入、卸下、抄槽、放回、接库或划定范围时，没有先停在指令边界上就改了它。
15. `fill` 的 `rN` 大于 `4096` 仍写入，或设备状态不是成功时仍然改了存储。
16. `carry` 的 `rN` 大于 `268435456` 仍写入，或失败时仍然改了存储。
17. 实现把一部分线性八位组只留给写入它的核心，但 `capture` 没有抄走这些八位组，`restore` 没有按原地址替换，或 `install`、`release` 成功后仍让下一份程序读到上一份留下的私有八位组。
18. 用 `install` 把动态库换成整段序列，`attach` 失败后仍改了目标，或把版本 1 映像后面多出来的字节当成链接目录接受。
19. 版本 2、种类 1 的映像带了数据重定位，`install` 仍按 0 号核心窗口的立即数换上，或重定位失败后仍清了寄存器。
20. 监督核用 `install` 或 `bound` 划定另一颗核心之后，那颗核心仍能执行 `gpu.compose`、`pass` 或 `gate`，或查询另一颗核心的运行状态；或者尚未出现监督核时就把某颗核心当成客核心拒绝了显卡指令。
21. `dwell` 的毫秒超出 `0` 至 `1000` 仍继续取指，等待时把核心改成停止，或用 `yield` 代替这次等待。客核心执行 `dwell` 被当成错误码 `22` 拒绝。
22. `mmap` 按字节访问扩展口，或同一页第二次读取又访问了扩展口。`munmap` 之后这段地址仍能读到映射内容。客核心执行 `mmap` 仍建立了映射。
23. 把 [NativeOpcodeRegistry.md](./NativeOpcodeRegistry.md) 的字节先编成 ZAP 下标再执行，或在没有 `REX.W` 时仍按 64 位执行了其中的整数运算。`call` 没有把返回用的线性位地址写入栈就跳走。
24. `0F 3F` 的系统调用把回复写入了 ZAP 寄存器，未登记的转义编号仍改了寄存器或指令指针，或已经有监督核时再次取得监督权仍成功。
25. 把 `0F 3F` 的装入或调度先编成 ZAP 指令再执行，或 `yield` 之后的调度从这段原生指令的第一条重新开始。
26. 把 `0F 3F` 的捕获、恢复、频率或接入先编成 ZAP 指令再执行，接入的入口编号写入了 ZAP 寄存器，或客核心执行 `0x0F` 仍改了频率。
27. 把 `0F 3F` 的显卡命令先编成 ZAP 指令再执行，绘制结果写入了 ZAP 寄存器，或客核心执行后仍把显卡命令送出。
28. 原生访存越过 bound 仍写入，或 8 个八位组只写进了一部分。`rsp` 减 8 后小于 0 时 `call` 或压栈仍改了 `rsp`。
29. `0F 3E` 的未登记操作、除数为 `0` 或移位次数越界时仍写入了目的寄存器。`0x81` 的 mod 不是 `3`，或 `0x81`、`0x83` 的 reg 不是已登记的 `0`、`1`、`4`、`5`、`6`、`7` 时仍改了目的。`0x83` 读不齐内存时仍改了标志。客核心执行 `0x14` 至 `0x1D` 中除 `dwell` 以外的转义仍改了扩展口或存储。把 `5A 4E 42 31` 按 ZAP 指令下标执行，或装入之后对这串代码的取指因 `bound` 失败。
30. 已经有一份兼容任务时 `admit` 仍进入第二份，或失败时改了目标。原生程序执行 `0F 05` 进入了服务号 `27`。兼容任务访问小于 `4096` 的用户地址仍成功。`release` 之后下一份任务仍读到上一份留在这 `16777216` 个八位组里的内容。
31. 没有 `REX.W` 的已登记 32 位运算仍留下了高 32 位，或把 SF 取成第 63 位。`REX.W` `0x63` 没有把源的低 32 位按符号扩到 64 位。`0xB8` 没有 `REX.W` 时仍读了 8 个八位组，或改了标志。
32. 兼容任务的 `lea` 因为地址是 `0` 或小于 `4096` 而失败，没有把这个地址写入寄存器。
33. `0xF3` `0xAB` 在 `rcx` 为 `0` 时仍写入，或第一次写入失败后改了 `rdi` 或 `rcx`。其它 `0xF3` 仍执行。单独的 `0xAB` 按 `rcx` 重复写入。
34. 8 位传送把目的寄存器的其余位清成 0，或没有 `REX` 时把字段 `4` 写成 `SPL` 而不是 `AH`。`0xEB` 没有按 8 位位移跳转。`0xF6` `/0` 仍改了目的字节。`0x0F` `0xB6` 读不齐时仍改了目的寄存器。
35. 带立即数的相对寻址从立即数本身起算，而不是从立即数之后的那个八位组起算。`0x64` 没有把 `fsbase` 加到非相对内存地址上，或把它加进了相对指令指针或 `lea`。
36. `0xC1` 或 `0xD1` 的次数在取余后为 `0` 时仍改了标志，或 reg 不是 `4`、`5`、`7` 时仍改了寄存器。`0xFF` `/2` 或 `/4` 的目标落在窗口外时仍改了指令指针，或 `/2` 在栈放不下时仍压入了返回地址。`0x66` 后面不是 `0x83`、`0x89`、`0x8B` 时仍改了寄存器，或 16 位比较仍写了目的，或 16 位传送把高位清成 0。

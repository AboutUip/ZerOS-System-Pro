# ZXD1 · 扩展口数据交换协议

> 路径：`Documents/Protocol/PhysicalHardware/Expansion/ZXD1.md`  
> 协议标识：`ZXD1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可判断一次扩展口数据交换是否符合 ZXD1。口的空满和引导见 [ZXP1.md](./ZXP1.md)。参考实现不是规范。

## 0. 文档定位与符合性

声称兼容 ZXD1 的设备和宿主必须：

1. 使用协议标识 `ZXD1`，大小写逐字一致；
2. 提供方法名 `Exchange`，拼写与大小写逐字一致；
3. 只在 ZXP1 状态 `2`（已引导）的口上交换；
4. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

一次 `Exchange` 搬一块八位组。宿主不解释这些八位组。设备自己的领域协议决定它们的含义。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZXD1`；
- 方向 `0` 与 `1`；
- 一块载荷的长度上界；
- `Exchange(Index, Direction, Payload)` 的失败规则。

### 2.2 本协议明确不规定

- 载荷里的命令、地址或文本；
- 流控、重传、端点号、描述符表；
- 同时在多个口上并行交换。宿主可以一次只进行一口，也可以分口并行。同一个口禁止重叠。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 载荷 | 长度在 `0` 至 `4096` 的八位组序列，含两端。每个八位组是 `0` 至 `255` |
| 方向 `0` | 宿主把载荷交给设备 |
| 方向 `1` | 设备把载荷交给宿主 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZXD1` |
| 宿主到设备 | `0` |
| 设备到宿主 | `1` |
| 载荷长度上界 | `4096` |

### 4.1 Exchange

`Exchange(Index, Direction, Payload)` 返回另一块载荷。

- `Index` 必须是 ZXP1 的 `0` 至 `3`。
- 该口不是状态 `2` 时必须失败，且不得把 `Payload` 交给设备。
- `Direction` 不是 `0` 或 `1` 时必须失败。
- `Payload` 的长度大于 `4096` 时必须失败。
- 同一个口上一次交换还没结束时，后一次必须失败，且不得改写前一次的结果。
- 设备返回的序列长度也必须在 `0` 至 `4096`。超出时宿主必须失败，且不得把这个非法序列交给调用方。
- 失败时调用方看不到半块结果。

方向 `0`：`Payload` 是宿主交给设备的数据，返回值是设备的应答，长度可以为 `0`。

方向 `1`：`Payload` 是宿主的请求，长度可以为 `0`。返回值是设备交出的数据。

宿主禁止按字节含义修改任一方向的序列。

### 4.2 必选成员

设备插头在 ZXP1 的必选成员之外，还必须提供 `Exchange`。`ActiveProtocol` 逐字为 `ZXD1`。

## 5. 不符合示例

1. 空口上 `Exchange` 仍返回了数据；
2. 状态停在 `1` 时已经开始交换；
3. 长度为 `4097` 的载荷被接受；
4. 宿主把载荷解释成自己的指令并改写了其中的八位组；
5. 同一口的两次交换交叉完成，后一次覆盖了前一次的返回值。

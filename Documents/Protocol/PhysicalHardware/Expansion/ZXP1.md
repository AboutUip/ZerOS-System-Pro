# ZXP1 · 扩展口协议

> 路径：`Documents/Protocol/PhysicalHardware/Expansion/ZXP1.md`  
> 协议标识：`ZXP1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可判断一份扩展口宿主是否符合 ZXP1。参考实现不是规范。冲突时以本文为准。数据交换见 [ZXD1.md](./ZXD1.md)。

## 0. 文档定位与符合性

声称兼容 ZXP1 的宿主必须：

1. 使用协议标识 `ZXP1`，大小写逐字一致；
2. 提供本文全部必选字段与方法名，拼写与大小写逐字一致；
3. 固定提供 4 个口，编号 `0` 至 `3`；
4. 空口不算失败；
5. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

符合本协议的宿主有 4 个扩展口。每个口要么空着，要么坐着一份设备插头。引导时按编号从小到大查看。空口跳过。非空口先 `Load`，再 `Boot`。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZXP1`；
- 口的个数与编号；
- 封闭状态 `0` 空、`1` 已加载、`2` 已引导；
- `Bind`、`Get`、`Load`、`Boot`、`Identity`；
- 设备插头的 `ProviderId`、`ProviderVendor`、`ActiveProtocol`、`DeviceProtocol`。

### 2.2 本协议明确不规定

- 某一种外设的领域命令；
- 热插拔时机、供电、线缆；
- 数据字节的含义，那是 [ZXD1.md](./ZXD1.md) 与设备自己的协议；
- 把扩展口说成 ZVHP1 的 `BusSlot`。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 扩展口 | 编号 `0` 至 `3` 的一个位置 |
| 空口 | 没有完成 `Bind` 的口，状态 `0` |
| 设备插头 | 坐在某个口上的一份实现 |
| `DeviceProtocol` | 该设备自己的协议标识。宿主保存它，不按它分支 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZXP1` |
| 口的个数 | `4` |
| 编号下界 | `0` |
| 编号上界 | `3` |
| 空 | `0` |
| 已加载 | `1` |
| 已引导 | `2` |
| `ProviderId` 长度 | `1` 至 `64` |
| `ProviderVendor` 长度 | `1` 至 `32` |
| `DeviceProtocol` 长度 | `1` 至 `64` |

上述字符串的每个字符都是可打印 ASCII，码位 `0x21` 至 `0x7E`。`ActiveProtocol` 必须逐字为 `ZXD1`。

### 4.1 口

宿主必须提供 4 个口。引导开始时，未被 `Bind` 的口是状态 `0`。禁止把空口当成故障。

编号不是 `0` 至 `3` 的整数时，`Bind`、`Get`、`Load`、`Boot`、`Identity` 必须失败，且不得改写任何一个口。

### 4.2 绑定

`Bind(Index, Provider)` 把一份插头坐到该口。

- 该口已经有插头时必须失败，不得替换。
- `ProviderId`、`ProviderVendor`、`DeviceProtocol` 长度或字符不合法时必须失败。
- `ActiveProtocol` 不是 `ZXD1` 时必须失败。
- 失败时该口保持原状。
- 成功时口仍是状态 `0`，直到 `Load`。

`Get(Index)` 返回该口的插头。空口返回空，不是失败。

`Identity(Index, Offset)` 返回该口 `DeviceProtocol` 的一个字符码。`Offset` 必须是 `0` 至 `63` 的整数。空口、或偏移不在这个范围时必须失败。偏移不小于字符串长度时返回 `0`，不是失败。宿主不按这个字符决定加载哪一种设备。

### 4.3 加载与引导

宿主在自己的引导序列里，按 `0`、`1`、`2`、`3` 的顺序处理。

对状态 `0` 且没有插头的口，跳过。

对已经 `Bind` 且仍是状态 `0` 的口：

1. 调用该插头的 `Load`。成功后状态变为 `1`。`Load` 失败则状态保持 `0`，且不得调用它的 `Boot`。
2. 状态为 `1` 时调用 `Boot`。成功后状态变为 `2`。`Boot` 失败则状态保持 `1`。

某一个口失败时，编号更大的口不再 `Load` 或 `Boot`。已经成功的口保持其状态。

`Load` 或 `Boot` 对空口、或对状态已经走过该步骤的口，必须失败，且不得重复调用设备方法。

### 4.4 必选成员

宿主侧：`Bind`、`Get`、`Load`、`Boot`、`Identity`。设备插头侧：`ProviderId`、`ProviderVendor`、`ActiveProtocol`、`DeviceProtocol`、`Load`、`Boot`。交换方法属于 ZXD1，不在本文重复定义。

## 5. 不符合示例

1. 只提供 3 个口仍声称兼容 ZXP1；
2. 空口导致整次引导失败；
3. `ActiveProtocol` 为 `ZXP1` 仍被 `Bind` 接受；
4. `Load` 失败之后仍然调用了 `Boot`；
5. 把这 4 个口登记成 ZVHP1 的 `Bus`。

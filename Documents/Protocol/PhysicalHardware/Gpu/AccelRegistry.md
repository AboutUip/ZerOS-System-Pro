# AccelRegistry · `gpu.accel` 操作码

> 路径：`Documents/Protocol/PhysicalHardware/Gpu/AccelRegistry.md`  
> 所属协议：ZGP1 / ZCP1  
> 权威优先级：本登记表 > 协议正文里的摘要

`gpu.accel rD, rOp, rA, rB, rC, rE` 是一条通用显卡指令。`rOp` 选择下表的操作。`rA` 到 `rE` 是四个二进制 64 位型，按 IEEE 754 解读。整数参数先变成恰好等于该整数的有限浮点，再取其位型。没有结果的操作仍把 `0` 写入 `rD`。

位型放不进 64 位、操作码不在下表、或该操作的参数使绘制无法完成时，这条指令必须失败，并且不得改写帧存储。

| 码 | 名称 | `rA` `rB` `rC` `rE` | 写入 `rD` |
|----|------|----------------------|-----------|
| 1 | Viewport | x, y, 宽, 高 | 0 |
| 2 | Scissor | x, y, 宽, 高 | 0 |
| 3 | ClearColor | 红, 绿, 蓝, 透明度，各在 0 到 1 | 0 |
| 4 | ClearDepth | 深度，其余忽略 | 0 |
| 5 | Clear | 掩码，其余忽略。1 是颜色，2 是深度，可相加 | 0 |
| 6 | Color | 红, 绿, 蓝, 透明度 | 0 |
| 7 | Vertex | x, y, z，第四个忽略 | 0 |
| 8 | TexCoord | u, v，其余忽略 | 0 |
| 9 | Normal | x, y, z，第四个忽略 | 0 |
| 10 | Begin | 图元种类，其余忽略 | 0 |
| 11 | End | 忽略 | 0 |
| 12 | MatrixMode | 0 模型视图，1 投影 | 0 |
| 13 | LoadIdentity | 忽略 | 0 |
| 14 | PushMatrix | 忽略 | 0 |
| 15 | PopMatrix | 忽略 | 0 |
| 16 | Translate | x, y, z | 0 |
| 17 | Rotate | 角度（度）, x, y, z | 0 |
| 18 | Scale | x, y, z | 0 |
| 19 | Ortho | 左, 右, 下, 上 | 0 |
| 20 | OrthoDepth | 近, 远 | 0 |
| 21 | Frustum | 左, 右, 下, 上 | 0 |
| 22 | FrustumDepth | 近, 远 | 0 |
| 23 | Enable | 能力号 | 0 |
| 24 | Disable | 能力号 | 0 |
| 25 | BlendFunc | 源因子, 目标因子 | 0 |
| 26 | DepthFunc | 比较号 | 0 |
| 27 | CullFace | 面号 | 0 |
| 28 | FrontFace | 绕序号 | 0 |
| 29 | GenTexture | 忽略 | 新的纹理编号，从 1 起 |
| 30 | BindTexture | 纹理编号 | 0 |
| 31 | TexImage | 宽, 高, 显存字节地址 | 0 |
| 32 | DrawArrays | 图元种类, 起点, 个数 | 0 |
| 33 | Fill | x, y, 宽, 高 | 0 |
| 34 | ScreenGlyph | 码点, x, y, 字号 | 0 |
| 35 | Corner | 半径，其余忽略 | 0 |
| 36 | Round | x, y, 宽, 高 | 0 |
| 37 | Ellipse | x, y, 宽, 高 | 0 |
| 38 | Frame | 选择号，其余忽略 | 选择号 0 是宽，1 是高 |

图元种类：0 点，1 线段，2 折线，3 三角形，4 三角带，5 三角扇，6 四边形。四边形在执行时收成两个三角形。

能力号：1 深度测试，2 混合，3 背面剔除，4 剪裁，5 二维纹理，6 光照。未知能力号必须失败。

光照开启后，片段红、绿、蓝乘以法线与 `(0, 0, 1)` 夹角的余弦，小于 0 按 0。法线长度为 0 时不改变颜色。

混合因子：0 零，1 一，2 源透明度，3 一减源透明度，4 目标透明度，5 一减目标透明度，6 源颜色，7 一减源颜色，8 目标颜色，9 一减目标颜色。不在这张表里必须失败。默认源因子是 2，目标因子是 3。

深度比较：0 永不，1 小于，2 等于，3 小于等于，4 大于，5 不等于，6 大于等于，7 总是。不在这张表里必须失败。默认是 1。

剔除面：0 正面，1 背面，2 正反两面。不在这张表里必须失败。默认是 1。两面都剔除时这次绘制不写入颜色目标。

绕序：0 逆时针为正面，1 顺时针为正面。不在这张表里必须失败。默认是 0。

矩阵栈每一种至少 32 层。再压入必须失败。只剩一层时再弹出必须失败。

`DrawArrays` 的起点与个数按 `Begin` 之后积累、尚未被 `End` 清空的顶点计。起点或个数小于 0，或超出已有顶点，必须失败。`End` 画出全部积累的顶点并清空。`DrawArrays` 不清空。

`Ortho` 使用此前 `OrthoDepth` 记下的近与远。`Frustum` 使用此前 `FrustumDepth` 记下的近与远。六个数要分成两条命令时，必须先写近远，再写左右下上。左右重合、上下重合或近远重合必须失败。`Frustum` 的近或远小于等于 0 必须失败。

`Rotate` 绕 `(x, y, z)` 指定的轴，角度单位是度。轴长度为 0 时矩阵不变。

`GenTexture` 的编号从 1 起，每次成功加 1。`BindTexture` 的编号没有生成过时，随后的绘制不采样该纹理。`TexImage` 在没有绑定从 1 起的编号，或宽、高小于 1，或字节超出显存时必须失败。

剪裁空间的 y 向上，z 从近到远对应 -1 到 1。帧存储的第 0 行必须是屏幕最上边。实现必须完成这个方向转换，可以发生在视口变换里，也可以发生在把颜色目标写入帧存储时，但同一像素只能翻转一次。

纹理的显存字节是紧挨着的 RGBA，每通道 8 位，行从图像上边开始。宽或高小于 1，或字节超出显存时，TexImage 必须失败。

`Fill`、`Round`、`Ellipse` 与 `ScreenGlyph` 使用颜色目标的像素坐标。原点在左上，y 向下，单位是像素。四者都不读取、不修改矩阵栈和顶点批次，不读不写深度缓冲。当前 `Color` 的通道超出 0 到 1 时，这四条操作必须先夹到 0 或 1，并且不得改写 `Color` 自己保存的值。叠色必须按源透明度、一减源透明度，并且不看混合能力有没有打开。剪裁能力打开时必须剪裁。完全落在颜色目标或剪裁矩形外面时必须成功，且不算一次图元绘制。盖住至少一个像素时算一次图元绘制。

`Fill` 的宽或高小于 0 必须失败，且不得改写颜色目标。宽或高等于 0 必须成功，且不算一次图元绘制。

`ScreenGlyph` 的字号小于 1，或码点不在 `0x20` 至 `0x7E`，必须失败，且不得改写颜色目标。字号等于 1 时格子宽是 1；字号大于等于 2 时格子宽是字号除以 2 向零截断。格子高是字号。位图是 [AccelGlyph.md](./AccelGlyph.md) 的 5 列 7 行，必须用最近邻铺满格子，禁止画出格子以外的墨。

`Corner` 记下圆角半径，单位是像素。它不是绘制，不得改写颜色目标，也不得改变矩阵、剪裁或 `Color`。半径小于 0 必须失败，且不得改写已记下的半径。半径大于等于 0 时必须记下该值，包括 0。尚未调用过 `Corner` 时，半径是 0。

`Round` 用当前 `Color` 和当前圆角半径画圆角矩形。宽或高小于 0 必须失败，且不得改写颜色目标。宽或高等于 0 必须成功，且不算一次图元绘制。半径先视为不小于 0，再收到不超过较短边的一半。覆盖按像素中心判定：中心落在圆角矩形内或边界上的像素必须着墨，落在包围盒内但形状外的像素必须保持原样。半径为 0 时，着墨的像素中心与同位置、同宽高的 `Fill` 相同。抗锯齿不是本操作的要求。包围盒盖住至少一个像素时算一次图元绘制，即使形状丢掉了包围盒里的一些像素。

`Ellipse` 用当前 `Color` 画包围盒的内切椭圆，不读取圆角半径。宽或高小于 0 必须失败，且不得改写颜色目标。宽或高等于 0 必须成功，且不算一次图元绘制。覆盖按像素中心判定：中心落在椭圆内或边界上的像素必须着墨。宽等于高时形状是圆。宽大于高、且圆角半径等于高的一半时，`Round` 是跑道形，不是这个椭圆。抗锯齿不是本操作的要求。包围盒盖住至少一个像素时算一次图元绘制。

`Frame` 不是绘制，不得改写颜色目标。选择号恰好是 0 时，结果是颜色目标当前的宽，单位是像素。恰好是 1 时，结果是高。其它选择号必须失败。这个宽高就是 `Fill` 所用坐标空间的宽高。不得用 `Metric` 的种类号查询帧边。

着色器语言、多重采样和几何着色器不在本登记表内。

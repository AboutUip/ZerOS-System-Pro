# 字体面

> 路径：`Documents/Protocol/PhysicalHardware/Gpu/Font.md`  
> 所属协议：ZGP1  
> 权威优先级：本文件 > [AccelRegistry.md](./AccelRegistry.md) 里字体操作的摘要

固件的 `Character` 与 `ScreenGlyph` 仍只使用封闭点阵，见 [Glyph.md](./Glyph.md) 与 [AccelGlyph.md](./AccelGlyph.md)。本文件不往那两张表增加码点。

字体面读取调用方已经放在内存里的 TrueType 字节，把 Unicode 标量光栅后画进颜色目标。符合本文件的实现不得调用宿主环境自带的字体引擎来代替这里规定的解析和着墨。

## 1. 操作

三条操作的码见 [AccelRegistry.md](./AccelRegistry.md)。它们都不是封闭点阵。

`FontFace` 的四个参数是位元地址、八位组长度、像素字号，第四个忽略。地址必须能被 `8` 整除。长度是 `1 .. 33554432`。字号是 `1 .. 256` 的整数。字节必须是下面第 2 节接受的 TrueType。成功时结果是字体面编号，从 `1` 起，只增不减。失败时不得分配编号，也不得改写颜色目标。

`FontSelect` 的参数是字体面编号、横坐标、纵坐标。编号必须是已成功的 `FontFace`。坐标是整数像素，原点在颜色目标左上，y 向下。它只记下画笔，不得改写颜色目标。

`FontDraw` 的参数是标量序列的位元地址、标量个数，其余忽略。地址必须能被 `8` 整除。个数是 `0 .. 4096`。个数为 `0` 时成功，且不算一次图元绘制。每个标量是按小端放在连续 4 个八位组里的整数，相邻标量的地址相差 `32` 个位元。标量必须符合 [../../Kernel/Utf8.md](../../Kernel/Utf8.md) 的标量值域。序列里任何一个标量不合法时，整条 `FontDraw` 失败，颜色目标保持调用前的内容。

画笔从 `FontSelect` 记下的位置开始，沿 x 正向前进。每个标量先找字形，再按第 3 节着墨，然后把画笔加上该字形的进宽。进宽是 `hmtx` 的前进宽度乘字号，除以 `head.unitsPerEm`，向 `0` 截断，结果小于 `0` 时按 `0`。还没有 `FontSelect` 时，`FontDraw` 失败且不改颜色目标。

## 2. TrueType 子集

字节是大端。偏移表 `sfnt` 版本必须是 `0x00010000`。必须同时有 `head`、`maxp`、`cmap`、`loca`、`glyf`、`hhea`、`hmtx`。表被截断、偏移重叠到文件外、或 `unitsPerEm` 不是 `16 .. 16384` 时，`FontFace` 失败。

`cmap` 只接受 platform `3` encoding `1` 的 format `4`，以及 platform `3` encoding `10` 的 format `12`。两者都有时，大于 `65535` 的标量只用 format `12`，其余标量先查 format `12`，没有再查 format `4`。都没有命中时字形号是 `0`。字形号 `0` 是 `.notdef`。`loca` 由 `head.indexToLocFormat` 决定是 `16` 位还是 `32` 位偏移。

`glyf` 的简单字形和复合字形都必须能读。复合字形嵌套超过 `16` 层，或简单字形的轮廓点超过 `4096` 时，该字形按 `.notdef` 绘制，`FontDraw` 仍然成功。`.notdef` 自己也无法光栅时，`FontDraw` 失败且不改颜色目标。

不读取 `cvt`、`fpgm`、`prep` 和字形指令。提示不是本文件的要求。

## 3. 着墨

不做抗锯齿。覆盖只有着墨与不着墨。

进宽的截断见第 1 节，不用于包围盒。字形包围盒换成像素时用实数：字体单位乘字号，再除以 `unitsPerEm`。左、下向下取整，右、上向上取整，得到掩码宽高。掩码的第 `0` 行是包围盒最上边。像素 `(列, 行)` 的中心映射回字体单位。中心按非零环绕落在填充内或边界上时，该像素着墨。

简单字形里相邻两个离曲线点之间，必须先补上它们的中点，作为在曲线上的点。二次曲线再细分，直到控制点到弦的距离不超过四分之一个像素。然后用上面的像素中心规则。复合字形先套用它自己的仿射变换，再并入同一环绕。

着墨像素使用当前 `Color`，合成方式与 `Fill` 相同。完全落在颜色目标或剪裁外时成功，且不算一次图元绘制。至少盖住一个像素时，整段标量算一次图元绘制。

同一字体面、同一字号、同一字形号的再次绘制，着墨像素必须与第一次一致。实现可以把掩码留在显卡一侧，但不得因此改变第一次的结果。

## 4. 明确不规定

- 固件点阵、`0x20` 至 `0x7E` 以外的 `ScreenGlyph`。
- UTF-8 字节如何解码。调用方必须已经交来标量。
- 规范化、双向、连字、字距微调、`GSUB` 与 `GPOS`。
- CFF、OpenType 变体、WOFF。
- 抗锯齿和 TrueType 指令提示。

## 5. 不符合示例

1. `ScreenGlyph` 接受了 `0x4E00`。
2. `FontFace` 用宿主字体库按家族名光栅，没有读取给出的字节。
3. 截断的 `glyf` 仍得到了字体面编号。
4. 标量序列的第二个值是 `55296`，第一个字已经画上了。
5. 同一字形第二次绘制的像素与第一次不同。

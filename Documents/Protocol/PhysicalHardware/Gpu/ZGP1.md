# ZGP1 · ZerOS 显卡协议

> 路径：`Documents/Protocol/PhysicalHardware/Gpu/ZGP1.md`  
> 协议标识：`ZGP1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可判断一份显卡实现是否符合 ZGP1。参考实现不是规范。冲突时以本文为准。

## 0. 文档定位与符合性

声称兼容 ZGP1 的实现必须：

1. 使用协议标识 `ZGP1`，大小写逐字一致；
2. 提供本文全部必选字段与方法名，拼写与大小写逐字一致；
3. 帧存储只含像素整数，命令失败时不留下半帧改写；
4. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

符合本协议的显卡持有一块显存，并按自己的 Hz 执行封闭的绘图命令。帧是显存最前面的一段。`Present` 交出当前帧的一份副本。面板和面板刷新率不属于本协议。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZGP1`；
- 帧边长与像素总数的上下界；
- 像素整数；
- 字段 `FrameWidth`、`FrameHeight`、`MemoryBytes`；
- 显存按字节寻址，帧占用最前面的 `FrameWidth × FrameHeight × 4` 个字节；
- 显卡频率，范围 `1` 至 `1000000000` Hz；
- `Clear`、`Plot`、`Image`、`Character`、`Present`；
- `ReadByte`、`WriteByte`、`SetHertz`、`Metric`；
- 节点树：`SpawnBox`、`SpawnText`、`Align`、`Paint`、`Glyph`、`Drop`、`Compose`；
- 封闭字形 `0x20` 至 `0x7E`，见 [Glyph.md](./Glyph.md)。
- 坐座主机转交帧时不解释像素。

### 2.2 本协议明确不规定

- 面板、面板刷新率、画布、扫描；
- 着色器、纹理、矩阵、窗口、光标；
- 把帧放进系统内存；
- ZAP 的写法。坐座主机若转发，一次只对应本文的一条命令，指令见 ZCP1。`Image` 仍只作为本协议命令；
- 一次发出多条绘图命令；
- 参考实现声明的帧宽、帧高、显存字节数和 Hz。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 帧存储 | 长度等于 `FrameWidth × FrameHeight` 的像素序列。下标 `0` 是左上角 |
| 像素 | 整数，闭区间 `0 .. 16777215`。高 8 位是红，中间 8 位是绿，低 8 位是蓝 |
| 呈现副本 | `Present` 返回的一份新序列。此后改写帧存储不得改写这份副本 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZGP1` |
| 边长下限 | `1` |
| 边长上限 | `16384` |
| 像素个数上限 | `16777216` |
| 像素上界 | `16777215` |
| 节点个数上限 | `4096`，含根 |
| 文本字形上限 | `1024` |
| 几何绝对值上限 | `16777216` |
| 盒子种类 | `1` |
| 文本种类 | `2` |
| 靠起始边 | `0` |
| 居中 | `1` |
| 靠结束边 | `2` |
| 显存字节下限 | `4` |
| 显存字节上限 | `268435456` |
| 显存对齐 | `4` |
| 频率下限 | `1` |
| 频率上限 | `1000000000` |
| 指标 `Hertz` | `0` |
| 指标 `Executed` | `1` |

### 4.1 帧尺寸

实现必须提供 `FrameWidth` 与 `FrameHeight`。

- 类型：整数。
- 每一边都在 `1` 以上且 `16384` 以下，含两端。
- 二者的乘积在 `1` 以上且 `16777216` 以下，含两端。
- 语义：这块帧存储的宽与高。挂上之后尺寸不变。
- 下标公式：`y × FrameWidth + x`。`x` 从左向右，`y` 从上向下。`(0, 0)` 是左上角。

刚建立帧存储时，每一个元素都是 `0`。

### 4.2 命令

一次只执行一条。前一条还没完成时，后一条必须失败，且不得改写帧存储。

| 方法 | 含义 |
|------|------|
| `Clear(Pixel)` | 每一个元素都写成 `Pixel` |
| `Plot(X, Y, Pixel)` | 只改下标 `Y × FrameWidth + X` 的那一个元素 |
| `Image(X, Y, Width, Height, Pixels)` | 把一块像素矩形写入左上角 `(X, Y)` |
| `Character(X, Y, Code, Foreground, Background)` | 把一个 8×8 字形写入左上角 `(X, Y)` |
| `Present()` | 返回当前帧的副本，帧存储保持不变 |

`Pixel` 不是 `0 .. 16777215` 的整数时，`Clear`、`Plot`、`Image` 与 `Character` 必须失败，且一个元素都不改。

`X` 不在 `0 .. FrameWidth-1`，或 `Y` 不在 `0 .. FrameHeight-1` 时，`Plot` 必须失败，且一个元素都不改。

`Image` 的 `Width`、`Height` 必须是不小于 `1` 的整数。矩形必须整个落在帧内。`Pixels` 的长度必须等于 `Width × Height`，下标规则与帧存储相同。任一像素非法或矩形越界时必须失败，且一个元素都不改。

`Character` 的字形固定为 8 宽、8 高。`Code` 必须是 `0x20` 至 `0x7E` 的整数。字形矩形必须整个落在帧内。编码、颜色或位置非法时必须失败，且一个元素都不改。一行 8 个位里，值为 1 的像素写成 `Foreground`，值为 0 的像素写成 `Background`。位 7 是该行最左像素，位 0 是最右像素。行字节见 [Glyph.md](./Glyph.md)。该表封闭，禁止追加编码。

`Present` 的副本长度必须等于 `FrameWidth × FrameHeight`。副本里的值就是当时的帧存储。调用返回之后再执行绘图命令，不得改到已经交出的那份副本。

### 4.3 节点树

帧存储之外还有一棵树。根的编号是 `0`，矩形等于整帧，自己不填色。新编号从 `1` 递增，不回收。同时存在的节点数不得超过 `4096`。树不在系统内存里。

| 方法 | 含义 |
|------|------|
| `SpawnBox(Parent, X, Y, Width, Height, Fill)` | 在盒子下追加填色矩形，返回新编号 |
| `SpawnText(Parent, X, Y, Width, Height)` | 在盒子下追加空文本，返回新编号 |
| `Align(Node, AlignX, AlignY)` | 设置文本的水平与垂直对齐 |
| `Paint(Node, Foreground, Background)` | 文本写入两个像素；盒子把 `Background` 当作填色 |
| `Glyph(Node, Code)` | 向文本末尾追加一个字形 |
| `Drop(Node)` | 摘掉该节点及其全部后代 |
| `Compose()` | 用整棵树替换帧存储。树不变。没盖住的像素写成 `0` |

`Parent` 必须是已经存在的盒子。文本不能再有子节点。`X`、`Y` 相对父节点左上角，可以是负整数。`Width`、`Height` 不小于 `0`。这四个数的绝对值不得超过 `16777216`。`Fill`、`Foreground`、`Background` 必须是像素整数。`AlignX` 与 `AlignY` 只能是 `0`、`1` 或 `2`。`Code` 必须落在封闭字形表。

任一参数非法、父节点不是盒子、对根执行 `Drop` 或 `Paint`、对盒子执行 `Align` 或 `Glyph`、节点数或字形数超限时，该命令必须失败，且树与帧都保持原样。

绘制时子节点画在父节点填色之后，后一个兄弟盖住前一个。每个节点先裁到自己的矩形，再裁到祖先和帧内。文本按 8×8 从左向右排列，下一字形放不下当前行就换行。一行或整块高出矩形的部分不画，字形仍留在节点里。`1` 是居中，余数丢弃。`2` 靠右或靠下。位 7 仍是字形最左像素。

`Clear`、`Plot`、`Image`、`Character` 只改帧，不改树。`Compose` 整帧替换，因此会盖掉这些直接写入。

### 4.4 坐座主机

启用本协议的坐座主机必须：

1. 只坐 `ActiveProtocol` 为 `ZGP1` 的实现；
2. 拒绝边长或乘积越界的声明，并且不留下半绑定；
3. 转交 `Present` 副本时原样送达，不改写其中的像素，也不按像素做混合。

坐座主机可以因为面板尺寸与帧尺寸不同而拒绝把这一份副本送上面板。拒绝时必须整份丢弃，面板保持上一幅。这个比较不是显卡实现的责任。

### 4.5 必选成员

`FrameWidth`、`FrameHeight`、`MemoryBytes`、`Clear`、`Plot`、`Image`、`Character`、`SpawnBox`、`SpawnText`、`Align`、`Paint`、`Glyph`、`Drop`、`Compose`、`Present`、`ReadByte`、`WriteByte`、`SetHertz`、`Metric`，以及元数据 `ProviderId`、`ProviderVendor`、`ActiveProtocol`（取值 `ZGP1`）。可插拔形态同时符合 ZVHP1。字形字节以 [Glyph.md](./Glyph.md) 为准。

### 4.6 显存

实现必须提供 `MemoryBytes`。

- 类型：整数。
- 值域：`4` 以上且 `268435456` 以下，含两端，并且是 `4` 的倍数。
- 单位：字节。
- 语义：这块显存的容量。挂上之后不变。
- 帧占用从地址 `0` 起的 `FrameWidth × FrameHeight × 4` 个字节。容量小于这段长度时，实现不得声称已经建立显存。
- 地址是整数。`ReadByte(Address)` 返回该地址的一个字节，范围 `0` 至 `255`。`WriteByte(Address, Value)` 只改这一个字节。
- 每个 4 字节按小端组成一个字：地址 `4n` 是最低 8 位。像素命令使用帧里每个字的低 24 位。
- 地址不在 `0 .. MemoryBytes-1`，或 `Value` 不是 `0` 至 `255` 的整数时，必须失败，且不得改写任何一个字节。

刚建立显存时，每一个字节都是 `0`。

### 4.7 频率

每个实现有一个当前 Hz，以及已完成命令条数。挂上时 Hz 由该实现自己选定，必须落在 `1` 至 `1000000000`。条数从 `0` 起。失败的命令不增加条数，也不推进时间。

`SetHertz(Hertz)` 把 Hz 改成新值，并重新记下时间起点。超出范围时必须失败，且不得改写已记下的 Hz。

`Metric(Kind)` 在 `Kind` 为 `0` 时返回当前 Hz，为 `1` 时返回已完成条数。别的 `Kind` 必须失败。

一条成功的命令至少推进 1 拍。`Clear`、`Compose`、`Present` 推进的拍数等于帧的像素个数。`Image` 等于矩形的像素个数。`Character` 等于 `64`。`Plot` 与字节读写以及其余命令推进 `1` 拍。

到期时刻是本次频率起点 + 累计拍数 × 1000 / Hz 毫秒。一次命令只等待一次。已经错过的时间不补做。这不是面板的刷新率。

## 5. 不符合示例

1. 协议标识使用 `zgp1` 或 `ZGP-1`；
2. `FrameWidth` 为 `0` 或 `16385`；
3. 乘积大于 `16777216` 仍建立了帧存储；
4. `Clear` 遇到非法像素后仍然改写了前面的元素；
5. `Plot` 越界后改写了别的像素；
6. `Present` 返回的序列随后被 `Clear` 改掉；
7. 显卡实现去读画面板或设置刷新率；
8. 坐座主机按像素把两帧混合后再声称这是 `Present` 的副本；
9. `Image` 越界后仍然写入了落在帧内的那一部分；
10. `Character` 使用 `0x1F` 或 `0x7F` 仍画出了字形。
11. `MemoryBytes` 小于帧的字节数，或不是 `4` 的倍数，仍建立了显存。
12. `WriteByte` 越界后改写了别的字节。
13. `SetHertz(0)` 后 `Metric(0)` 不再是原来的 Hz。
14. 把显卡 Hz 说成面板刷新率。

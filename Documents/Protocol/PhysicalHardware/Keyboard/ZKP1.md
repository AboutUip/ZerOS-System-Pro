# ZKP1 · 键盘协议

> 路径：`Documents/Protocol/PhysicalHardware/Keyboard/ZKP1.md`  
> 协议标识：`ZKP1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可实现一份键盘设备，或判断一次交换是否符合 ZKP1。参考实现不是规范。冲突时以本文为准。

扩展口的绑定、加载、引导见 [ZXP1](../Expansion/ZXP1.md)。一次交换的方向与长度见 [ZXD1](../Expansion/ZXD1.md)。CPU 如何取出通道上的整数、如何发起一次交换，见 [ZCP1](../Cpu/ZCP1.md)。本文不重复那些规则。

## 0. 文档定位与符合性

声称兼容 ZKP1 的设备必须：

1. 使用协议标识 `ZKP1`，大小写逐字一致，并把它放在扩展插头的 `DeviceProtocol` 上；
2. `ActiveProtocol` 仍是 `ZXD1`；
3. 按本文解释每一次 `Exchange` 的八位组；
4. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

一份键盘事件是连续 6 个无符号 64 位整数。每个整数占一次方向 `0` 的交换，载荷固定 8 个八位组，小端。收满 6 个合法整数才算一次事件。设备记下这次事件，并把已完成次数加 1。

方向 `1` 按请求码读回已记下的数。宿主和主板都不解释这些整数。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZKP1`；
- 一次事件的 6 个整数槽位；
- 方向 `0` 写入与方向 `1` 读回；
- 失败时不得留下半次事件。

### 2.2 本协议明确不规定

- 键的用途、布局、重复率、指示灯；
- 谁把浏览器事件收成这 6 个整数。显示器若因宿主限制代收，那是该显示器实现的让步，不是本协议的方法；
- 扩展口编号。官方参考实现使用口 `0`，其它实现可以坐在别的已引导口上；
- 机器码字节。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 字 | 一个无符号整数，范围 `0` 至 `2^64-1`，小端 8 个八位组 |
| 事件 | 连续 6 个合法字 |
| 已完成次数 | 成功收下的事件个数，从 `0` 起 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZKP1` |
| 一字的八位组数 | `8` |
| 一次事件的字数 | `6` |
| 按下 | `0` |
| 松开 | `1` |
| 连按 | `2` |
| 请求已完成次数 | `0` |
| 请求上一次种类 | `1` |
| 请求上一次键值 | `2` |
| 请求上一次码值 | `3` |
| 请求上一次是否重复 | `4` |
| 请求上一次位置 | `5` |
| 请求上一次修饰位 | `6` |

修饰位：位 `0` 是 Shift，位 `1` 是 Ctrl，位 `2` 是 Alt，位 `3` 是 Meta。其余位必须为 `0`。

### 4.1 六个字

| 槽 | 含义 | 合法范围 |
|----|------|----------|
| `0` | 种类 | `0`、`1` 或 `2` |
| `1` | 是否重复 | `0` 或 `1` |
| `2` | 位置 | `0` 至 `3` |
| `3` | 修饰位 | `0` 至 `15` |
| `4` | 键的第一个 UTF-16 码元。空则 `0` | `0` 至 `65535` |
| `5` | 键位名，最多 8 个可打印 ASCII，小端。空则 `0` | 每个非零字节是 `0x20` 至 `0x7E`。出现 `0` 之后的字节必须全是 `0` |

### 4.2 方向 0

载荷长度必须是 `8`。设备把这 8 个八位组收成一个字，按当前槽位检查范围。

- 不合法：这次交换失败。尚未收满的字全部丢掉。已完成次数不变。不得返回半次事件。
- 合法且未满 6 字：字留下，已完成次数不变。返回值是当前已完成次数的 8 个八位组。
- 合法且正好满 6 字：记下这一次事件，已完成次数加 `1`，槽位回到 `0`。返回值是新的已完成次数。

### 4.3 方向 1

载荷长度必须是 `8`，内容是请求码。

| 请求码 | 返回 |
|--------|------|
| `0` | 已完成次数 |
| `1` | 上一次事件的种类。还没有事件时返回 `0` |
| `2` | 上一次事件的键值。还没有事件时返回 `0` |
| `3` | 上一次事件的码值。还没有事件时返回 `0` |
| `4` | 上一次事件是否重复。还没有事件时返回 `0` |
| `5` | 上一次事件的位置。还没有事件时返回 `0` |
| `6` | 上一次事件的修饰位。还没有事件时返回 `0` |

其它请求码必须失败，且不得改写已记下的事件或次数。返回值同样是 8 个小端八位组。

## 5. 不符合示例

1. `DeviceProtocol` 写成 `zkp1`；
2. 方向 `0` 接受了长度不是 `8` 的载荷；
3. 第 6 个字不合法时仍然增加已完成次数；
4. 设备自己去读显示器或主板队列，不经 `Exchange`。

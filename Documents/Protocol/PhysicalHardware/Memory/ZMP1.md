## 0. 文档定位与符合性

### 0.1 目的

本文是 **ZerOS Memory Protocol 第 1 版（ZMP1）** 的完整对外契约。

- ZerOS-PRO **仅保证**对「符合本文全部规范性要求」的内存实现提供支持。
- 第三方开发者**不得以查阅 ZerOS-PRO 源码为前提**理解本协议；**仅依据本文**即可判定自身实现是否兼容 ZMP1。
- 若某实现**声称**完全兼容 ZMP1，却因偏离本文而导致无法在 ZerOS-PRO 下按约定运行，则在协议层面视为该实现**不符合 ZMP1**，而非 ZerOS-PRO「未写明约定」。

### 0.2 规范性用语

本文中：

| 用语 | 含义 |
|------|------|
| **必须（MUST）** | 绝对要求；违反即不符合 ZMP1 |
| **禁止（MUST NOT）** | 绝对禁止；违反即不符合 ZMP1 |
| **应（SHOULD）** | 强烈建议；不满足不自动构成不符合，但可能影响互操作质量 |
| **可以（MAY）** | 真正可选 |

未使用上述用语的叙述，若出现在「规范正文」中且表述为定义、判定或约束，仍按**必须**理解。

### 0.3 符合性声明

仅当实现同时满足以下全部条件时，方可声称「完全兼容 ZMP1」或同等含义表述：

1. 提供本文规定的**全部必选字段与协议固定常量**；
2. 所有字段名、协议标识字符串、固定常量取值与本文**逐字一致**（大小写敏感）；
3. 所有字段满足本文对其**类型、值域、长度、字符集与语义判定**的要求；
4. 凡对外报告内存子系统异常，均使用符合 §4.11 的 `MemoryException` 四属性形态；
5. 凡提供内存单元，均维护符合 §4.12 的 `InitState`（默认 `0x0`，取值仅五档）；
6. 凡提供内存单元，均维护符合 §4.13 的 `Events`、`Signals`、`Exceptions` 三个对象数组；
7. 提供符合 §4.14 的引导暴露字段：`MachineMemory`、`MachineMemory.MemoryInit`，以及面向 Kernel 的 `MemoryController` 字段名；
8. 不依赖本文「明确不规定」的内容作为与 ZerOS-PRO 互操作的前提。

**禁止**在未满足以上条件时声称兼容 ZMP1。

### 0.4 字段名与标识的规范性

为避免「口头兼容、机器无法对接」：

- 本文给出的**字段名**（如 `MemoryIdByteLength`、`ShallowDimension`）为**规范名**，**必须**按此精确使用（Unicode 拼写与大小写均不可更改）。
- **禁止**以「语义等价但标识符不同」的命名替代规范名后仍声称兼容 ZMP1。
- 协议修订标识的对外机器可读值**必须**精确为字符串 `ZMP1`（四个字符：`Z` `M` `P` `1`），**禁止**使用 `zmp1`、`ZMP-1`、`ZMP 1` 等变体冒充。

### 0.5 本文与参考实现的关系

- `MemoryConfig.ts` 仅为参考实现，**不是**规范正文的一部分。
- 参考实现中的具体标定数值（如某一版的 `UnitCount = 256`）**不构成**对第三方的强制取值，除非本文明文写死。
- 若参考实现与本文冲突，**以本文为准**。

## 1. 概述

ZMP1 规定 Machine 层虚拟内存硬件在**配置契约**、**异常契约**与**内存单元状态契约**上必须遵守的约定，包括：

- 浅维度、深维度；
- 内存颗粒数量、单个内存颗粒大小（字节）；
- **总内存大小（字节）**；
- 内存 ID、内存标识（厂商）；
- 协议固定常量及其不可变取值；
- **内存异常对象**（`MemoryException`）的形态、四属性与类别档位；
- **内存单元初始化状态字段**（`InitState`）及其五档取值；
- **内存单元侧信道数组**（`Events` / `Signals` / `Exceptions`）的存在性与元素类型约束；
- **引导与对外暴露字段**（`MachineMemory` / `MemoryInit` / 面向 Kernel 的 `MemoryController`）；
- 可插拔替换见独立协议 **ZVHP1**（[PluggableVirtualHardware/ZVHP1.md](../PluggableVirtualHardware/ZVHP1.md)）：`MemorySlot.Bind` / `GetActive`。

运行时算法（随机数生成、读写、地址翻译、块/颗粒行为、状态迁移编排、异常如何处理或抛出到宿主、初始化与 Boot/Kernel 的具体调用实现等）不在本文范围；但实现一旦对外暴露「ZMP1 配置面」、报告「ZMP1 内存异常」或提供「ZMP1 内存单元」，**必须**满足本文对应契约。可插拔绑定语义以 ZVHP1 为准。

## 2. 契约范围

### 2.1 本协议规定（规范性）

- 必选字段集合、规范字段名、协议固定常量及其取值；
- 各字段的类型、值域、长度计量方式与字符集；
- 浅维度与深维度的语义定义（不含二者与颗粒数量之间的算术公式）；
- 总内存大小（字节）字段及其「默认 0 / 由初始化写入」规则；
- 内存 ID 的启用 / 禁用判定规则；
- 内存异常对象 `MemoryException` 的四属性形态、类别五档、标号空间与概述长度约束；
- 内存单元 `InitState` 五档取值与默认 `0x0`；
- 内存单元必选数组 `Events`、`Signals`、`Exceptions` 及其元素类型约束（§4.13）；
- 引导与对外暴露规范字段名：`MachineMemory`、`MemoryInit`、面向 Kernel 的 `MemoryController`（§4.14）；
- 符合性判定规则。

### 2.2 本协议明确不规定（非规范性缺口，禁止当作隐含约定）

下列事项**不在** ZMP1 内；符合本协议的实现**禁止**把下列事项宣称为「ZMP1 已规定」：

- `TotalSizeBytes` 与 `UnitCount`、`UnitSizeBytes`、浅维度、深维度之间的**任何强制算术等式**（例如是否必须等于 `UnitCount × UnitSizeBytes`）；
- 初始化阶段如何由硬件/标定推导出 `TotalSizeBytes` 的具体算法；
- 内存 ID 的随机算法、熵源、字符在允许字符集内的具体分布；
- 内存块 / 内存颗粒的读写、所有权、回收、嵌套结构的操作语义；
- `InitState` 的**完整状态迁移图**、允许的跳转边集合，以及由谁（总控/单元自身）写入（仅规定字段存在、默认值与五档语义）；
- `ExceptionChain` 对象的**内部键名、嵌套结构与序列化格式**（仅要求其为非 null 的 object）；
- `Events` / `Signals` 元素对象的**内部字段名与业务语义**（仅要求数组存在且元素为 object；结构留空待后续修订）；
- 除本文已登记标号外，其余 `ExceptionCode` 的业务含义细表（后续修订追加）；
- **异常如何被处理**：含是否写入 `Exceptions`、是否 `throw`、是否恢复/降级、检查与 try 的顺序、终止策略等（仅规定：一旦以 ZMP1 异常对象对外报告，该对象**必须**符合 §4.11）；
- 异常如何映射到宿主语言的 `throw` / Promise rejection / 日志通道；
- **`MemoryController` 上的业务方法名、参数、返回值**，以及 `MemoryInit` 上除 `Initialize` 以外的方法（`Initialize` 见 §4.14.3）；
- Boot 如何发现与加载实现的宿主语言模块语法（调用 `Initialize` 的职责仍属 Boot）；
- 操作系统页表、进程虚拟地址空间、调度与权限模型。

上述缺口若需标准化，必须通过后续协议修订（如 ZMP2+ 或其它独立协议）明文规定。

| 协议固定常量 | 配置面必须提供、取值由本文写死、禁止改写的常量 |
| 可标定字段 | 配置面必须提供，取值在本文值域内可由实现自行选定的字段 |

| 内存初始化入口 | 规范名 `MemoryInit`；必须挂在 `MachineMemory` 上；仅 Boot 可访问 |
| 内存总控对外实例字段 | 规范名 `MemoryController`；总控初始化完成后暴露给 Kernel 的字段名 |

## 4. 规范正文

### 4.0 协议固定常量（必选 · 取值不可变）

配置面**必须**提供下列常量，名称与取值**必须**如下，**禁止**缺失或改值：

| 规范字段名 | 类型要求 | 固定取值 | 附加约束 |
|------------|----------|----------|----------|
| `MemoryIdByteLength` | 正整数 | `256` | 必须恒为 256 |
| `MemoryVendorMaxLength` | 正整数 | `16` | 必须恒为 16 |

任一违反，即**不符合 ZMP1**。

若需改变上述固定取值，**必须**发布新的协议修订（ZMP2+），**禁止**在仍标识为 `ZMP1` 时改写。

### 4.1 协议修订标识（必选）

| 规范字段名 | 类型要求 | 取值约束 |
|------------|----------|----------|
| `ActiveProtocol` | 字符串 | **必须**精确等于 `ZMP1` |

### 4.2 浅维度（必选 · 可标定）

| 规范字段名 | 类型要求 | 值域 |
|------------|----------|------|
| `ShallowDimension` | 正整数 | ≥ 1 |

**语义（规范性）：** `ShallowDimension` 表示将内存划分为内存块所使用的切块尺度；实现**必须**按「存在可由该尺度划分出的内存块」这一语义解释该字段。

**本协议不规定：** 切块所得块数与 `ShallowDimension` 的精确算术公式，以及该字段与 `UnitCount` 的数量关系。

### 4.3 深维度（必选 · 可标定）

| 规范字段名 | 类型要求 | 值域 |
|------------|----------|------|
| `DeepDimension` | 正整数 | ≥ 1 |

**语义（规范性）：** `DeepDimension` 表示**单个内存块**可保存维度或可嵌套深度的上限。

**本协议不规定：** 「维度 / 嵌套」的内部数据结构与操作语义。

### 4.4 内存颗粒数量（必选 · 可标定）

| 规范字段名 | 类型要求 | 值域 |
|------------|----------|------|
| `UnitCount` | 正整数 | ≥ 1 |

**语义（规范性）：** 表示配置面上的内存颗粒个数。

### 4.5 单个内存颗粒大小（必选 · 可标定 · 单位固定）

| 规范字段名 | 类型要求 | 值域 | 单位 |
|------------|----------|------|------|
| `UnitSizeBytes` | 正整数 | ≥ 1 | **必须**为字节（byte，8 bit）；**禁止**改用 bit、字、页等其它单位表达同一字段 |

**语义（规范性）：** 每一颗内存颗粒的容量；在配置面上，全体颗粒**必须**视为同构（同一 `UnitSizeBytes`）。

### 4.6 总内存大小（必选 · 单位固定 · 默认 0 · 由初始化确定）

| 规范字段名 | 类型要求 | 值域 | 单位 |
|------------|----------|------|------|
| `TotalSizeBytes` | 非负整数 | ≥ 0 | **必须**为字节（byte，8 bit）；**禁止**改用其它单位表达同一字段 |

**语义（规范性）：**

- `TotalSizeBytes` 表示整机内存的总容量（按字节计）。
- **配置面默认值必须为 `0`**，表示「尚未由初始化确定」。
- 在声明「已完成初始化且总容量有效」的状态下，`TotalSizeBytes` **必须**为 **≥ 1** 的非负整数（即正整数）；**禁止**在该状态下仍保持 `0` 却宣称容量已就绪。
- 具体写入何值由初始化逻辑确定；本文**不规定**其与 `UnitCount`、`UnitSizeBytes` 等字段的算术关系。

**判定摘要：**

| `TotalSizeBytes` | 含义 |
|------------------|------|
| `0` | 未由初始化确定（默认 / 未就绪） |
| ≥ 1 | 已确定的总容量（字节） |

### 4.7 内存 ID（必选）

| 规范字段名 | 类型要求 | 长度 | 字符集 |
|------------|----------|------|--------|
| `MemoryId` | 字符串 | **必须**精确等于 `MemoryIdByteLength`（即 256） | 每一位**必须**为 ASCII 字符（`U+0000`–`U+007F`） |

#### 4.7.1 长度计量（消除歧义）

因每位均为 ASCII 字符，下列计量**必须**同时成立且彼此相等：

- 字符串长度为 256（按 Unicode 码点计数为 256；因均在 BMP 基本ASCII，亦等于 256 个 UTF-16 code unit）；
- 以 UTF-8 编码时的字节数为 256。

本文所称「256 字节的内存 ID」，在 ZMP1 下**即指**满足上款的 256 位 ASCII 字符串，**禁止**使用需要代理对的非 BMP 字符充数。

#### 4.7.2 启用 / 禁用判定（不另设布尔字段）

设 `ZeroId` 为：长度为 256、每一位均为数字字符 `0`（`U+0030`）的字符串。

- 当且仅当 `MemoryId` **逐位等于** `ZeroId` 时，判定为**禁用 / 未初始化**。
- 当 `MemoryId` 长度为 256、字符集合法，且**至少有一位不是** `U+0030` 时，判定为**已启用**。
- **禁止**使用单独的布尔「启用标志」字段替代上述判定后仍声称兼容 ZMP1（主机侧只认本判定）。
- **禁止**用 NUL（`U+0000`）全填充或其它字符冒充「全零禁用」语义。

#### 4.7.3 初始化与随机串

- 在未初始化或明确处于禁用态时，`MemoryId` **必须**等于 `ZeroId`。
- 在声明「已完成初始化且内存身份有效」的状态下，`MemoryId` **必须**为已启用状态（非 `ZeroId`），且每位仍为 ASCII 字符、长度仍为 256。
- 随机算法与字符在 ASCII 内的具体选取**可以**由实现自定，但**必须**满足本节长度、字符集与启用判定；**禁止**因自选算法而产出非法长度或非 ASCII 字符。

### 4.8 内存标识 / 厂商（必选 · 内容可自定）

| 规范字段名 | 类型要求 | 长度 | 字符集 |
|------------|----------|------|--------|
| `MemoryVendor` | 字符串 | 长度 L 满足 **1 ≤ L ≤ `MemoryVendorMaxLength`**（即 1–16） | 每一位**必须**为可打印 ASCII（`U+0021`–`U+007E`） |

- **禁止**空字符串。
- **禁止**空格（`U+0020`）及可打印 ASCII 以外的字符。
- 厂商具体文案由实现自定；参考实现使用 `ZerOS-Team-M1`，该具体字符串**不是**对其它实现的强制内容。

### 4.9 配置面必选成员总表（机器核对清单）

声称兼容 ZMP1 的配置面**必须**同时包含下表全部成员，不多不少地满足各列约束（汇聚用视图字段见 4.10）：

| 规范字段名 | 类别 | 约束摘要 |
|------------|------|----------|
| `ActiveProtocol` | 标识 | 精确字符串 `ZMP1` |
| `MemoryIdByteLength` | 协议固定常量 | 正整数，值 = 256 |
| `MemoryVendorMaxLength` | 协议固定常量 | 正整数，值 = 16 |
| `ShallowDimension` | 可标定 | 正整数 ≥ 1 |
| `DeepDimension` | 可标定 | 正整数 ≥ 1 |
| `UnitCount` | 可标定 | 正整数 ≥ 1 |
| `UnitSizeBytes` | 可标定 | 正整数 ≥ 1，单位 = byte |
| `TotalSizeBytes` | 规模 | 非负整数 ≥ 0，单位 = byte；默认 0；初始化后就绪时必须 ≥ 1 |
| `MemoryId` | 身份 | 长度 256，全 ASCII；全 `U+0030` = 禁用 |
| `MemoryVendor` | 身份 | 长度 1–16，可打印 ASCII |

### 4.10 可选汇聚视图（非必选）

下列名称若出现在参考实现中，仅为便利分组，**不是** ZMP1 符合性的必选条件：

- `Dimensions`、`Units`、`Identity`

实现**可以**提供、**可以**不提供；不得因缺少它们而单独判定不符合 ZMP1。若提供，其内嵌字段仍**必须**与必选字段语义一致，且**禁止**与必选字段取值冲突。

### 4.11 内存异常对象（必选形态 · 报告内存异常时）

凡符合本协议的实现，在对外报告**内存子系统异常**时，**必须**使用规范对象 `MemoryException`，且**必须**包含下列四个规范属性（名称逐字固定、大小写敏感）。**禁止**以普通字符串、无结构 Error、或缺属性对象冒充 ZMP1 内存异常。

#### 4.11.1 对象与属性总表

| 规范属性名 | 类型要求 | 值域 / 约束 |
|------------|----------|-------------|
| `ExceptionCode` | 非负整数 | **必须**落在 `0x0000`–`0xFFFF`（含端点）；对外记法为十六进制；标号含义见 4.11.3 |
| `ExceptionCategory` | 非负整数 | **必须**精确为五档之一：`0x00` / `0x01` / `0x02` / `0x03` / `0x04`（见 4.11.2） |
| `ExceptionSummary` | 字符串 | 码点长度 L 满足 0 ≤ L 且 L 严格小于 256 |
| `ExceptionChain` | object | **必须**为非 `null` 的 object；**禁止** `null` / `undefined` / 原始类型；内部键与嵌套由实现自定义 |

**禁止**增删改上述四属性的规范名；**可以**在对象上附加其它实现私有属性，但主机侧互操作**只保证**识别上述四属性。

#### 4.11.2 异常类别（仅五档 · 自 `0x00` 递增至强制终止）

`ExceptionCategory` **必须**取下表之一；**禁止**其它取值。档位按严重度自低到高排列：

| 取值 | 规范档名 | 语义 |
|------|----------|------|
| `0x00` | `Ignorable` | 可忽略异常：可记录后继续，不要求中断当前内存操作语义 |
| `0x01` | `Advisory` | 提示异常：应提示，默认不强制中断 |
| `0x02` | `Recoverable` | 可恢复异常：出现故障但允许按实现策略恢复后继续 |
| `0x03` | `Severe` | 严重异常：当前操作应视为失败；是否终止进程由宿主策略决定，但不得当作可忽略 |
| `0x04` | `Abort` | 强制终止异常：必须终止相关内存操作路径；不得静默忽略 |

#### 4.11.3 异常标号空间与已登记标号

- 标号空间自 **`0x0000`** 起，上限 **`0xFFFF`**。
- 新标号**必须**在协议修订中登记后方可被「符合 ZMP1」的实现作为稳定对外标号使用；未登记标号**禁止**冒充本文已定义含义。
- 分配规则：在 `0x0000`–`0xFFFF` 内按升序占用；本文已占用的号段不得挪作他义。

**ZMP1 已登记标号：**

权威完整登记以独立文档为准（本文仅摘要）：

- 编码登记：[ExceptionCodeRegistry.md](./ExceptionCodeRegistry.md)
- 检索索引：[ExceptionIndex.md](./ExceptionIndex.md)

| 标号 | 规范短名 | 说明 |
|------|----------|------|
| `0x0000` | `Unspecified` | 未细分的通用内存异常占位；在尚未登记更具体标号前，允许使用本标号，但仍必须带合法的 `ExceptionCategory`、`ExceptionSummary`、`ExceptionChain` |
| `0x0001` | `IllegalUnitSizeBytes` | 非法颗粒大小（`UnitSizeBytes` 非正整数等） |
| `0x0002` | `IllegalUnitCount` | 非法颗粒数量（`UnitCount` 非正整数，或关联表大小与之不一致） |
| `0x0003` | `CryptoUnavailable` | 宿主缺少可用的 `crypto.getRandomValues`（实现层索引 ID 生成失败） |
| `0x0004` | `UnitIndexAlphabetInvalid` | 颗粒索引 ID 字符表非法（实现层） |

后续具体业务异常标号在后续修订中自下一未占用号起追加登记，并**必须**同步写入上述登记表与索引。

#### 4.11.4 异常概述长度

- 设上限常量语义：`ExceptionSummaryMaxLength = 256`（协议固定语义常量；**不是**配置面必选字段）。
- `ExceptionSummary` 的 Unicode 码点长度 **必须**满足 `length < 256`。
- **禁止**长度为 256 或更大的概述。

#### 4.11.5 异常链

- `ExceptionChain` **必须**是 object，且 **禁止**为 `null`。
- 链的内部结构（字段名、是否嵌套、是否含堆栈、是否含子异常数组等）**由实现自定义**；本文不规定其 schema。
- 实现**可以**使用空对象 `{}` 作为「无附加链信息」。

### 4.12 内存单元初始化状态（必选字段 · `InitState`）

凡符合本协议的实现，其**内存单元（MemoryUnit）**在初始化相关生命周期中**必须**维护规范字段 `InitState`。

#### 4.12.1 字段约束（摘要）

| 规范字段名 | 类型要求 | 默认值 | 值域 |
|------------|----------|--------|------|
| `InitState` | 非负整数 | **必须**为 `0x0` | **必须**为已登记五档之一 |

**禁止**使用其它数值、布尔或字符串冒充 `InitState`。

#### 4.12.2 专一登记与索引（权威表）

五档取值、规范短名、语义及生命周期对应关系以独立文档为准（本文不重复展开全文）：

- 编码登记：[InitStateRegistry.md](./InitStateRegistry.md)
- 专一索引：[InitStateIndex.md](./InitStateIndex.md)

| 取值 | 规范短名（摘要） |
|------|------------------|
| `0x0` | `InvalidPending` |
| `0x1` | `Preparing` |
| `0x2` | `InitFault` |
| `0x3` | `InitComplete` |
| `0x4` | `Active` |

#### 4.12.3 与初始化的关系（摘要）

- 初始对外状态 **必须**为 `0x0`；初始化中 **必须**为 `0x1`；失败 **必须**为 `0x2`；完成未启用 **必须**为 `0x3`；正式启用 **必须**为 `0x4`。
- 完整语义与核对清单见登记表 / 索引；状态迁移编排见 §2.2（明确不规定完整跳转表）。
- **禁止**在仍为 `0x0` / `0x1` / `0x2` 时宣称单元已「正式启用」。

### 4.13 内存单元侧信道数组（必选 · `Events` / `Signals` / `Exceptions`）

凡符合本协议的实现，其**内存单元（MemoryUnit）必须**维护下列三个数组字段。规范字段名逐字固定、大小写敏感。三个数组的元素**必须**均为 **object**（**禁止**以数字、字符串、布尔等原始类型作为元素冒充）。

#### 4.13.1 数组总表

| 规范字段名 | 元素类型要求 | 默认 | 约束 |
|------------|--------------|------|------|
| `Events` | object | 构造完成时**必须**为空数组 `[]` | 元素对象内部字段**本修订不规定**（结构留空）；**禁止**缺失本数组 |
| `Signals` | object | 构造完成时**必须**为空数组 `[]` | 元素对象内部字段**本修订不规定**（结构留空）；**禁止**缺失本数组 |
| `Exceptions` | `MemoryException`（§4.11 四属性齐全） | 构造完成时**必须**为空数组 `[]` | 凡写入本数组的元素**必须**满足 §4.11；**禁止**以非四属性对象充数；**不规定**何时写入、是否写入 |

#### 4.13.2 与异常对象的关系

- `Exceptions` 是存放 `MemoryException` 的容器字段；**是否**、**何时**、**如何**向其中追加，以及异常的恢复/抛出/终止策略，**均不在**本修订规定（见 §2.2）。
- 一旦某元素出现在 `Exceptions` 中，该元素**必须**为合规 `MemoryException`。
- `Events` / `Signals` 的推入时机与消费语义**不在**本修订规定；实现**禁止**声称「某事件/信号字段布局为 ZMP1 已规定」直至后续修订明文给出。

#### 4.13.3 不符合示例（本条）

- 缺失 `Events` / `Signals` / `Exceptions` 任一数组；
- `Exceptions` 中推入 `{ code: 1 }` 或缺四属性对象；
- `Events` 中推入字符串 `"ready"` 等非 object 元素。

### 4.14 引导与对外暴露字段（必选规范名）

凡符合本协议的实现，**必须**按下列规范名提供引导与对外挂载字段，供 Boot / Kernel 与第三方用**相同字段名**完成引导与后续调用。大小写敏感，**禁止**用语义近似名替代。

#### 4.14.1 字段总表

| 规范名 | 挂载位置 | 角色约束 | 本修订要求 |
|--------|----------|----------|------------|
| `MachineMemory` | 实现提供的内存引导门面（对象或等价命名空间） | 整机内存侧对外引导入口 | **必须**存在 |
| `MemoryInit` | **必须**为 `MachineMemory` 上的字段 | 内存初始化入口；**仅 Boot** 可访问并执行引导；**禁止** Kernel、其它 Machine 子系统或用户态将其当作公开入口 | **必须**存在；**必须**提供方法 `Initialize`（见 §4.14.3） |
| `MemoryController` | **必须**作为面向 **Kernel** 的暴露字段名 | 内存总控完成初始化后，将**自身**挂到该字段，供 Kernel 调用；后续业务 API 亦挂在此实例上 | 字段名**必须**为 `MemoryController`；初始化前可为空/未就绪 |

#### 4.14.2 引导关系（规范性链路）

符合本协议的实现**必须**支持下列逻辑链路（名称与方向固定）：

1. **Boot** 经 `MachineMemory.MemoryInit` 取得内存初始化入口并调用 `Initialize`；
2. `MemoryInit.Initialize` **引导并初始化**内存总控；
3. 内存总控初始化完成后，将自身暴露为 Kernel 侧的 `MemoryController`。

**禁止**将初始化入口挂在其它规范名（如 `Init`、`MemoryBootstrap`、`machine_memory`）后仍声称兼容 ZMP1。  
**禁止**宣称「非 Boot 角色可合法直接调用 `MemoryInit`」为 ZMP1 要求（本文要求仅 Boot 可访问该入口）。

#### 4.14.3 最小规范方法 `Initialize`（必选）

挂在 `MemoryInit` 上的下列方法为 ZMP1 **最小必选**（名称逐字固定）：

| 规范方法名 | 参数 | 返回值 | 语义 |
|------------|------|--------|------|
| `Initialize` | **无** | **无**（`void` / 等价「无返回值」） | 执行内存初始化：创建内存总控（若尚未创建），并将其自身写入 Kernel 侧字段 `MemoryController` |

附加约束：

- **幂等**：若 `MemoryController` 已非空（已初始化），再次调用 `Initialize` **必须**安全返回，**禁止**要求调用方先查状态才能调用。
- **禁止**以 `init` / `Run` / `Bootstrap` 等非规范名替代 `Initialize` 后仍声称兼容 ZMP1。
- 除 `Initialize` 外，挂在 `MemoryInit` / `MemoryController` 上的**其它**方法名、参数与返回值由**后续协议修订**规定；本修订不锁定它们。

## 5. 不符合示例（非穷尽）

下列情形**一律不符合 ZMP1**（示例用于消除常见钻空子说法）：

1. 使用字段名 `memory_id` / `MemId` / `MemoryID` 替代 `MemoryId`；
2. `ActiveProtocol = "zmp1"` 或 `"ZMP-1"`；
3. `MemoryIdByteLength = 128` 或未提供该常量；
4. `MemoryId` 长度为 256 但含非 ASCII 字符，或 UTF-8 字节数因非 ASCII 而不为 256；
5. 以 256 个 NUL（`U+0000`）表示禁用；
6. `ShallowDimension = 0`、`UnitCount = -1`、`UnitSizeBytes = 1.5`；
7. 缺失 `TotalSizeBytes`，或使用 `TotalSize` / `total_size_bytes` 等非规范名冒充；
8. `TotalSizeBytes` 单位按 KiB/MiB 计数却仍用字段名 `TotalSizeBytes`；
9. 声明「初始化已完成且总容量有效」但 `TotalSizeBytes === 0`；
10. `MemoryVendor = ""` 或含空格 / 中文 / 表情符号；
11. 另设 `MemoryIdEnabled: false` 且 `MemoryId` 为非全零，却宣称「以布尔为准」；
12. 声称「`TotalSizeBytes` 必须等于 `UnitCount × UnitSizeBytes`」并把它当作 ZMP1 要求（本文未规定该等式）；
13. 声称「浅维度 × 深维度必须等于颗粒数」并把它当作 ZMP1 要求（本文未规定该公式）；
14. 报告内存异常时仅抛出字符串 / 原生 `Error`，或不含完整四属性的对象；
15. 使用属性名 `code` / `Category` / `message` 等替代 `ExceptionCode` / `ExceptionCategory` / `ExceptionSummary` / `ExceptionChain`；
16. `ExceptionCategory = 0x05` 或其它非五档取值；
17. `ExceptionSummary` 码点长度 ≥ 256；
18. `ExceptionChain = null` 或 `ExceptionChain = "trace"`；
19. 使用未登记标号并宣称其具有本文已定义的稳定业务含义（除 `0x0000 Unspecified` 外）；
20. 内存单元缺少 `InitState`，或 `InitState = 0x5` / 其它非五档取值；
21. 单元构造后默认 `InitState !== 0x0`；
22. `InitState` 仍为 `0x0` / `0x1` / `0x2` 却宣称单元已「正式启用」（`0x4`）；
23. 内存单元缺失 `Events` / `Signals` / `Exceptions` 任一数组，或 `Exceptions` 中出现非合规 `MemoryException`，或 `Events` / `Signals` 中出现非 object 元素；
24. 缺失 `MachineMemory`，或初始化入口未以字段名 `MemoryInit` 挂在 `MachineMemory` 上；
25. 使用 `memoryInit` / `InitMemory` / `Bootstrap` 等非规范名冒充 §4.14 字段后声称兼容 ZMP1；
26. 总控对 Kernel 暴露时使用非 `MemoryController` 的字段名（如 `MemCtrl` / `Controller`）却声称兼容 ZMP1；
27. `MemoryInit` 缺失方法 `Initialize`，或以 `init` / `Run` / `Bootstrap` 冒充后声称兼容 ZMP1。

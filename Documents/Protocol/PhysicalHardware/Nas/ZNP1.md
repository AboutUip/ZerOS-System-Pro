# ZNP1 · NAS 协议

> 路径：`Documents/Protocol/PhysicalHardware/Nas/ZNP1.md`  
> 协议标识：`ZNP1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可实现一份 NAS 设备，或判断一次交换是否符合 ZNP1。参考实现不是规范。冲突时以本文为准。

扩展口的绑定、加载、引导见 [ZXP1](../Expansion/ZXP1.md)。一次交换的方向与长度见 [ZXD1](../Expansion/ZXD1.md)。本文规定这 8 个八位组的含义。宿主不得另加一套寻址方式，也不得把文件内容当成中央处理器的取指来源。

## 0. 文档定位与符合性

声称兼容 ZNP1 的设备必须：

1. 使用协议标识 `ZNP1`，大小写逐字一致，并把它放在扩展插头的 `DeviceProtocol` 上；
2. `ActiveProtocol` 仍是 `ZXD1`；
3. 按本文解释每一次 `Exchange` 的八位组；
4. 服务进程没有启动、路径不存在、或一次文件操作失败时，不得让这次失败变成扩展口 `Load` / `Boot` 的失败，也不得变成宿主引导序列的失败；
5. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

设备保存一棵树。客程序看见的根是 `/`。一次客调用先 `Begin`，再送路径、句柄和数据，然后 `Exec`，需要字节时再 `Pull`，最后 `End`。每个字都是 8 个八位组。服务没有应答时，返回状态表示未就绪，扩展口保持已引导。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZNP1`；
- 方向 `0` 的会话、路径、句柄、范围、阶段数据和执行；
- 路径怎样相对客根 `/` 折叠，以及哪些名字非法；
- 一次执行的动词，以及成功时返回字里各八位组的位置；
- 失败时不得把该次执行报告为成功。

### 2.2 本协议明确不规定

- 扩展口编号。官方参考实现使用的口不是本协议的一部分；
- 客程序用哪一种语言组这些字。官方 Obr 库不是本协议的一部分；
- 设备进程的监听地址、传输方式，以及数据目录在宿主磁盘上的位置；
- 符号链接、权限位、设备节点和硬链接。本协议没有这些对象；
- 文件名在屏幕上的字形。屏幕字体仍只覆盖可打印 ASCII。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 字 | 一个无符号整数，范围 `0` 至 `2^64-1`，小端 8 个八位组。第 0 个八位组是最低的 8 位 |
| 客根 | 客路径 `/`。它不是宿主操作系统的根目录 |
| 会话 | 从一次成功的 `Begin` 到 `End` 或 `Reset`。同一时间只能有一个会话 |
| 阶段 | 尚未执行的写入字节，上限 1024 |
| 句柄 | `1` 至 `32` 的整数。`0` 不是有效句柄 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZNP1` |
| 一字的八位组数 | `8` |
| 路径上界 | `240` 个八位组 |
| 搬运下界 | `262144` 个八位组。连续批量读取从这里起 |
| 搬运上界 | `268435456` 个八位组。一次读取或写入不得多于这个数 |
| 同时打开的句柄 | `32` |
| 复位 | `0` |
| 追加路径 | `1` |
| 收存路径 | `2` |
| 设置句柄 | `3` |
| 设置窗口 | `4` |
| 追加阶段 | `5` |
| 执行 | `6` |
| 拉回 | `7` |
| 开始 | `8` |
| 结束 | `9` |

未列入的操作码必须失败，状态为 `13`，且不得改会话。

### 4.1 方向与长度

只接受方向 `0`。方向不是 `0`，或载荷不是 8 个八位组时，这次交换失败，会话保持原样，扩展口仍是已引导。失败是交换本身失败，不是下面的状态码。

返回必须也是 8 个八位组。第 0 个八位组是状态。

### 4.2 状态

| 码 | 含义 |
|----|------|
| `0` | 成功 |
| `1` | 未就绪。服务没有应答 |
| `2` | 没有这个路径或目录项 |
| `3` | 需要目录，目标不是目录 |
| `4` | 需要文件，目标是目录 |
| `5` | 句柄无效，或这一次打开方式不允许该操作 |
| `6` | 名字非法，或路径逃出客根 |
| `7` | 超出路径、阶段、句柄表或单次搬运的上界 |
| `8` | 设备内部失败。含符号链接 |
| `9` | 已经有会话，不能再 `Begin` |
| `10` | 没有会话 |
| `11` | 目标已经存在 |
| `12` | 目录非空 |
| `13` | 操作码、槽、长度或打开方式不在规定范围内 |

未列入的状态码禁止使用。

### 4.3 会话

`Reset` 清空路径、句柄、窗口、阶段、拉回缓冲，并解除会话，然后询问服务是否在应答。服务应答且状态为 `0` 时返回 `0`。没有应答时返回 `1`。无论哪种，清空都已经发生。

`Begin` 在已有会话时返回 `9`，且不得清空上一次调用的路径。没有会话时建立会话，清空路径、句柄、窗口、阶段和拉回缓冲，返回 `0`。`Begin` 不访问服务。

`End` 解除会话，返回 `0`。没有会话时也返回 `0`。

除 `Reset`、`Begin`、`End` 以外的操作，没有会话时返回 `10`，且不得改状态以外的字段。

### 4.4 路径

路径是 UTF-8 八位组。分隔符只有 `/`。空路径和 `/` 都是客根。不以 `/` 开头的路径也从客根算起，设备没有当前工作目录。

连续的 `/` 折成一个。`.` 留下当前这一层。`..` 回到上一层。已经在客根时再遇 `..`，这一次执行失败，状态为 `6`，且不得访问客根之外。八位组 `0`、`\`、`:` 出现在路径里时，状态为 `6`。不是合法 UTF-8 时，状态为 `6`。

路径槽有两个。`PathAppend` 的第 1 个八位组是长度，必须是 `1` 至 `6`，随后该长度的八位组追加到正在组装的路径。追加后会超过 `240`，或长度不在 `1` 至 `6` 时，必须失败且不得收下这一片段。

`PathKeep` 的第 1 个八位组是槽，只能是 `0` 或 `1`。它把正在组装的路径抄进该槽，然后清空组装缓冲。空缓冲抄进去就是客根。

需要一个路径的动词使用槽 `0`。重命名使用槽 `0` 为源、槽 `1` 为目的。

### 4.5 句柄与窗口

`SetHandle` 的第 1、第 2 个八位组是小端 16 位句柄。

`SetRange` 的第 1 至第 4 个八位组是小端 32 位起点，第 5、第 6 个八位组是小端 16 位长度。这个字段最大是 `65535`。长度大于 `65535` 时无法放进这两个八位组，这次设置失败，状态为 `7`，窗口保持原样。起点大于 `2^32-1` 无法放进这 4 个八位组，因而不在本协议内。大于 `65535` 的读取不使用这个字段，而使用下面的按句柄一次读取。

`Stage` 的第 1 个八位组是长度，必须是 `1` 至 `6`，随后该长度的八位组追加到阶段缓冲。追加后会超过搬运上界时失败，状态为 `7`，且不得收下这一片段。

一次读取或写入的长度大于搬运上界时失败，状态为 `7`，且不得改树。连续批量读取的长度从搬运下界起。上一笔实际个数等于当时请求的长度、且该长度小于搬运上界时，下一笔是本次的 2 倍，但不得超过搬运上界，也不得超过对象剩余。上一笔没有搬满，或剩余少于搬运下界时，下一笔回到搬运下界；剩余更短则这一笔就等于剩余。对象本身短于搬运下界时，一次取完剩余，这一笔可以小于搬运下界。

### 4.6 动词

`Exec` 的第 1 个八位组是动词，第 2 个八位组只在打开时是打开方式。

| 动词 | 作用 |
|------|------|
| `1` | 查看槽 `0`。成功时第 1 个八位组是种类：`1` 文件，`2` 目录。第 2 至第 5 个八位组是小端 32 位大小。目录的大小是 `0`。大小超过 `2^32-1` 时状态为 `7` |
| `2` | 打开槽 `0`。打开方式 `0` 只读，`1` 只写并截断或创建，`2` 读写并在缺少时创建，`3` 追加并在缺少时创建。其它方式状态为 `13`。成功时第 2、第 3 个八位组是小端 16 位句柄。目标是目录时状态为 `4` |
| `3` | 关闭当前句柄 |
| `4` | 从当前句柄、窗口起点读出至多窗口长度的八位组，放进拉回缓冲。成功时第 2、第 3 个八位组是实际长度。读到末尾时状态仍是 `0`，长度可以是 `0` |
| `5` | 把阶段缓冲写到当前句柄。打开方式 `3` 时写到末尾，忽略窗口起点；其它可写方式写到窗口起点。成功时第 2、第 3 个八位组是写下的长度。阶段为空时写下的长度是 `0` |
| `6` | 创建槽 `0` 这一层目录。父层必须已经存在。已存在时状态为 `11` |
| `7` | 删除槽 `0`。文件直接删除。空目录可以删除。非空目录状态为 `12` |
| `8` | 把槽 `0` 改名为槽 `1` |
| `9` | 读取槽 `0` 目录中窗口起点所指数的一项，从 `0` 起。成功时第 2、第 3 个八位组是名字的八位组数，名字放进拉回缓冲。没有这一项时状态为 `2`。名字按 UTF-8 八位组序排列。不列出 `.` 和 `..` |

未列入的动词必须失败，状态为 `13`，且不得改树。

句柄表已满时，打开失败，状态为 `7`，且不分配新句柄。

符号链接不作为文件或目录。查看、打开、枚举到它时，状态为 `8`。枚举跳过符号链接，使客程序看不见它。

### 4.7 拉回

`Pull` 取走拉回缓冲中尚未取走的至多 6 个八位组。第 1 个八位组是这次取走的个数，随后是这些八位组。缓冲取完后，个数是 `0`，状态是 `0`。

上一次执行的状态不是 `0` 且缓冲为空时，`Pull` 重复该状态，个数是 `0`。

宿主还可以一次取走尚未取走的至多 `4096` 个八位组。这次取走不是新的操作码，也不经过 8 个八位组的字。游标只前进实际取走的个数，剩余仍可由 `Pull` 取走。没有会话，或上一次执行失败且缓冲为空时，状态不是 `0`，取走个数是 `0`。禁止一次取走多于 `4096`。取走的字节必须与从同一游标起反复 `Pull` 能得到的字节相同。

宿主还可以一次完成「`Begin`、设句柄、设窗口、`Exec` 读取、取走、`End`」。效果与客机按这个顺序各做一次相同，包括失败时的状态。返回前会话必须已经结束。这一次的长度是上面的批量长度，可以大于 `65535`，但不得大于搬运上界。实际个数由这次操作的结果给出。执行应答里第 2、第 3 个八位组仍是小端 16 位，放不下大于 `65535` 的完整个数。这不是新的操作码，8 个八位组的字也不变。

### 4.8 失败隔离

`Load` 与 `Boot` 必须成功，即使服务进程没有启动。未就绪只出现在之后的交换里。

一次 `Exec` 的读取，要么把读到的整段放进拉回缓冲并返回成功，要么返回非 `0` 且拉回缓冲为空。禁止返回成功的同时又只放进半段却把长度说成请求的长度。

一次 `Exec` 的写入，要么该段全部落下并返回实际长度，要么返回非 `0`，且不得把这次报告为成功。设备不把已经落盘的前缀再撤销。

## 5. 不符合示例

1. 服务进程没启动时，`Boot` 失败，后面的扩展口不再引导；
2. 路径 `/../` 读到了客根之外的宿主文件；
3. 已有会话时再次 `Begin`，把前一次的路径清掉并返回成功；
4. 追加路径超过 `240` 时仍收下了超出的片段；
5. 读取失败，却把拉回缓冲里的半段报告为成功且长度等于请求长度；
6. 返回的载荷不是 8 个八位组。
7. 一次取走拉回缓冲时超过 `4096`，或取走之后剩余字节与继续 `Pull` 能取到的不一致。
8. 一次读取多于 `268435456` 个八位组仍报告成功。
9. 对象剩余不少于 `262144` 时，下一笔批量读取仍固定为 `1024`。

|------|------|
| ZNP1 | 首版：扩展口上的单根目录。8 八位组会话，服务未就绪不失败引导 |

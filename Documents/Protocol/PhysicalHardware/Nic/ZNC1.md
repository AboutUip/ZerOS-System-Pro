# ZNC1 · 网卡协议

> 文档路径：`Documents/Protocol/PhysicalHardware/Nic/ZNC1.md`  
> 规范状态：**规范性（Normative）**  
> 协议标识字符串（唯一）：`ZNC1`  
> 参考实现（非规范）：`ZerOS-PRO/Hardware/Nic/`  
> 索引：[README.md](./README.md)

读者只凭本文即可判断一份网卡实现是否符合 ZNC1。参考实现不是规范。冲突时以本文为准。数据交换的载体是 [ZXD1](../Expansion/ZXD1.md)。

## 0. 文档定位与符合性

声称兼容 ZNC1 的网卡必须：

1. 使用协议标识 `ZNC1`，大小写逐字一致；
2. 通过 ZXD1 的方向 `0` 提供 8 个八位组的控制字；
3. 通过 `Offer` 接收一帧原始以太网报文，通过 `Carry` 交出一帧原始以太网报文；
4. 不解释以太网、IP、TCP、UDP、ARP、DNS 或 HTTP 的字节含义；
5. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

ZNC1 是哑网卡。它只负责把原始以太网帧交给线，以及把线收到的原始以太网帧交回宿主。所有网络状态、连接、重传、校验、调度和缓冲策略属于驱动，不属于网卡。

网卡不提供 HTTP、DNS、TCP、UDP 或 socket 级 API。它也不解析帧里的任何字段。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZNC1`；
- 控制字的 8 个八位组布局；
- 发送一帧和接收一帧的 ZXD1 方法；
- 状态码 `0` 至 `7`；
- 帧上界通过控制字报告，不在协议里写死；
- 驱动选择参考线：回环或 UDP 虚拟线段。

### 2.2 本协议明确不规定

- 以太网帧的内容、地址、类型和校验；
- 线的物理形态（虚拟回环、UDP 数据报、TAP、真实网卡等）；
- 帧的顺序、重传、流控和队列策略；
- 并发度、队列深度和多条连接；
- 驱动怎样组织 TCP/IP 栈。

线的形态和启动参数属于参考实现，不属于 ZNC1 的语义。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 帧 | 一段八位组序列，含义由以太网及其上层决定。网卡不解释 |
| 控制字 | ZXD1 方向 `0` 上 8 个八位组的交换 |
| 发送 | 宿主用 `Offer` 把一帧交给网卡 |
| 接收 | 宿主用 `Carry` 从网卡取走一帧 |
| 空 | 当前没有可接收的帧，状态 `1` |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZNC1` |
| 成功 | `0` |
| 空 | `1` |
| 未就绪 | `2` |
| 操作码不认识 | `3` |
| 太长 | `4` |
| I/O 错误 | `5` |
| 忙 | `6` |
| 参数不合法 | `7` |

### 4.1 控制字

`Exchange(Index, 0, Payload)` 的 `Payload` 必须是 8 个八位组。宿主只使用方向 `0`；方向 `1` 不是 ZNC1 的操作，必须失败。

控制字的第一个八位组是操作：

| 操作 | 名称 | 含义 |
|------|------|------|
| `0` | INFO | 读取能力 |
| `1` | CONFIG | 选择线 |

`INFO` 的答复也是 8 个八位组，按小端解释：

| 偏移 | 宽度 | 含义 |
|------|------|------|
| 0 | 1 | 状态 |
| 1 | 4 | 一帧上界，八位组 |
| 5 | 2 | 参考接收队列深度 |
| 7 | 1 | 线的种类，参考实现自定 |

状态不是 `0` 时，其余字段可以是 `0`。一帧上界是这一次连接的能力上界，不是协议常量。驱动可以按它决定每次交多少。

`CONFIG` 的请求布局：

| 偏移 | 宽度 | 含义 |
|------|------|------|
| 0 | 1 | `1` |
| 1 | 1 | 线种类：`0` 回环，`1` UDP |
| 2 | 4 | IPv4 地址，按网络顺序 |
| 6 | 2 | UDP 端口，按网络顺序 |

回环忽略地址和端口。UDP 线把一帧放进一个数据报。实现不支持的线种类必须返回状态 `7`，不得静默换成另一种线。`CONFIG` 的答复是 8 个八位组，只有偏移 `0` 的状态有意义，其余可以是 `0`。

选哪条线是驱动的事。网卡不替驱动决定，也不因为某条线不可用而改走另一条。

### 4.2 发送

`Offer(Index, Request, ReplyMax)` 的 `Request` 正好是一帧原始以太网报文。网卡必须：

1. 不解析、不改写、不截断 `Request`；
2. 把整帧交给线；
3. 成功时返回状态 `0`，答复字节为空；
4. 超过该次控制字报告的上界时返回 `4`；
5. 线发生 I/O 错误时返回 `5`。

网卡不得把一帧拆成多条上层消息，也不得把多帧合成一条 `Offer`。

### 4.3 接收

`Carry(Index, 0, 0, Count)` 取走至多一帧，`Count` 是宿主能接收的最大八位组数。网卡必须：

1. 成功时返回状态 `0`，字节正好是一帧；
2. 没有帧时返回状态 `1`，字节为空；
3. 帧长超过 `Count` 时返回状态 `4`，不交半帧；
4. 线发生 I/O 错误时返回 `5`。

队列为空不是错误。驱动可以立即再试，也可以按自己的调度等待。

### 4.4 顺序与并发

ZXD1 规定同一个口不能重叠交换。ZNC1 不额外规定帧的顺序、队列深度和并发度。参考实现按到达顺序交出帧；这不是协议要求。

## 5. 不符合示例

1. 网卡解析 IP 头或 TCP 头后改写帧；
2. 网卡提供 `connect`、`listen`、`send` 这类 socket API；
3. `Offer` 成功却返回了非空答复；
4. 帧超过控制字报告的上界仍被接受；
5. 没有帧时用状态 `0` 交出空字节；
6. 把一条 `Offer` 当成多条上层消息。

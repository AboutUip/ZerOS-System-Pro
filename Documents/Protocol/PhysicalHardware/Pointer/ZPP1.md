# ZPP1 · 鼠标协议

> 文档路径：`Documents/Protocol/PhysicalHardware/Pointer/ZPP1.md`
> 规范状态：**规范性（Normative）**
> 协议标识字符串（唯一）：`ZPP1`
> 参考实现（非规范）：`ZerOS-PRO/Hardware/Pointer/`
> 索引：[README.md](./README.md)

读者只凭本文即可实现一份 ZPP1 鼠标设备，或判断一次交换是否符合 ZPP1。参考实现不是规范。冲突时以本文为准。

扩展口的绑定、加载、引导见 [ZXP1](../Expansion/ZXP1.md)。一次交换的方向与长度见 [ZXD1](../Expansion/ZXD1.md)。CPU 如何取出通道上的整数、如何发起一次交换，见 [ZCP1](../Cpu/ZCP1.md)。本文不重复那些规则。

## 0. 文档定位与符合性

声称兼容 ZPP1 的设备必须：

1. 使用协议标识 `ZPP1`，大小写逐字一致，并把它放在扩展插头的 `DeviceProtocol` 上；
2. `ActiveProtocol` 仍是 `ZXD1`；
3. 按本文解释每一次 `Exchange` 的八位组；
4. 不把本文「明确不规定」的内容宣称为协议要求。

本版 ZPP1 在开发期原位更新为 7 字事件：前 6 字语义不变，第 7 字是关联号。协议标识不升版本；旧 6 字实现不兼容，设备仍必须在 `DeviceProtocol` 上写 `ZPP1`。

## 1. 概述

一份鼠标事件是连续 7 个无符号 64 位整数。每个整数占一次方向 `0` 的交换，载荷固定 8 个八位组，小端。收满 7 个合法整数才算一次事件。设备把这次事件放进未读队列，并把已完成次数加 1。按下和松开还会改按住掩码。

方向 `1` 按请求码读回。请求码 `1` 至 `6` 读的是队列里最旧的一次，读本身不把它移出队列。请求码 `9` 才移出。请求码 `10` 返回最旧未读事件的关联号。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZPP1`；
- 一次事件的 7 个整数槽位；
- 第 7 个整数是关联号；
- 方向 `0` 写入与方向 `1` 读回；
- 按住掩码随按下、松开更新；
- 未读队列至少能留下 32 次事件，读和移出分开；
- 失败时不得留下半次事件，也不得改按住掩码。

### 2.2 本协议明确不规定

- 光标形状、加速、双击间隔、滚轮一格对应多少行；
- 谁把浏览器事件收成这 7 个整数；
- 坐标相对哪一块面板。设备只检查整数范围，不读显示器；
- 扩展口编号。官方参考实现使用口 `3`，其它实现可以坐在别的已引导口上；
- 机器码字节。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 字 | 一个无符号整数，范围 `0` 到 `2^64-1`，小端 8 个八位组 |
| 事件 | 连续 7 个合法字 |
| 已完成次数 | 成功收下的事件个数，从 `0` 起。被挤出队列的也算 |
| 未读队列 | 还没有被请求码 `9` 移出的事件，按收下的先后排列 |
| 按住掩码 | 当前还按着的键。位 `0` 左，位 `1` 右，位 `2` 中，位 `3` 后退，位 `4` 前进。在第 7 个字收下时更新 |
| 关联号 | 第 7 个字；设备原样保存，查询码 `10` 返回最旧未读事件的关联号 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZPP1` |
| 一字的八位组数 | `8` |
| 一次事件的字数 | `7` |
| 移动 | `0` |
| 按下 | `1` |
| 松开 | `2` |
| 滚轮 | `3` |
| 无键 | `0` |
| 左键 | `1` |
| 右键 | `2` |
| 中键 | `3` |
| 后退 | `4` |
| 前进 | `5` |
| 坐标上界 | `16383` |
| 未读队列至少保留 | `32` |
| 请求已完成次数 | `0` |
| 请求最旧未读种类 | `1` |
| 请求最旧未读键 | `2` |
| 请求最旧未读横坐标 | `3` |
| 请求最旧未读纵坐标 | `4` |
| 请求最旧未读修饰位 | `5` |
| 请求最旧未读滚轮 | `6` |
| 请求按住掩码 | `7` |
| 请求未读个数 | `8` |
| 请求移出最旧未读 | `9` |
| 请求最旧未读关联号 | `10` |

修饰位：位 `0` 是 Shift，位 `1` 是 Ctrl，位 `2` 是 Alt，位 `3` 是 Meta。其余位必须是 `0`。

### 4.1 七个字

| 字 | 含义 | 合法范围 |
|----|------|----------|
| `0` | 种类 | `0`、`1`、`2` 或 `3` |
| `1` | 键 | 移动或滚轮时必须是 `0`。按下或松开时是 `1` 到 `5` |
| `2` | 横坐标，向右增大 | `0` 到 `16383` |
| `3` | 纵坐标，向下增大 | `0` 到 `16383` |
| `4` | 修饰位 | `0` 到 `15` |
| `5` | 滚轮 | 见下。移动、按下、松开时必须是 `0` |
| `6` | 关联号 | 任意 64 位值 |

滚轮字的位 `15 .. 0` 是垂直分量，位 `31 .. 16` 是水平分量，都是二进制补码的 16 位整数。位 `63 .. 32` 必须是 `0`。垂直分量向下为正，水平分量向右为正。

### 4.2 方向 0

载荷长度必须是 `8`。设备把这 8 个八位组收成一个字，按当前槽位检查范围。

- 不合法：这次交换失败。尚未收满的字全部丢掉。已完成次数和按住掩码都不变。不得返回半次事件。
- 合法且未满 7 字：字留下，已完成次数不变。返回值是当前已完成次数的 8 个八位组。
- 合法且正好满 7 字：已完成次数加 `1`，槽位回到 `0`。这次事件（包括第 7 字关联号）进入未读队列。按下把该键的位设 `1`，松开把该键的位清 `0`。这两步发生在进入队列的同时，不因后来被挤出而撤销。返回值是新的已完成次数。

未读队列至少保留 32 次。队列未满时，禁止丢掉已经收下的事件。队列已满又来一次时，必须先丢掉最旧的一次移动（种类 `0`）。没有移动可丢时，必须丢掉最旧的一次。丢掉的事件不再被读到，已完成次数不减。

### 4.3 方向 1

载荷长度必须是 `8`，内容是请求码。

| 请求码 | 返回 |
|--------|------|
| `0` | 已完成次数 |
| `1` | 最旧未读事件的种类。队列空时：有过事件则是最近一次离开队列的种类，否则 `0` |
| `2` | 最旧未读事件的键。空队列规则与种类相同 |
| `3` | 最旧未读事件的横坐标。空队列规则与种类相同 |
| `4` | 最旧未读事件的纵坐标。空队列规则与种类相同 |
| `5` | 最旧未读事件的修饰位。空队列规则与种类相同 |
| `6` | 最旧未读事件的滚轮字。空队列规则与种类相同 |
| `7` | 按住掩码。还没有按下过时返回 `0` |
| `8` | 未读个数。不移出事件 |
| `9` | 移出最旧未读事件，返回剩下的个数。队列空时返回 `0` |
| `10` | 最旧未读事件的关联号。空队列规则与种类相同 |

其它请求码必须失败，且不得改写已记下的事件、次数或按住掩码。

## 5. 不符合示例

1. `DeviceProtocol` 写成 `zpp1`；
2. 方向 `0` 接受了长度不是 `8` 的载荷；
3. 7 个字不合法时仍然增加已完成次数；
4. 按下或松开没有更新按住掩码；
5. 队列未满时丢掉已经收下的事件；
6. 声称 ZPP1 却按 6 字事件完成。

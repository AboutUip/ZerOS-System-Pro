# ZSP1 · 沙盒协议

> 路径：`Documents/Protocol/PhysicalHardware/Sandbox/ZSP1.md`  
> 协议标识：`ZSP1`  
> 规范状态：**规范性**  
> 索引：[README.md](./README.md)

读者只凭本文即可实现一份沙盒设备，或判断一次交换是否符合 ZSP1。参考实现不是规范。冲突时以本文为准。

扩展口的绑定、加载、引导见 [ZXP1](../Expansion/ZXP1.md)。一次交换的方向与长度见 [ZXD1](../Expansion/ZXD1.md)。交给设备的文本是 ZAP，标号展开规则与提交给 CPU 之前的文本相同。本文不重新定义 ZAP 助记符。

## 0. 文档定位与符合性

声称兼容 ZSP1 的设备必须：

1. 使用协议标识 `ZSP1`，大小写逐字一致，并把它放在扩展插头的 `DeviceProtocol` 上；
2. `ActiveProtocol` 仍是 `ZXD1`；
3. 按本文解释每一次 `Exchange` 的八位组；
4. 程序执行失败时不得让这次失败变成扩展口 `Load` / `Boot` 的失败，也不得变成宿主引导序列的失败；
5. 不把本文「明确不规定」的内容宣称为协议要求。

## 1. 概述

沙盒收下一段程序文本，执行一次，然后用状态、寄存器和故障说明回答读回。程序中的故障记成状态 `4`。交换本身不合法时，这次交换失败，已收下的文本保持原样。

## 2. 契约范围

### 2.1 本协议规定

- 协议标识 `ZSP1`；
- 方向 `0` 的三条命令：复位、追加、运行；
- 方向 `1` 的读回：状态、文本长度、故障说明、寄存器；
- 程序失败只改变状态和故障说明。

### 2.2 本协议明确不规定

- 扩展口编号，以及用哪一颗核心执行；
- 文本如何被某一种语言编译出来；
- 故障说明的自然语言措辞，只规定它能被逐字符读回，且长度有上界；
- 同一次执行的时限。

## 3. 术语

| 术语 | 定义 |
|------|------|
| 字 | 一个无符号整数，范围 `0` 至 `2^64-1`，小端 8 个八位组 |
| 程序文本 | 若干可打印 ASCII（码位 `0x20` 至 `0x7E`）或换行 `0x0A` |
| 状态 | `0` 空闲，`1` 已武装，`2` 执行中，`3` 通过，`4` 失败 |

## 4. 规范正文

### 4.0 协议固定常量

| 名称 | 取值 |
|------|------|
| 协议标识 | `ZSP1` |
| 一字的八位组数 | `8` |
| 程序文本上界 | `4096` 个八位组 |
| 故障说明上界 | `256` 个字符。超出部分必须截断 |
| 复位 | `0` |
| 追加 | `1` |
| 运行 | `2` |
| 读状态 | `0` |
| 读文本长度 | `1` |
| 读故障长度 | `2` |
| 读故障字符 | `3` |
| 读寄存器 | `16` 至 `23`，对应寄存器 `0` 至 `7` |

### 4.1 方向 0

载荷第 0 个八位组是命令。

复位：清空文本、故障说明和寄存器，状态变为 `0`。正在执行的那一次若稍后才结束，其结果必须丢掉。返回的字是状态 `0`。

追加：第 1 个八位组是长度，必须是 `1` 至 `6`。随后该长度的八位组是程序文本。状态为 `2` 时必须失败且不得改文本。追加后长度会超过 `4096`，或出现可打印 ASCII 与换行以外的字节时，必须失败且不得收下这一个片段。成功后状态变为 `1`，返回的字是当前文本长度。

运行：状态已经是 `2` 时不得再启动一次，返回状态 `2`。文本为空时状态变为 `4`，故障说明表示没有程序，不得抛出到宿主引导。文本无法展开时同样变为 `4`。成功启动后状态变为 `2`，返回的字是当前状态。

其它命令必须失败，且不得改状态。

### 4.2 方向 1

载荷第 0 个八位组是读回码。

读状态、读文本长度、读故障长度：返回对应的非负整数。

读故障字符：第 1 个八位组是起点。返回值的 8 个八位组依次是从该起点起的故障字符码。不足的位置是 `0`。起点可以落在说明之后，此时 8 个八位组都是 `0`。

读寄存器：读回码 `16 + n` 返回寄存器 `n` 的低 64 位。负数按二进制补码截断。还没有执行结果时，8 个寄存器都是 `0`。

其它读回码必须失败。

### 4.3 失败隔离

状态变为 `4` 时，设备必须仍然处于已引导，后续交换仍可复位并收下另一段文本。禁止因客程序失败而让宿主的引导循环停止。

## 5. 不符合示例

1. 空文本上的运行命令让宿主引导失败；
2. 客程序里的非法指令让扩展口从已引导退回；
3. 追加第 `4097` 个八位组时仍改写了文本；
4. 执行中再次运行，把前一次的结果覆盖掉；
5. 复位之后，复位前那一次的迟到结果仍把状态改成通过。

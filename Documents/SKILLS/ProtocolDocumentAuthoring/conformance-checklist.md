# 协议文档符合性审查清单

对任意对外协议文档，审查者（人或 Agent）必须逐项判定。结果只能是 **通过 / 不通过**；不通过必须指出原文位置与漏洞类型。

## A. 定位与责任边界

- [ ] 写明约束对象是「声称兼容的实现」，不是本仓库实现进度
- [ ] 写明读者无需阅读源码即可裁决符合性
- [ ] 写明主机仅保证支持「符合本文」的实现
- [ ] 写明「声称兼容但不符本文 → 实现不符合」，而非主机未约定
- [ ] 参考实现标注为非规范；冲突以本文为准

## B. 用语与人称

- [ ] 使用必须 / 禁止 / 应 / 可以（或 MUST 等同等用语）且前后一致
- [ ] 无「我们正在实现」「当前还没做」等第一人称进度叙述充当规范
- [ ] 无「协议必须实现某某」的主谓错位

## C. 标识与命名

- [ ] 协议标识字符串唯一、精确、大小写固定
- [ ] 所有必选字段给出规范字段名
- [ ] 明确禁止等价命名 / 别名冒充兼容
- [ ] 枚举或修订号的非法变体已在不符合示例中点名

## D. 固定常量 vs 可标定

- [ ] 固定常量：必须存在 + 取值写死 + 改值须升版协议
- [ ] 可标定字段：必须存在 + 值域内可选
- [ ] 两类在正文中分区或分表，避免混读

## E. 值域可裁决性

- [ ] 每个数值字段排除 0/负/非有限/非整数（若不允许）
- [ ] 每个字符串字段写明长度、字符集、长度计量
- [ ] 「字节」与「字符」若同时出现，已消除 UTF-16/代理对歧义
- [ ] 单位写死处不得被其它单位替换

## F. 判定规则

- [ ] 启用/禁用、相等、前缀等判定无双标准（例如布尔与哨兵值并存且冲突）
- [ ] 哨兵值字符码点写死（如 `U+0030`），禁止「看起来像零」

## G. 明确不规定

- [ ] 单列「本协议不规定」
- [ ] 未标准化的算术关系 / 运行时行为被明文排除
- [ ] 禁止第三方把排除项宣称为本协议要求

## H. 符合性闭环

- [ ] 有「何时可声称完全兼容」的合取条件
- [ ] 有必选成员总表（可机器核对）
- [ ] 有不符合示例（覆盖命名、大小写、值域、字符集、隐含公式等）
- [ ] 可选汇聚字段（若有）标明不影响符合性，且禁止与必选冲突

## I. Registry + Index 专一拆分

- [ ] 凡可枚举、可增长的编码/状态/标号表，已拆成 `{Topic}Registry.md` + `{Topic}Index.md`
- [ ] 协议正文仅保留摘要 + 链接，未把完整长表只堆在正文
- [ ] 页眉或目录 README 写明优先级：Registry > Index > 正文摘要
- [ ] Index 每条可跳回 Registry；无「索引独有、登记表没有」的取值
- [ ] 该协议子目录 `README.md` 已列出全部附属登记/索引文档
- [ ] 新增「已遇到」项时遵循：先 Registry → 再 Index → 再正文（若需要）

## J. 终审

- [ ] 假设敌对实现只钻空子、不配合：能否仍被本文判为不符合？
- [ ] 假设善意实现只读本文（含 Registry/Index）、不看代码：能否独立做出兼容实现的配置面？
- [ ] 两问皆「能」→ 通过；任一「不能」→ 不通过并修订正文

# 官方 CPU

命名空间：`ZerOS.Hardware.Cpu`。协议：`ZCP1`。指令文本是汇编语言 ZAP。

引导默认把无扩展名二进制交给核心。没有导出、导入和 `-pie`、且每一行都能编成原生指令时，文件头是 `ZNB1`，代码从第 12 个八位组起，核心按指令指针取这些字节。其余是 `ZPB1`，版本是 `1`，多字节整数是小端，解码后的指令和解析 ZAP 得到的是同一种。标号在写入之前已经收成指令编号。要文本对照时另加 `-zap`，CPU 不读那份文件。沙盒继续只收 ZAP 文本。

`install` 从线性地址把八位组读走一次。`ZNB1` 把文件头后面的代码安到目标核心并设好指令指针。`ZPB1` 必须是完整映像，版本 `1`，小端，读完不能剩字节，解完之后执行指令序列。长于 `16777216` 个八位组的跨度直接拒绝。目标停着，直到 `Schedule` 把它调成执行中。沙盒不走这条路径。以 `7F 45 4C 46` 开头的字节不是原生映像，监督核不把它交给 `install`。

`admit` 把一颗已停止的核心放进兼容尾区。尾区从位地址 `2432696320` 起，长 `134217728` 位，不在映射区里。全机同时一份。`0F 05` 只在这份任务里陷入，服务号是 27。原生调用不进 27。

这一份实现把 `CoreCount` 标为 `8`，挂上时的 Hz 标为 `100000000`。这些是标定，不是协议常量。0 是固件画面，2 是内核。1 的数据窗给定沙盒客程序，平时由内核调度空转。3 至 7 给服务、驱动和用户程序。换实现时整体替换 `ActiveProvider/`，导出名保持 `ActiveCpuProvider`。

停机时 CPU 线程把这一颗核心最近一次停下的记录交给主板，主板再交给页面。页面控制台用 `ZerOSCoreStop(核心号)` 读取。没有停过则是 `null`。字段是 `Core`、`Reason`、`Index`、`Op`、`Detail`。`Reason` 为 0 是结束或 halt，1 是让出、时间片或抢占，2 是在等系统调用，3 是执行失败。3 不写进查询字段 11，也不进客程序能读的内存。`Index` 是指令编号，对得上 `obrc -debug` 的对照表；CPU 不读那份文件。`Op` 是操作名，序列走到头时是空串。`Detail` 是失败原文，其它时候是空串。只保留当前这一条，没有调用栈。引导画面不画它。`waitMessage` 换掉 `onmessage` 之后，后来的停机仍然送到页面。

主板按声明挂载 8 条核心 Worker，并可以 `ForceUnload`。每个核心有 8 个寄存器，并记下当前 Hz 和已完成条数。Hz 可以改到 `1` 至 `1000000000`。每条指令占一拍，本地指令并成一次突发时也逐条记账。累计等待短于 1 毫秒不挂起。时间起点是主板上电时记下的那一个。监督核对另一颗正在执行的核心装入、卸下、抄槽、放回、接库或划定范围时，先把它停在下一条指令边界，停止原因是 1。客程序停在系统调用里时，核心仍保持执行中，大约每 33 毫秒空转一次，不取客程序指令，回复之后才继续。访存仍经主板通道。比较、按编号跳转、入站取数、扩展口上的一次 8 八位组交换，一次写下已准备应答的 `fill`，以及按句柄一次读取的 `carry`，也是通用指令。装入映像时，没留在核心里的八位组按一段一次读回。

# 官方显示器 API

协议正文是 `Documents/Protocol/PhysicalHardware/Display/ZDP1.md`。本文只描述 `ZerOS-PRO/Hardware/Display/` 这一份实现。

命名空间：`ZerOS.Hardware.Display`。入口对象：`Display`。

## 协议字段

| 名字 | 说明 |
|------|------|
| `Width` / `Height` | 当前分辨率。官方启动时是 640 与 480 |
| `Hertz` | 当前刷新率。官方启动时是 60 |
| `Framebuffer` | `Uint32Array`，长度等于宽乘高。下标 `Y × Width + X`，`(0, 0)` 在左上角 |
| `SetResolution` | 合法则换成全 0 的新缓冲并改画布栅格。非法则抛出，原缓冲不动 |
| `SetHertz` | 合法则改节拍。非法则抛出，帧缓冲不动 |
| `Redraw` | 把每个像素拆成 R、G、B 写入画布，透明通道固定写成 255。发现非法像素时整幅不画 |

像素 `P` 的 R 是位 23..16，G 是位 15..8，B 是位 7..0。呈现不按宿主字节序整块拷贝。

抛出前缀是 `[ZerOS.Hardware.Display.Display]`。宿主 `throw` 不是协议。

## 官方宿主

| 名字 | 说明 |
|------|------|
| `Display.Attach` | 接上页面里的那一块画布，取得二维上下文，画出第一帧，并启动时间轴。不是 ZDP1 方法名 |
| `sealHostPage` | 在 `Attach` 之后调用。文档主体只留这块画布。捕获阶段截住点击、指针、滚轮和拖放。键盘事件不在这里丢掉 |

`index.html` 的正文只有 `<canvas>`。工具链在提供页面时插入模块脚本，脚本不属于显示器内容。

页面宿主先 `Attach` 再封印，然后登记键盘发布，再动态加载 `Boot`。静态加载会在画布出现前给主板加电。显示器模块不导入 Boot 或内核。

因为浏览器的存在，迫不得已做出的让步：键盘事件只交给持有文档的线程。显示器接上 `keydown`、`keyup`、`keypress`，把它们收成整数交给主板，不解释按键。这是显示器对主板的唯一额外发布。

显示器留在页面线程上，因为它要画这块画布。内存和主板各自在自己的 Worker 里，测试不会堵住这里的呈现。

时间轴是绝对的：第 n 拍到期于 `起点 + n × 1000 / Hertz` 毫秒。宿主定时可能提前醒来，醒来后若还没到期就再排一次，后面的拍不累计这个误差。已经错过的拍丢掉，只画当前这一幅。某一拍的像素不合法时，面板保持上一幅。直接调用 `Redraw` 时，非法像素仍然抛出。

画布的 `width` / `height` 属性就是分辨率。

## 页面封印不是协议

点击和滚轮不属于 ZDP1。封印是这一份官方页面对宿主文档和窗口的管理。`console` 的输出方法在封印后是空操作。键盘事件由页面发布给主板，显示器仍不解释它们。

# 主板说明

命名空间：`ZerOS.Hardware.Motherboard`。  
源码：`ZerOS-PRO/Hardware/Motherboard/`。  
本文只说明这一块板实际支持什么、上电做了什么、内存通道的底层口是什么。

## 1. 支持的协议

主板按协议标识决定能不能坐。标识对上才 Bind。对不上就不进插座。

| 设备 | 支持的协议 | 当前情况 |
|------|------------|----------|
| 内存 | `ZMP1` | 上电时坐 `Hardware/Memory/ActiveProvider/` 导出的插头 |
| CPU | `ZCP1` | 上电时坐 `Hardware/Cpu/ActiveProvider/`。核心数读那份实现的 `CoreCount`。主板按这个数挂载，并能强制卸载。不调度核心，不转达核心之间的传递 |
| 显卡 | `ZGP1` | 上电时坐 `Hardware/Gpu/ActiveProvider/`。帧宽高读那份实现的声明。主板只转交 `Present` 副本，不解释像素 |
| 扩展口 | `ZXP1` / `ZXD1` | 固定 4 个口，编号 `0` 至 `3`。可以为空。非空则在收尾 logo 之前 `Load` 再 `Boot`。数据交换不解释八位组。官方键盘插头在引导前坐上口 `0` |
| 键盘 | `ZKP1` | 经扩展口交换。实现在 `Hardware/Keyboard/ActiveProvider/`。主板不识别按键 |
| 沙盒 | `ZSP1` | 经扩展口交换。实现在 `Hardware/Sandbox/ActiveProvider/`。官方标定坐在口 `1`。程序失败留在设备状态里，不画成引导故障 |

以后 CPU 协议再有一个版本，把新标识加进 `SupportedCpuProtocols`。核心之间怎么配合仍由 CPU 自己决定。

显示器不在这张表里。它使用自己的协议，不经本板接入。

内存协议升级出新版本时，把新标识加进 `SupportedMemoryProtocols`，并用那一版的导出端口接到下面同一条通道上。旧标识仍然留在名单里，通道的方向、地址、字宽不改。

换内存实现：整体替换 `ZerOS-PRO/Hardware/Memory/ActiveProvider/`，保持 `Provider.ts` 与导出名 `ActiveMemoryProvider`。内存线程加载这个目录。Boot 不导入它。页面上的主板入口也不导入它。

## 2. 线程

显示器留在页面线程，因为它持有唯一的画布。其余虚拟硬件各自一条 Worker。源码仍按原来的 TypeScript 文件拆开，由工具链装进对应线程，不收成手写的单文件。构建时主板调度和内存调度各打成一份脚本，内存实现不进页面脚本。`Host/QueuedWorker.ts` 先用一段没有静态导入的经典脚本接上消息，再装入调度模块。模块图还在下载时，第一条消息留在这个队列里。

| 线程 | 入口 | 装进线程的源码 |
|------|------|----------------|
| 页面 | `Hardware/Display/Host/PageHost.ts` | 显示器，以及 `Boot` 对主板的一次上电投递 |
| 主板 | `Host/QueuedWorker.ts` 再装 `Host/BoardDispatch.ts` | 主板运行时、内存座、通道 |
| 内存 | `Hardware/Memory/Host/MemoryDispatch.ts` | 内存实现、插座上的 Bind / Test / Initialize |
| CPU | `Hardware/Cpu/Host/CpuDispatch.ts` | CPU 主体：调度、执行入口、核心间保持位 |
| CPU 核心 | `Hardware/Cpu/Host/CoreDispatch.ts` | 每一个已挂载核心一条。条数等于该实现声明的 `CoreCount` |
| 显卡 | `Hardware/Gpu/Host/GpuDispatch.ts` | 帧存储、`Clear` / `Plot` / `Present` |

内存和以后的 CPU 不互相调用。通道访问先到主板线程，再由信箱交给内存线程。内存线程先回报就绪，主板再把信箱交过去。之后的等待是共享内存加 `Atomics.wait`，只在主板线程里进行。页面线程不参加这次等待。

工具链给页面加上跨源隔离响应头，信箱才能建立。这不是协议。

## 3. 上电

页面上的 `Motherboard.Power()` 立即返回。Boot 只调用这一步。

主板线程里的顺序：

1. 已经坐稳时直接返回。不重新自检，不重新抽 `MemoryId`。
2. 主板自检：协议名单里有 `ZMP1`、`ZCP1`、`ZGP1`、`ZXP1` 和 `ZXD1`，内存指令操作码 `1` 至 `14` 与通道字宽、方向一致。失败就停，不坐内存。
3. 坐显卡，并做它自己的 `Clear` / `Plot` 自检。这一次不把帧送到页面。
4. 把 `SupportedCpuProtocols` 交给 CPU 线程。协议不在名单里，或 `CpuSlot.Bind` 没有接受插头，就停。
5. 读取该实现的 `CoreCount`，挂载编号 `0` 至 `CoreCount - 1`，每个核心一条 Worker。
6. CPU 先核对调度和保持位。访存核对留到内存坐稳之后。
7. CPU 执行 Boot 的 logo 指令：居中文字，`gpu.present` 把这一帧送到面板。logo 留在画面上。
8. 把 `SupportedMemoryProtocols` 交给内存线程，Bind，自检通过后初始化。主板再读一次线性位元 0。
9. CPU 补做访存核对：`place`、`add`，把和写入线性地址 0 的八位组再读回，然后把该八位组恢复为 0。
10. 按编号 `0` 至 `3` 查看 4 个扩展口。口 `0` 若仍空着，先坐下官方键盘插头。空口跳过。已经 `Bind` 的口先 `Load` 再 `Boot`。某一个口失败则编号更大的口不再处理。
11. CPU 进入固件循环。logo 上标出 `F12 BIOS`。这段时间按下 F12 就进入设置画面。时间过了还没按，就摘掉 logo，画面保持全黑，之后再按 F12 仍然进入。
12. 设置画面用 Tab 切换已经坐上的硬件，Shift+Tab 往回，Esc 回到全黑。每一页是该硬件当前能读到的数。
13. 主板通知页面。通知发生在固件循环开始之前。
14. 引导或固件循环里有指令失败时，CPU 再画一帧：`ERROR`、十进制错误码、十进制来源和短名、以及说明里能显示的 ASCII。只画一次。

页面在通电之前已经做过显示器自检。失败就不通电。

主板可以 `ForceUnload` 卸掉一个已挂载核心。卸掉之后该编号不再可调度。主板不转达核心之间的 `Pass`。

内存自己的高级端口（位元、块、领取、加深）仍在内存实现上。主板不把那些方法再导出一遍。失败时主板线程把原句送回页面，页面不写入宿主控制台。`Power` 也不因此变成同步抛出。

## 4. 内存通道

通道是主板用内存已经导出的端口组出来的底层口。地址是线性位元下标（`bigint`）。数据是 `bigint`。方向与字宽如下。

| 方向 | 数值 | 方法 |
|------|------|------|
| 读 | `0` | `Read(Address, Width)` |
| 写 | `1` | `Write(Address, Width, Data)` |

| 字宽（位） | 落到内存的端口 |
|------------|----------------|
| `1` | `ReadLinearBit` / `WriteLinearBit` |
| `8` | `ReadOctet` / `WriteOctet`（按线性地址找到那一颗） |
| `16` | `ReadLinearInteger` / `WriteLinearInteger`，八位组宽度 `2` |
| `32` | 同上，八位组宽度 `4` |
| `64` | 同上，八位组宽度 `8` |

字宽大于 `1` 时，地址必须能被 `8` 整除。不对齐就停，一个位元都不写。字宽不在上表里同样停。

总控还没发布时，通道拒绝访问。内存端口拒绝时，异常记在内存自己的总控或颗粒上，通道不另造一套异常标号。

低位是窗口里的最低有效位，与 ZMP1 的小端一致。`16` / `32` / `64` 可以跨过颗粒边界，因为走的是内存的线性整数端口。

## 5. 内存指令

通道组好之后，对外提供的是指令，不是再包一层内存高级端口。这些操作码就是 ZAP 访存指令使用的编码：读和写分开，字宽写在操作码里。没有机器码字节。

| 操作码 | 含义 | 通道 |
|--------|------|------|
| `1` | 读 1 位 | 方向 `0`，字宽 `1` |
| `2` | 写 1 位 | 方向 `1`，字宽 `1` |
| `3` | 读 8 位 | 方向 `0`，字宽 `8` |
| `4` | 写 8 位 | 方向 `1`，字宽 `8` |
| `5` | 读 16 位 | 方向 `0`，字宽 `16` |
| `6` | 写 16 位 | 方向 `1`，字宽 `16` |
| `7` | 读 32 位 | 方向 `0`，字宽 `32` |
| `8` | 写 32 位 | 方向 `1`，字宽 `32` |
| `9` | 读 64 位 | 方向 `0`，字宽 `64` |
| `10` | 写 64 位 | 方向 `1`，字宽 `64` |
| `11` | 读二进制 32 的位型 | 方向 `0`，字宽 `32`。通道上的整数是这 32 位的补码 |
| `12` | 写二进制 32 的位型 | 方向 `1`，字宽 `32` |
| `13` | 读二进制 64 的位型 | 方向 `0`，字宽 `64`。通道上的整数是这 64 位的补码 |
| `14` | 写二进制 64 的位型 | 方向 `1`，字宽 `64` |

一条指令有三个字段：`Opcode`、`Address`、`Data`。`Address` 是线性位元下标。Load 的 `Data` 写 `0`，不参与读取。Store 的 `Data` 送进通道，值不合法时仍由内存端口拒绝。

`ExecuteLoad` 只接受读操作码，`ExecuteStore` 只接受写操作码。放错就停，通道一次都不访问。一次调用只执行一条。不取下一条，也不把指令排成程序。

对齐和字宽规则与上面的通道相同。执行时先拆操作码，再进入 `Read` / `Write`。CPU 执行这些指令时，仍由主板完成这一次通道访问。

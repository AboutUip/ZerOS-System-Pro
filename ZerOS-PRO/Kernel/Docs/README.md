# 内核

源码在 `ZerOS-PRO/Kernel/`，按层分目录，编译进 NAS 的 `/kernel/`，不进浏览器包。常驻核心是 `2`。数据窗口是 `[537919488, 675823616)`。入口文件是 `Init/start.obr`，客路径 `/kernel/start`。`Text/` 是 UTF-8 库。CPU 上电自检仍跑 `utf8-check.obr`。入口映像另链 `Test/suite.obr`，划定窗口后在本核心再跑一遍标量、三字节「中」和 UTF-8 的空串、双字节、四字节、打包、拒绝与容量。失败时先把 `6272` 写成 1，请固件停笔，再用点阵画英文 `CHECK FAILED`。

层与层之间不是一张共用的头文件。每层自己的 `.mr` 只列出这一层对外的函数。实现文件开头的 `#LINK` 写明哪些源文件可以调用它，编译器会拒绝表外的调用。

| 层 | 目录 | 谁可以调用 |
|----|------|------------|
| 入口 | `Init/` | 回复只给 `task.obr` 和 `vfs.obr` |
| 进程 | `Proc/` | 入口、调度、文件、执行、堆 |
| 堆 | `Mm/` | 只有入口 |
| 调度 | `Sched/` | 入口、执行、文件、进程 |
| 文件 | `Fs/` | 入口、执行、进程 |
| 执行 | `Exec/` | 只有入口 |
| 字体 | `Font/` | 只有入口 |
| 文本 | `Text/` | 自检程序 `utf8-check.obr` 由 CPU 上电自检执行。入口在划定窗口后调用 `Test/suite.obr`，核对标量和一段 UTF-8 |
| 驱动样例 | `Drv/pulse.obr` | 单独编译，不链进入口 |
| 不再装入 | `Hold/` | `fs.obr` 与 `drvman.obr` 留着对照 |

这是按类 Linux 的完整度来写的内核，按下面的阶段推进。后一阶段使用前一阶段的对象，不另起一套。

| 阶段 | 内容 | 现在 |
|------|------|------|
| 1 核 | 任务、凭证、地址空间、内核堆、调度、系统调用入口上的权限 | 已接上 |
| 2 文件 | 虚拟文件系统、路径、属主与权限位、每任务的文件描述符。NAS 是第一种文件系统。根在 NAS 未就绪，或 `/boot/root` 正好是三个八位组 `mem` 时，改成内存目录。内存文件 6 份，每份 1048576 个八位组，路径分量最长 512 个八位组，整条路径最长 8192，`spawn` 能直接跑 | 已接上 |
| 3 设备与执行 | 驱动模型、装入并执行程序、信号、管道、进程的退出和等待。核心 4 至 7 在时间片用尽时可以换上另一份已经留在槽里的任务。监督核按 30 Hz 空转前，若同核还有就绪任务，也会在下一条指令边界抢占再换 | 已接上。字符设备挂在 `/dev`。客核心不能再发显卡和扩展口。一核能装多少由任务表、256 个上下文槽和该核槽尾的堆池决定。任务还不跨核 |
| 4 控制台 | 监督核代画。客程序写 `/dev/con`，监督核用系统字体把标量画进深色格子。脏行才重画，一次写只呈现一帧。读没有字节时先睡下 | 已接上 |
| 5 用户态 | 1 号任务是单独的映像。它直接调度 `/os/sh`，并收下孤儿。shell 是交互式的：提示符、行编辑、历史，以及 echo、cd、pwd、exit、history、clear。可以重定向和接管道。外部程序仍只按路径派生。终端由监督核用系统字体画。同一进程里的多条执行流还没有。进程和文件的权限继续留在内核，不写进 ZCP1 | 1 号和 shell 已接上。会话映像仍在，1 号不再拉起。多条执行流留着 |

用户核 3 至 7 不再按份数封顶。全机任务表是 512 份。上下文槽是官方标定的 256 个，槽号由内核分配：0 至 255 优先用和下标相同的槽，256 至 511 领任意空槽。`held` 为 0 表示还没进槽，大于 0 时槽号是 `held` 减 1。同时留在槽里的任务至多 256 份，领不到槽的继续占着核心，等有槽空出来再换。`capture` 和 `restore` 抄的是这颗核心上别人读不到的栈、静态区和堆前缀。时间片用尽时，当前任务抄进自己的槽并改成就绪，再把另一份已经在槽里的就绪任务放回去。停在系统调用里的不换。监督核自己不换，监督核上仍只有一份任务。用户堆在该核编译器映像之后的槽尾，先给 4194304 个八位组，池里不够就先给 65536，紧挨着的空闲块还能继续长。要装入的程序先读到监督核的同一段槽尾，最长 16316416 个八位组。

入口用 `obrc -slot 2` 编译，地址写死在核心 2。编完执行 `node ZerOS-PRO/Hardware/Nas/Server/provision.mjs`：缺 `/boot/display` 时按显示器驱动的默认宽高写成四个八位组，缺 `/boot/debug` 时写成一个八位组 0，并把 `ZerOS-PRO/Resource/Font` 拷到客路径 `/font`、标成只读。这三处都不是源码，重编不覆盖已经改过的分辨率和调试开关。会装到核心 4 至 7 的程序用 `obrc -pie -slot 0`：不小于 `1048576` 的数据立即数记成重定位，`install` 再按目标核心加上窗口位移。`-slot` 每次加上 `核心号 × 268435456`，核心号是 `0` 至 `7`。入口要和各层的 `.mr`、实现、`obr.nas.obr`、`Text/utf8.obr`、`Test/suite.obr` 一起交给编译器，并用 `-I` 指向 `Init`、`Proc`、`Mm`、`Sched`、`Fs`、`Exec`、`Font`、`Text`、`Test`。引导自检失败时用点阵画英文 `CHECK FAILED`，此时还没有字体面。

NAS 上只放运行时映像：`/kernel/start`、`/kernel/init`、`/kernel/idle`、`/os/sh`、`/os/session`，以及 `/kernel/drv/` 里不带点的驱动。这棵树在 `ZerOS-PRO/Hardware/Nas/Root`，整目录不进版本库。源码分层不复制上去。旁边不放 `.zap`。带点的名字引导时跳过。`/font` 是从 `Resource/Font` 拷来的只读副本。`/boot/display` 是固件记住的显示器宽高，四个八位组，不装入，文件保持可写。缺文件时固件留在驱动默认档。`/boot/debug` 是一个八位组的调试开关，0 关，1 开，不装入，同样可写。缺文件时是关。

`fs.obr` 不再装入。文件调用在监督核里完成。

倒计时在核心 0 上。探活清掉启动画面之后，固件先画 Starting：白字、向左阴影、六个点，底部是 F12 提示。倒计时结束前只画一次，不逐拍等待。结束时核心 0 只 `schedule` 核心 3。核心 3 装内核的期间，每 200 圈换一颗红点，这一段不等待。核心 2 把 `/kernel/drv` 里不带点的文件按顺序装到空闲的核心 4 至 7，放行字写成 0 后就调度。驱动按 30 Hz 空转，先不发系统调用。然后写下结束标志 `5952`。固件这时才铺上四块蓝色方标和绕圈的拖影，这是操作系统还在起来。接着把 `/kernel/init` 装到下一颗空闲的 4 至 7，作为 pid 1，并马上调度。1 号只派生 `/os/sh`，然后进入 `wait`。shell 打开 `/dev/con`，画出 `root@zeros:` 提示符后停在读键盘上。监督核认出这份不是驱动的子任务后，先把 `6272` 写成 1，请固件停笔，再去读字体。固件看见之后把 `6336` 写成 1，并且不再画方标，同时开始把按下写进 `6528` 的键盘环。监督核读到 `6336` 才把 `/font/sarasa-mono-sc.ttf` 映射进来、建立 16 像素的字体面，再把格子里已经写下的提示符画出来。字体打不开就停在这一步，方标已经不再画。客程序不能发显卡，所以这一帧由监督核画。1 号进入等待后，监督核把 6208 写成 1。固件不读这一字，驱动靠它放行。没有任务的核心装上 `/kernel/idle` 并按 30 Hz 调度，保持执行中。设置开着时监督核不干等加载画面，这些核心会先醒；离开设置后，内核若还没写完 `5952`，固件回到 Starting，写完才铺方标。核心 1 不装用户任务，数据窗留给沙盒客程序；沙盒跑完后空转从第一条继续。监督核没有系统调用时也按 30 Hz 空转，不让出。正在执行的核心仍可以装入：监督核先把它停在下一条指令边界。停在系统调用里的核心不卸下客程序，固件大约每 33 毫秒空转一次并保持执行中，回复之后从留下的下一条继续。1 号写到还没打开的描述符时，监督核仍然可以直接把字节画到控制台。引导本身不再写字。NAS 没开或 `/kernel/start` 不在时，装入程序自己写下结束标志并停下。

核心 2 调用 `gate` 成为监督核。之后只有它能装入、调度、划定范围和卸下。它给每个被装入的核心划定 `[数据下限 + 核心号 × 槽距, 一整个槽)`，槽尾因此能被客程序访问，下一颗核心和映射区仍然在范围外。监督核自己持有门，不受这道限制。被它装入或划定的其它核心是客核心，不能再发显卡、扩展口，也不能改别的核；运算、窗口内访存、让出和系统调用仍然可以。

任务表在监督核窗口的 `+65536` 处，最多 512 份，每份 19 个 64 位字。末尾是退出码、正在等的子任务，以及槽号加 1。等待字为 0 表示没在等，-1 表示等任意一个，正数是指定的 pid。槽字为 0 表示还没抄过。别的核心的界限盖不到这张表。监督核不进任务表。1 号是 `/kernel/init`，uid 0，没有管理权，父任务是 0。驱动从 pid 2 起，也是 uid 0、没有管理权，父任务是 1。经 `spawn` 装入的程序继承调用者的 uid、euid 和 cap，父任务是调用者。

地址空间记在任务的 `Mm` 里：可分配区起点、长度、堆起点、递增指针、空闲链表。用户核的可分配区从该核槽尾的堆池里领，起点和长度都记在任务上，用尽相邻空闲块之前还能长。核心 2 的起点仍是编译器映像那一段，堆还要让开任务表和文件区。每块前面两个字，载荷位数和空闲链；使用中的链字是 -1。释放时核对块在自己的堆里、链字是 -1、位数不超过块本身，再按地址插入并合并相邻空闲块。堆池用完时，整块交回槽尾并和相邻空闲块合并。

八颗核心的窗口到 `2148532224` 为止。后面直到 `2432696320` 是监督核的映射区，`mmap` 按 4096 个八位组向上取整。再后面 `134217728` 位是兼容尾区，不是映射区，字体文件也不放进去。位元线到 `2566914048`。客核心的 `bound` 是整整一槽，槽尾给堆池，到不了映射区，也不能执行 `mmap`。监督核持有门，不受这道界限。固件的 Starting 和方标仍用点阵字形。终端由监督核用 `obr::font` 画。Obr 字符串的下标就是标量，抄成小端 32 位再交给 `draw`。点阵错误帧仍然只能画英文。客程序不能发这两条。UTF-8 在 `Text/utf8.obr`，由核心 1 上的 Obr 自检解开。系统字体的源文件在 `ZerOS-PRO/Resource/Font`。编译时拷到 NAS 的 `/font` 并标成只读：`sarasa-mono-sc.ttf` 是 0 号，`maple-mono-cn.ttf` 是 1 号。引导时 `stat` 一次，结果放在监督核窗口 `+20480`，每份两个字。缺文件不中断引导。服务 26 把当时记下的在不在、八位组数和路径交回调用者，不读取文件正文。shell 留在任务表里之后，监督核才把 0 号映射进来并建立字体面。超过 `16777216` 个八位组的文件不建立字体面。停笔已经发生，最后一帧方标留在面板上。1 号仍只登记。字体文件在协议上最长 `33554432` 个八位组，映射区放得下一份。

调度看任务状态。时间片用尽或 `yield`（停止原因 1），若同一核心上还有一份已经留在槽里的就绪任务，就把当前这份抄进槽再换上那一份。下一份从当前这一格的后面接着找，先等到的先跑。没有这样的兄弟，就原样再次 `schedule`。监督核每次按 30 Hz 空转之前再看一遍：核心仍在执行、停止原因不是 2、同核有一份在槽里的就绪任务，就 `capture` 停在下一条指令边界再换上。停在系统调用里不换。任务仍绑在装入时的那颗核心上，窗口里的堆不跟着搬。`halt`（停止原因 0）的变成僵尸，退出码 0；这颗核心上若还有就绪的兄弟，就把它放回去，核心不卸下。信号 9 不能被取走。核心已经停住且挂着信号 9 时，退出码记成 9，同样变成僵尸。停在系统调用里（停止原因 2）时不换任务。1 号自己退出就收掉。父任务不在时，子任务改挂到 1 号；1 号也不在才立刻收掉。这颗核心上没有别的任务时才卸下。父任务正在 `wait`，就把 pid 和退出码交回去再收掉。否则僵尸留到父任务来等。

引导之后只有监督核访问 NAS。驱动按 `/kernel/drv` 的目录顺序装到核心 4 至 7，名字里带 `.` 的跳过。每个驱动 30 Hz。装上的同时在 `/dev` 下登记同名的字符设备，权限 `0666`。`/dev` 本身不在 NAS 上，种类是 4。字符设备的种类是 3，`stat` 看到的大小是 0。一次读写至多搬 4096 个八位组，和环一样长。控制台一次也是这么多。`/dev/con` 在引导时挂上，所属核心是 2，任务是 pid 1。写入先收成 UTF-8 标量，放进内存文件正文之后的格子，一格 32 位，最多 160 列、48 行，整段 253952 位。换行码是 10，回车是 13，退格是 8 或 127，12 清屏。个数是负数时实际写成 0，调用仍然成功，也不呈现。字号 16 的系统字体只重画脏行，光标是一颗浅色竖条，一次写完只 `present` 一帧。读没有字节、且个数大于 0 时，这次调用先睡下；键盘环里有字节再抄进调用者窗口并应答。已经有人在等时，另一个读得到 11。个数是 0 的读直接得到 0，不睡。固件把 `4096` 写成 1 之后，监督核不再用点阵往加载画面上写字。用户写进其它设备的字节由驱动用 23 号调用取走，驱动送出的字节由用户的 `read` 取走。环是空的或满的时候，这次调用先睡下。驱动任务收掉之后，堵着的读得到 0 个字节，堵着的写得到 5。管道是 64 条、每条 4096 个八位组的环形缓冲，和设备环一样长。调用者窗口的读写字节在 `+131072`，一次最多 262144 个八位组。NAS 的一次执行仍只能写下 65535 个八位组，应答长度是 16 位。库会把更长的写入拆开重复执行，调用者一次最多 268435456。系统调用先受窗口 262144 的限制。读的时候没有字节、写端还在，这次调用先睡下，有字节或写端关光了再应答。写的时候缓冲区满、读端还在，同样先睡下。写端关光且缓冲已空，读端得到 0 个字节，这才是结束。读端关光时，堵着的写端得到 5。

入口映像暂存放得下 2097152 个八位组，起点是 `944259072`。这一段在核心 3 的编译器映像之后、核心 4 的窗口之前。现在这份是 499571 个八位组。装入程序超过这个长度就停下并写下结束标志。

系统调用是 `svc`。没有对应任务回复 -1。装入和卸下要管理权的最低位，只是 euid 0 不够。文件没有执行位时，`spawn` 回复 -1，根除外。内部的 -2 只表示这次调用还堵着，不会交回给调用者。服务号：

| 号 | 作用 |
|----|------|
| 1 | 让出。回复 0 |
| 2 | 在调用者自己的堆里分配。窗口起点处的字是位数，回复是用户区起点，0 表示没有 |
| 3 | 释放。起点和位数放在窗口的前两个字。成功回复 1 |
| 4 | stat。路径在 `+16384`。回复 0 时，`+128` 种类，`+192` 大小，`+256` 权限位，`+320` uid，`+384` gid。种类 1 是 NAS 文件，2 是 NAS 目录，3 是字符设备，4 是只在核里的目录，5 是内存文件，6 是内存目录 |
| 5 | open。路径在 `+16384`，`+128` 是方式：0 只读，1 只写并截断，2 读写，3 追加。成功时 `+192` 是文件描述符 |
| 6 | close。`+128` 是文件描述符 |
| 7、8 | read、write。`+128` 描述符，`+192` 偏移，`+256` 个数，字节在 `+131072`，实际个数在 `+320` |
| 9 | readdir。路径在 `+16384`，`+128` 下标，`+192` 容量，名字在 `+131072`，长度在 `+256` |
| 10、11 | mkdir、unlink。路径在 `+16384`。父目录要有写和执行 |
| 12 | 把 `/kernel/drv/pulse` 装到核心 6 或 7。核心上还有任务并且正在执行时拒绝。没有任务时，正在空转也可以，装入会先停在指令边界。要管理权。新任务是 uid 1 |
| 13 | 让核心 6 或 7 退出，并卸下。正在执行时先停在指令边界。要管理权。父任务当时正在 `wait`，会先收到 pid 和退出码 |
| 14 | chmod。路径在 `+16384`，`+128` 是权限位 |

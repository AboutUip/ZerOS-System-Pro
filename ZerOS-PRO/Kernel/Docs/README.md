# 内核

源码在 `ZerOS-PRO/Kernel/`，按层分目录，编译进 NAS 的 `/kernel/`，不进浏览器包。常驻核心是 `2`。数据窗口仍是 `[17825792, 23592960)`。入口文件是 `Init/start.obr`，客路径 `/kernel/start`。

层与层之间不是一张共用的头文件。每层自己的 `.mr` 只列出这一层对外的函数。实现文件开头的 `#LINK` 写明哪些源文件可以调用它，编译器会拒绝表外的调用。

| 层 | 目录 | 谁可以调用 |
|----|------|------------|
| 入口 | `Init/` | 回复只给 `task.obr` 和 `vfs.obr` |
| 进程 | `Proc/` | 入口、调度、文件、执行、堆 |
| 堆 | `Mm/` | 只有入口 |
| 调度 | `Sched/` | 入口、执行、文件、进程 |
| 文件 | `Fs/` | 入口、执行、进程 |
| 执行 | `Exec/` | 只有入口 |
| 驱动样例 | `Drv/pulse.obr` | 单独编译，不链进入口 |
| 不再装入 | `Hold/` | `fs.obr` 与 `drvman.obr` 留着对照 |

这是按类 Linux 的完整度来写的内核，分三个阶段。后一阶段使用前一阶段的对象，不另起一套。

| 阶段 | 内容 | 现在 |
|------|------|------|
| 1 核 | 任务、凭证、地址空间、内核堆、调度、系统调用入口上的权限 | 已接上 |
| 2 文件 | 虚拟文件系统、路径、属主与权限位、每任务的文件描述符。NAS 是第一种文件系统 | 已接上 |
| 3 设备与执行 | 驱动模型、装入并执行程序、信号、管道、进程的退出和等待。核心 4 至 7 在时间片用尽时可以换上另一份已经留在槽里的任务 | 换任务已接上。字符设备挂在 `/dev` |

用户核 4 至 7 上至多两份任务。`capture` 和 `restore` 把已停止核心的寄存器、下一条、指令序列，以及这颗核心上别人读不到的栈、静态区和堆前缀，抄进 8 个槽或放回来。槽号用的是任务表下标。时间片用尽时，当前任务抄进自己的槽并改成就绪，再把另一份已经在槽里的就绪任务放回去。停在系统调用里的不换。监督核自己不换。两份任务的用户堆各占编译器栈之前的一半，从窗口 `+16384` 起各 `516096` 位，互不覆盖。

入口用 `obrc -slot 2` 编译，地址写死在核心 2。会装到核心 4 至 7 的程序用 `obrc -pie -slot 0`：不小于 `1048576` 的数据立即数记成重定位，`install` 再按目标核心加上窗口位移。`-slot` 每次加上 `核心号 × 8388608`。入口要和各层的 `.mr`、实现、`obr.nas.obr` 一起交给编译器，并用 `-I` 指向 `Init`、`Proc`、`Mm`、`Sched`、`Fs`、`Exec`。

| 源文件 | 客路径 | 核心 |
|--------|--------|------|
| `Init/start.obr` 与 `Proc/task.obr`、`Mm/mm.obr`、`Sched/sched.obr`、`Fs/vfs.obr`、`Exec/exec.obr` | `/kernel/start` | 2。版本 1，`-slot 2` |
| `Drv/pulse.obr` | `/kernel/drv/pulse`，节点 `/dev/pulse` | 4 起，按目录顺序装入空闲的 4–7。`-pie -slot 0`。写进去的字节会原样读回 |

`Lib/add.obr` 和 `Drv/useadd.obr` 留在源码里，说明动态库怎么接。它们不放进 NAS，引导也不装入。

NAS 上只放运行时映像：`/kernel/start`，以及 `/kernel/drv/` 里不带点的驱动。源码分层不复制上去。旁边不放 `.zap`。带点的名字引导时跳过。

`fs.obr` 不再装入。文件调用在监督核里完成。

倒计时在核心 0 上。六个点按显示器的毫秒换色。结束时核心 0 只 `schedule` 核心 3。核心 3 上的装入程序若 NAS 已就绪，把 `/kernel/start` 读到暂存 `31981568`，`install` 到核心 2 再 `schedule`。核心 2 把 `/kernel/drv` 里不带点的文件按顺序装到空闲的核心 4 至 7，然后写下结束标志，固件才清成黑屏。NAS 没开或 `/kernel/start` 不在时，装入程序自己写下结束标志并停下。

核心 2 调用 `gate` 成为监督核。之后只有它能装入、调度、划定范围和卸下。它给每个被装入的核心划定 `[数据下限 + 核心号 × 槽距, 同样的跨度)`，范围外的访存失败。监督核自己不受这道限制。

任务表在监督核窗口的 `+65536` 处，最多 8 份，每份 19 个 64 位字。末尾是退出码、正在等的子任务，以及是否已经留在槽里。等待字为 0 表示没在等，-1 表示等任意一个，正数是指定的 pid。槽标志为 0 表示还没抄过，为 1 表示槽里是这份任务。别的核心的界限盖不到这张表。引导时监督核是 pid 1、uid 0，持有管理权。`/kernel/drv` 里装上的驱动是 uid 0，但没有管理权，所以不能再装入别的映像。经 `spawn` 装入的程序继承调用者的 uid、euid 和 cap，父任务是调用者。

地址空间记在任务的 `Mm` 里：可分配区起点、长度、堆起点、递增指针、空闲链表。用户核的可分配区就是自己的那一半堆，从窗口 `+16384` 起，长度 `516096` 位，停在编译器栈之前。核心 2 的起点仍是整段窗口，堆还要让开任务表、文件表和四份设备环。每块前面两个字，载荷位数和空闲链；使用中的链字是 -1。释放时核对块在自己的堆里、链字是 -1、位数不超过块本身，再按地址插入并合并相邻空闲块。

调度看任务状态。时间片用尽或 `yield`（停止原因 1），若同一核心上还有一份已经留在槽里的就绪任务，就把当前这份抄进槽再换上那一份。没有这样的兄弟，就原样再次 `schedule`。`halt`（停止原因 0）的变成僵尸，退出码 0；这颗核心上若还有就绪的兄弟，就把它放回去，核心不卸下。信号 9 不能被取走。核心已经停住且挂着信号 9 时，退出码记成 9，同样变成僵尸。停在系统调用里（停止原因 2）时不换任务。父任务是 1 号，或父任务已经不在，调度立刻收掉；这颗核心上没有别的任务时才卸下。父任务正在 `wait`，就把 pid 和退出码交回去再收掉。否则僵尸留到父任务来等。父任务先消失的，子任务改挂到 1 号，下一轮收掉。

引导之后只有监督核访问 NAS。驱动按 `/kernel/drv` 的目录顺序装到核心 4 至 7，名字里带 `.` 的跳过。每个驱动 30 Hz。装上的同时在 `/dev` 下登记同名的字符设备，权限 `0666`。`/dev` 本身不在 NAS 上，种类是 4。字符设备的种类是 3，`stat` 看到的大小是 0。一次读写至多搬 64 个八位组。用户写进设备的字节由驱动用 23 号调用取走，驱动送出的字节由用户的 `read` 取走。环是空的或满的时候，这次调用先睡下。驱动任务收掉之后，堵着的读得到 0 个字节，堵着的写得到 5。管道是 8 条、每条 64 个八位组的环形缓冲。读的时候没有字节、写端还在，这次调用先睡下，有字节或写端关光了再应答。写的时候缓冲区满、读端还在，同样先睡下。写端关光且缓冲已空，读端得到 0 个字节，这才是结束。读端关光时，堵着的写端得到 5。

入口映像暂存放得下 327680 个八位组，再长就会写进核心 4 的数据槽。装入程序超过这个长度就停下并写下结束标志。

系统调用是 `svc`。没有对应任务回复 -1。装入和卸下要管理权的最低位，只是 euid 0 不够。文件没有执行位时，`spawn` 回复 -1，根除外。内部的 -2 只表示这次调用还堵着，不会交回给调用者。服务号：

| 号 | 作用 |
|----|------|
| 1 | 让出。回复 0 |
| 2 | 在调用者自己的堆里分配。窗口起点处的字是位数，回复是用户区起点，0 表示没有 |
| 3 | 释放。起点和位数放在窗口的前两个字。成功回复 1 |
| 4 | stat。路径在 `+512`。回复 0 时，`+128` 种类，`+192` 大小，`+256` 权限位，`+320` uid，`+384` gid。种类 1 文件，2 NAS 目录，3 字符设备，4 只在核里的目录 |
| 5 | open。路径在 `+512`，`+128` 是方式：0 只读，1 只写并截断，2 读写，3 追加。成功时 `+192` 是文件描述符 |
| 6 | close。`+128` 是文件描述符 |
| 7、8 | read、write。`+128` 描述符，`+192` 偏移，`+256` 个数，字节在 `+4096`，实际个数在 `+320` |
| 9 | readdir。路径在 `+512`，`+128` 下标，`+192` 容量，名字在 `+4096`，长度在 `+256` |
| 10、11 | mkdir、unlink。路径在 `+512`。父目录要有写和执行 |
| 12 | 把 `/kernel/drv/pulse` 装到已经停止的核心 6 或 7。要管理权。新任务是 uid 1 |
| 13 | 让已经停止的核心 6 或 7 退出，并卸下。要管理权。父任务当时正在 `wait`，会先收到 pid 和退出码 |
| 14 | chmod。路径在 `+512`，`+128` 是权限位 |
| 15 | chown。路径在 `+512`，`+128` uid，`+192` gid。只要根 |
| 16 | chdir。路径在 `+512`，必须是目录，并且有执行位 |
| 17 | spawn。路径在 `+512`，`+128` 是核心，0 表示先找 4 至 7 里空闲的，没有再找一颗已经因时间片停住、且只有一份任务的。文件要有执行位。第二份装上之前，原来的那份先被抄进自己的槽。成功时 `+192` 是 pid，`+256` 是核心。当时没有能装的核心，回复 11 |
| 18 | kill。`+128` 是 pid，`+192` 是信号号。不能打到 pid 1。信号 0 只检查能不能发。根，或 euid 与对方的 uid、euid 相同，才能发 |
| 19 | sigtake。取走最小的一个待处理信号并回复它。没有则回复 0。信号 9 留着，由调度在核心停住后变成退出 |
| 20 | pipe。成功时 `+128` 是读端，`+192` 是写端。空读在写端还在时会堵住 |
| 21 | wait。`+128` 是子任务 pid，0 表示任意一个。成功时回复 pid，退出码在 `+192`。没有这样的子任务回复 2。子任务还在跑时，这次调用先不返回 |
| 22 | loadlib。路径在 `+512`，是 NAS 上的动态库。接到调用者自己的指令末尾。不要管理权。成功回复 0，`+192` 是第一个导出的指令编号。同名库已经接过则不再加长。读盘失败时回复 NAS 的状态 |
| 23 | 驱动和自己的设备交换字节。调用者必须是登记这块设备时的那个任务。`+128` 是方向：0 取用户写进来的，1 把字节送给用户的 `read`。`+256` 是个数，字节在 `+4096`，实际个数在 `+320`。没有字节或环已满时先睡下。不是这块设备的驱动时回复 -1 |

权限位仍只记在索引节点里。文件 `0644`，目录 `0755`，根跳过检查。`chmod` 只许属主或根，`chown` 只许根。
